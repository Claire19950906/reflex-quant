# v396 P3 · 99% HOLD 的三层根因与修复（2026-11-16）

> 提问："99% 出 HOLD 是什么原因？是不是闸口开太大 / 要求太严？"
> 答案：**都不是**。闸门在数量上确实只剩 4 条方向性，但 HOLD 是在闸门之前就产生的：
> 89.5% 的 HOLD 是"降级兜底"，不是判断。反过来说，闸门在质量上是**太松**——
> 它放过了降级路径产出的"方向"，3 笔成交里 2 笔就是这么来的。

## 一、494 条决策的真实构成

| 类别 | 条数 | 占比 | 说明 |
|---|---|---|---|
| `target_none`（标的不可交易） | 273 | 55.3% | 标的不在 BTC/XAU/WTI/ETH/SOL 池内 |
| `llm_empty`（LLM 没给可用分析） | 73 | 14.8% | 空输出 / 截断 / schema 不合格 |
| `summary_only`（只有摘要） | 63 | 12.8% | 未形成八段推演 |
| `server_fallback`（服务端兜底） | 33 | 6.7% | 模板拼出来的方向 |
| 真 HOLD（非降级） | 52 | 10.5% | 平均置信度仅 2.4 |
| 方向性（BUY 2 / SELL 2） | 4 | 0.8% | 其中 1 条被"过度分析惩罚"降级 |

降级率 = **89.5%**（440/490 的 HOLD 带 `analysis_degraded=1`）。

## 二、`target_none` 的真身

抽样 8 条：哈铁科技总经理辞职、爱奇艺财报、新洋丰磷酸铁毛利、锦浪科技回购、
中国国航客座率、上海亚虹要约收购……来源 `sina_flash` 188 + `wscn` 61 = 91%。

**判 NONE 是正确的**——这些是 A 股个股公告。问题在于它们仍然走完了
"门卫 LLM → 主分析 LLM → 判 NONE → 记降级 HOLD"的全流程。

## 三、闸门的真实状态：数量严、质量松

| 仓位 | 决策 | 降级 | 置信度 |
|---|---|---|---|
| #258 | 11483 | 无 | 25.8 |
| #259 | 11555 | `summary_only` | 27.3 |

闸门只校验 `confidence ≥ 20`，不看这条决策是不是真分析出来的 → **假方向变成了真仓位**。

另一个反向激励：52 条被"过度分析惩罚"扣分（reasoning > 800 字 → ×0.86）。
#11485 是全库唯一一条 BTC SELL、真正有方向的决策，被压到 17.9，卡在 20 分闸门之下 → HOLD。
**推演越认真越容易被砍。**

## 四、修复

| # | 问题 | 修复 | 落点 |
|---|---|---|---|
| A | 降级信号可建仓 | **R11**：`analysis_degraded=1` 禁止建仓（SQL + Python 双保险） | `quick_sim.pending_signals`、`sample_quality_filter` |

## 六、还没解决的

1. `llm_empty` 的两半都已处理（截断 → max_tokens 4000；schema 不合格 → 见第七节）。
   仍未解的：模型真的什么都没产出（纯空响应 / 只有思考没有正文），这类只能靠两步抢救兜。
2. 有效样本仍然只有 1 笔。R11 会**让样本更少**（砍掉降级信号），这是正确的方向：
   宁可 0 笔真样本，不要 3 笔假样本。
3. 真正的信号量取决于"池内新闻"的供给。如果池外占 10%、HOLD 80%、降级剩下的，
   那这套系统的上限不在闸门，而在**新闻源与交易池的匹配度**。


## 七、schema 那一半：把"格式门槛"从"内容门槛"上挪开

### 7.1 先看失败到底卡在哪

`[asset_nature] '' is too short` 104 次、`[factor_ranking] [] should be non-empty` 103 次、
`[reasoning] '' is too short` 100 次 —— 三次加起来 307 次，占全部 schema 报错的绝对多数。
而 `hard_data_evidence` 只有 7 次（它早已在 v323 被摘出 required）。

结论很直白：**作废整条分析的是三个"叙述字段"，不是核心判断。**

### 7.2 两处改动（都只动格式，不动内容）

1. **从 required 摘掉**：`asset_nature` / `factor_ranking` / `reasoning`
   —— 与 v323 对 `hard_data_evidence` / `asset_reasoning` 的处理同源。
2. **空值归一化（摘除 → 校验 → 还原）**：只剩第一步不够。模型常把键**带着空值**
   一起吐出来（`"asset_nature": ""` / `"factor_ranking": []`），键存在 → `minLength` /
   `minItems` 照样报错，整条照样作废（实测 `[asset_nature] '' is too short` 104 次就是这么来的）。

   所以 `validate_ai_decision` 外面加了一层：校验期间把空值**临时摘掉**，让 schema 只看
   "内容成不成立"；校验完**原样还原**（写回 `""` / `[]`），并记进 `_empty_narrative_fields`。

   还原这一步很重要 —— 不还原，一条缺了三个叙述字段的决策会显示 `completeness_score=1.0`，
   那才是真的骗人。实测新决策 `11923` 保留 `completeness=1.0` 是因为它八段推演真的写满了；
   而 `11920` 这类 `missing_fields=["asset_nature","asset_reasoning","hard_data_evidence"]`
   的，缺口一条不少地记在库里。

### 7.3 为什么这不是"放水"

这三个字段下游本来就有**非编造**的补全路径，这是 v200 P0+ 就设计好的：

| 字段 | 补全来源 | 性质 |
|---|---|---|
| `asset_nature` | L2 业务知识驱动的定性（如 "WTI 供给驱动属性"） | 真实知识，非生成 |
| `factor_ranking` | L2 驱动列表 | 真实知识，非生成 |
| `reasoning` | 从 `reasoning_path` 的 `[总结]` 段回填（v323 同法） | 模型自己的话，非生成 |

**仍然强制 required 的**：`reasoning_path`（≥100 字，这是"有没有真推演"的唯一硬证据）、
`target_asset`（必须在白名单）、`suggested_action`（BUY/SELL/HOLD）、各类分数与时间锚。
换句话说：**方向可以没有排版，但不能没有推演、不能没有标的。**

另加一条反向约束：值**非空但不合规**照样报错
（`factor_ranking=[{"direction":"看多"}]` 这种，`direction` 只认 利多/利空/中性），
不能借这个口子把假结构化洗白。
