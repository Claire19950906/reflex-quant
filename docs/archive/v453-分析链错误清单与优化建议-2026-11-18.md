## 3. 优化建议（按"今天就能做"排序）

### P0-1 修决策引擎的死链（30 分钟）

- 改 `decision_engine.py:59`：`evidence_json` → `context_json`；顺手确认 `SCHEMA_VERSION` 与 `trade_decisions` 实际列一致（`status`、`score`、`confidence` 都在）。
- 验收：手动 `python decision_engine.py live --once` 不再 traceback；`select count(*) from trade_decisions where decision_source<>'log_decision' and decision_ts>=...` 在下一轮后 > 0。
- 若一时不想动代码：先把 `run_service_guard.sh:19-20` 注释掉，避免每 5 分钟制造一次崩溃日志。

### P0-2 重启引擎并加"代码-进程一致性"闸（10 分钟）

- 停 `com.trident.engine` → 起；随后确认 `runtime/ai_worker_progress.json` 的 `step_ts` 在 5 分钟内更新。
- 在 `/api/health` 里加：读 `realtime_filter.py`/`ai_worker.py` 的 mtime 与进程启动时间，**mtime 晚于进程启动就直接报 `code_stale`**（比 `code_version` 手写字符串可靠）。
- 验收：重启后 1 小时，`gate_verdict='未判定'` 新增 = 0，`filter_reason='gate_down'` 新增 = 0。

### P0-3 门卫主品种标准化（1 小时，收益最大）

在门卫落库前加一层 `normalize_main_asset()`：

```
黄金/金/现货金/XAUUSD → XAU      原油/WTI/布油/炼油厂 → WTI
比特币/大饼/BTC        → BTC      以太坊/ETH           → ETH
Solana/SOL            → SOL
个股/美股/港股/加密主流/山寨/空 → None（同时把 verdict 降为"池外个股"或"无信号"）
```

- 规则门卫必须"有池内主品种才可交易"；LLM 门卫返回"个股/美股"时直接改判 `排除`（这些本来就不该进主分析）。
- 验收 SQL：
```sql
-- 应为 0
select count(*) from raw_news
where ts>=strftime('%s','2026-11-18 22:00:00','-8 hours')
  and gate_verdict='可交易'
  and coalesce(gate_main_asset,'') not in ('BTC','XAU','WTI','ETH','SOL','');
-- 应 < 10%
select round(100.0*sum(target_asset='NONE')/count(*),1)
from ai_decisions where created_at>=date('now');
```
预期：NONE 从 41% 降到 ≤10%，模板决策 116 条/天基本消失，主分析 token 至少省 1/4。

### P0-4 队列兜底按价值分诊（半天）

- `backlog_cap` 只淘汰"低价值"：`gate_unavailable<>2 OR gate_verdict<>'可交易'`；
  可交易行**不参与水位推进**，只受 45 分钟建仓窗约束。
- 把 cap 从 `200/keep 100` 调成 `400/keep 200`（或按内存水位动态），并每小时最多推进一次。
- 验收：`pre_recovery_skip` 中 `gate_verdict='可交易'` 新增 = 0；`DONE/可交易` 从 15.7% 提到 ≥50%。

### P0-5 交易执行幂等（2 小时）

- `quick_sim` 的候选查询加"已尝试"条件：`NOT EXISTS (select 1 from trade_decisions td where td.ai_decision_id=ad.id and td.final_action in ('REJECTED','HOLD','CLOSE'))`，或给 `ai_decisions` 加 `sim_processed_at`。

### P1-1 失败可归因（30 分钟）
