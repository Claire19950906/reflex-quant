# v342 · 多周期结算

> 2026-11-16 · 分支 `v342-judgment-grain` · 纯增量（主口径 5 天不变）

## 一、问题

AI 每条决策都要输出 `expected_horizon`（intraday / 1-3d / 1w+），但结算只有**一个 5 天窗口**：

```
decision_engine.HORIZON_S = 5 * 86400
```

后果：

1. 日内判断被拿去用 5 天结算 —— **方向对、节奏错会被判成判断错**。
2. 这个错还会进 `trade_reflections_v2`，被反思系统当成真错误，污染 E 码归因。
3. 无法回答"这套系统擅长 1 小时还是 5 天"，因为只有一个周期。

## 二、设计

### 1. 新表 `decision_outcomes_horizon`
一条决策 × 5 个周期各一条，主键 `(decision_id, horizon)` 保证幂等：

| 列 | 含义 |
|---|---|
| `horizon` / `horizon_sec` | 15m / 1h / 4h / 1d / 5d |
| `entry_price` / `decision_ts` / `target_ts` | 结算基准 |
| `fwd_price` / `fwd_ts` | 实际取到的远期价（取不到就是 NULL） |
| `outcome_pct` | 裸价收益（与主口径同义） |
| `pnl_pct` | 扣完成本（`cost_model.apply_costs`） |
| `hit` | 按**净收益**判：BUY 正 / SELL 负 |
| `status` | `settled` / `no_price` / `not_executable` / `implausible` |
| `note` | 不结算的原因（可追溯） |

### 2. 取价与口径
- 15m / 1h / 4h / 1d：`ohlcv_intraday` 优先（容差 15m/30m/2h/12h），日线回退。
- **5d：直接复用 `db.forward_price(settle_days=5)`** —— 与主结算同一实现，两处数字必须一致。
- T+1 品种（股票）：`cost_model.earliest_exit_ts` 之前的所有周期记 `not_executable`。
  实测 AAPL 最早可平仓 = 入场后约 26 小时，所以 **1d 也不可执行**，只有 5d 有效。
- `|收益| > 90%` 视为取价异常 → `implausible`，不写 `hit`（与 v310 P1 规则一致）。

### 3. 接入方式
`decision_engine.run_settle_only()` 结算完主口径后，同一趟顺带调 `multi_horizon_settle.run_once()`。
失败只留日志，**绝不阻断主结算**。

## 三、验证

```
python -m pytest tests/test_v342_multi_horizon.py -q                       → 9 passed
python -m pytest tests/test_v342_*.py tests/test_execution_cost_settlement.py \
                 tests/test_decision_guard_v318.py -q                      → 76 passed
```

新增 9 条用例钉死：
- 5 个周期各一条，`15m +1% → hit=1`、`4h −1% (BUY) → hit=0`
- 未到期周期不写空行；重复跑行数仍为 5
- 无行情 → `no_price` 且 `fwd_price`/`outcome_pct` 均 NULL（不猜价）
- +900% → `implausible`，`hit=0`、`pnl_pct` NULL
- AAPL 的 15m/1h/4h/1d 全部 `not_executable`
- SELL 方向 hit 按净收益为负判
- `run_once` 扫 2 条决策 → 写 10 行

迁移验证：`db.migrate()` 后在全新库上确认 `decision_outcomes_horizon` 建表成功、16 列齐全。

## 四、不变量

- `trade_decisions.actual_outcome_pct`、`trade_reflections_v2`、`settle_one` 的口径**一个字没改**。
- 5 天仍是主口径；新表只是"另存一份各周期读数"。
- 老数据不回填（没有分钟线的历史决策只会得到 `no_price`，如实记录）。

## 五、后续可接

| 项 | 说明 |
|---|---|
| API | `/api/decision/horizons?decision_id=` 读新表（`read_horizons` 已实现，未挂端点） |
| 前端 | 复盘页按周期分列展示，一眼看出"这套系统擅长哪个周期" |
| 反思码 | E 码归因可加 `horizon` 维度，区分"方向错"与"节奏错" |
| 回填 | 有分钟线历史（`ohlcv_intraday`）的老决策可批量补算 |
