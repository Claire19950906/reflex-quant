# 三大需求优化总结

> 针对三个核心需求实施的全部优化（含过程修复），附机制说明、参数、默认值与部署状态。
> 对应实施包：v8（时效门槛）→ v9（后台可调）→ v10（分级止盈）→ v11（P3 买卖质量）→ v12（P4 反思深化）

## 需求 1：加强 AI 反思能力 ✅

**目标**：从"每天复盘一次"升级到"每笔即时反思 + 经验持续验证"。

### 1.1 单笔实时反思（P4 新增）
| 项 | 说明 |
|---|---|
| 机制 | 持仓结算后自动入队 `trade_reflections` → 引擎 `reflection_worker` 每 30s 处理 → **LLM 单笔归因**（失败→17 类框架 / 成功→10 类框架，走 OpenRouter→MiniMax）|
| 经验沉淀 | 同类失败原因**累计 ≥3 笔** → 自动生成经验写入 `review_insights`（防单笔噪音）|
| 数据 | `trade_reflections` 表：decision_id / 原因编码 / 名称 / 说明 / 置信度 / 状态 |
| 日志 | `[REFLECT] 处理 N 笔单笔反思` / `[REFLECT] 沉淀经验: ...` |

### 1.2 经验命中验证（P4 新增）
| 项 | 说明 |
|---|---|
| 机制 | 建仓时记录本单**参考的生效经验 id**（`ai_decisions.insight_hit_ids`）→ 引擎每小时统计每条经验"被参考过的交易"胜率 |
| 停用规则 | 样本 ≥5 且胜率 <40% → 自动停用（比原有"全局胜率"评估更精准，只统计真正参考过的交易）|
| 日志 | `[REFLECT] 命中验证停用 N 条低效经验` |

### 1.3 既有基础（会话早期已实现）
- 每日复盘报告：17 类失败 / 10 类成功 LLM 归因 + 占比统计
- 经验规则自动回灌 AI 分析 prompt（`[Review Insights]`）
- 参考信号实时注入（`[Reference Signals]`：品种/方向/阶段/强度/入场时机 + 提示词风格总结语）

### 1.4 过程修复（支撑数据准确性）
- **成败判定修复**：复盘统计原用 `ai_decisions.is_correct`（历史几乎全是 'HOLD'）→ 改用 `quick_sim_trades.verdict`（权威 WIN/LOSS），成功/失败归因从 0/0 变为真实数据
- **成功归因持久化**：`save_report` 原来不存 successes → 补存并读回，刷新后不再丢失

## 需求 2：优化买入/卖出策略（卖出逻辑 + 新闻即时性）✅

**目标**：确保交易信号基于**即时新闻**，买卖判断更果断、不追单。

### 2.1 新闻时效门槛（P0，后台可调）
| 项 | 说明 |
|---|---|
| 机制 | 新闻发布时间距今超过阈值 → **BUY/SELL 信号不再建仓**（过期信号仍分析入库统计，不交易）|
| 默认值 | **2700 秒（45 分钟）**，后台可调（30~86400 秒），引擎 ≤5s 生效 |
| 入口 | 模拟盘页面 `新闻时效 [2700] 秒` |
| 日志 | `[AI] 信号过期，跳过建仓: news=#xx 已 120 分钟` |

### 2.2 买卖即时性 prompt 规则（P0）
```
· 利空+价格未反应 → 果断 SELL（early 吃主跌段）
· 利空+价格已大跌 → 不追空（HOLD 等反弹）
· 利多+价格未反应 → 果断 BUY；已大涨 → 不追多（利好出尽警惕）
· 恐慌/流动性危机类利空 → SELL 置信上调，分钟级窗口
```

### 2.3 买卖方向不对称门槛（P3，后台可调）
| 项 | 说明 |
|---|---|
| 机制 | 多证据闸门方向判定参数化：`BUY 需 ≥0.4`（做多胜率偏低→加严）、`SELL 需 ≤-0.3`（更倾向做空）|
| 入口 | 模拟盘页面 `买/卖门槛 [0.4] / [0.3]`，引擎 5s 生效 |
| 依据 | 做多胜率 53.4% < 做空 56.3% |

### 2.4 新闻新鲜度分级（P3）
| 新闻年龄 | 权重 |
|---|---|
| 0~15 分钟 | ×1.0 |
| 15~30 分钟 | ×0.85 |
| 30~45 分钟 | ×0.7 |
| >45 分钟 | ×0.5（硬门槛已拦交易）|
| 机制 | LLM 打分后按新鲜度加权 score，与硬门槛配合（门槛管禁止、分级管衰减）|
| 日志 | `[FRESH] 新闻 20 分钟前，新鲜度权重 ×0.85 → score +0.43` |

### 2.5 品种×方向组合胜率注入（P3）
- 参考信号新增 **品种×方向** 组（如 `BTC×做多`、`XAU×做空`），注入 AI prompt + 页面展示
- 带总结语：`BTC×做多 6笔胜率67%，该品种×方向组合历史质量高，可提高置信度`
- AI 对低胜率组合自动降置信

## 需求 3：优化止损和出场逻辑 ✅（止损保持原有，完善止盈）

**决策**：按用户要求，**止损保持原有**（到期结算 + 固定移动止损 trailing_callback_rate 不变）；重点**完善止盈（分级部分止盈）**。

### 3.1 分级部分止盈（新增）
| 项 | 说明 |
|---|---|
| 目标价 | **动态** = 入场 ± 系数 × 历史MFE（同品种×事件强度已结算均值，样本 ≥5；非固定值）|
| 触发 | 目标1（×0.6）→ 止盈 **50%**；目标2（×1.0）→ 再止盈 **30%**；剩余 **20%** 交移动止损/到期 |
| 记录 | `ai_decisions` 加 partial_exit_price / partial_exit_ratio / partial_pnl_pct（同一行记录进度，不拆仓）|
| 结算 | 最终盈亏 = 已平部分按平仓价 + 剩余部分按结算价（**加权平均**）|
| 参数（后台可调）| 止盈开关 / 系数1（0.6）/ 系数2（1.0）/ 比例1（0.5）/ 比例2（0.3）|
| 入口 | 模拟盘页面 `止盈 [开] [0.6] [1.0] [0.5] [0.3]`，引擎 5s 生效 |
| 日志 | `[TRACKER] TP #xx SELL XAU 部分平仓 50% @ 4557.00 (pnl +0.72%)` |

### 3.2 既有出场机制（保持）
- 移动止损轮询 **5s**（从 30s 优化，行情响应更及时；价格走 2s TTL 缓存）
- 到期结算：AI 的 expected_horizon（1-3d→2天 / 1w+→7天）或策略 holding_horizon_minutes，默认 120 分钟
- verdict 决策树：MFE/MAE vs IMPACT_THRESHOLD → WIN/LOSS/HOLD

### 3.3 入场即反向的止损行为（现状说明）
- 建仓时 max_price = 入场价 → 移动止损从入场价算 → 反向约 **trailing_callback_rate%（默认 0.5%）** 触发止损
- 0.5% 是固定距离（非波动自适应），高波动品种可能被正常波动扫掉——ATR 自适应止损**按用户要求未实施**（方案已备，需要时可加）
