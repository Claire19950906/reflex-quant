## 4. 还差什么（被额度卡住的那一步）

重跑判断需要调用主分析 chain（`_call_llm_sync`，完整 prompt 约 1.6 万 token/次）。
当前两个 key 均报额度上限：

```
429 {"type":"error","error":{"type":"rate_limit_error",
     "message":"已达到 Token Plan 用量上限：请升级 Token Plan 套餐或购买积分补充用量。 (2056)"}}
```

**恢复后按这个顺序跑：**

| 步骤 | 命令 | 预算 | 目的 |
|---|---|---|---|
| ① 试跑 | `--limit 5 --live` | 约 8 万 token | 验证 JSON 解析、HOLD 比例、成本 |
| ② 小批 | `--limit 20 --live` | 约 32 万 token | 与线上 20 条逐条对比方向一致率 |
| ③ 扩量 | `--limit 100~200 --live` | 160 万~320 万 token | 到 60 笔以上可下结论的样本 |

验收看三件事：**方向一致率**（回放 vs 线上）、**HOLD 比例**（回放不该比线上更沉默）、
**净利是否转正**（如果零延迟仍为负，就不必再纠结延迟了）。

## 7. 时点对齐审计（2026-11-18 追加）

问"是不是全对齐了"，实测答案是：**行情对齐了，prompt 里原来还漏着 16 处**。已全部掐掉。

### 7.1 修掉了什么

原来 `market_context` 只是 prompt 的一部分，`_call_llm_sync` 还会往里塞十几个旁路块，
取数时点全是"跑的时候"：

| 注入块 | 数据来源 | 为什么算未来信息 |
|---|---|---|
| `_build_technical_state_block` | 实时快照 | 现价/RSI/ADX 是 11-18 的，不是 11-16 02:39 的 |
| `_build_calendar_hint` | 实时日历 | 注入的是"未来 24h 财经事件" |
| `_origin_search_block_for` | 实时全网搜索 | 搜到的是这条新闻**后来**的报道与结果 |
| `_stock_context_for` / `_asia_context_for` | 实时行情 | 美股/亚太现价 |
| `_load_reflection_block` | 当前库 | 含 11-17、11-18 的教训 |
| `_load_experience_block_sync` | 当前库 | v186 经验库当前状态 |
| `_load_spa_applied_block_sync` | 当前库 | v199 已应用策略调整 |
| `_build_graph_block` | 当前库 | 因果图谱是回放之后才学到的 |
| `_build_chain_prior_block` | 当前库 | 因果链先验同理 |
| `_hard_data_block` | 当前库 | 事后补录的硬数据 |
| `_load_attribution_block` `_load_kline_block` | 当前库 | 事后归因 / K 线缓存 |
| `market_style_block` | 实时 | 市场风格判定 |
| `get_full_verdict_block` | 实时快照 | server 已算好的水位/方向结论 |
| `_microstructure_block` | 外网(investing/coinglass) | 资金费率/OI/多空比，历史不可还原 |

开关：`--strict`。实现方式是回放进程内 monkey-patch 这 16 个 loader 返回空串，**不改生产代码**。

### 7.2 验证方式（不花钱）

用 `--dump-prompt` 把构建出的完整 prompt 落盘，比注入前/后两份：

| 指标 | 默认 | `--strict` |
|---|---|---|
| user 部分字符 | 5,947 | **2,004** |
| system 部分字符 | 10,270 | 10,270（规则骨架，不动） |
| 出现 `VERDICT` 块 | 1 | **0** |
| 出现"反思错误码" | 4 | **0** |
| 出现"v186 经验" | 1 | **0** |
| 出现"v199 SPA" | 2 | **0** |
| 出现"技术状态读数" | 1 | **0** |
| prompt 里出现 `2026-11-18` | 6 | **0** |
| 残留"资金费率/微观结构" | 11 | 9 → 全是我写的 `N/A` 字样，无一个真实数值 |

严格模式下 prompt 里只剩：锚点行情摘要 + 新闻正文 + 静态事件类型字典（39 行，无时间属性）。

### 7.3 仍然对不齐的四件事（结构性的，别装作解决了）

| 项 | 为什么对不齐 | 影响 |
|---|---|---|
| **prompt 规则版本** | 用的是今天的 v186/v199/v422 规则，不是 11-16 那天的版本 | 规则本身"来自未来"，会系统性影响回放判断 |
| **模型版本** | 用的是当前 MiniMax-M3 | 若期间换过模型/温度，判断分布不同 |
| **微观结构** | 资金费率/OI/POC 历史无存档 | 回放比线上少一块输入，判断必然偏保守 |
| **定价精度** | WTI 1m 断源（止于 11-17 14:28），退 1h | 入场价与真实锚点价有 0.1%~0.5% 偏差 |

结论：**能对齐的是"数据时点"，对不齐的是"规则与模型版本"。**
所以锚点回放只能回答"如果当时用今天这套规则、看当时的数据会怎样"，
不能回答"当时那个系统本来会怎样"。写论文要按前者的口径表述。

### 8.4 中断保护（长期规则，2026-11-18 定）

**规则：中断就断，恢复就重起。恢复那一刻当新起点，停机期堆在队列里的历史新闻一条不处理。**

实现（`forward_pool.py`）：

| 机制 | 行为 |
|---|---|
| `last_scan_ts` | 每次扫描结束写一次时间戳 |
| 间隔判定 | 恢复时若 `now - last_scan_ts > gap_threshold`（默认 600s）→ 起点直接前进到 `now` |
| 无记录 | 没有 `last_scan_ts` → **视同中断**（宁严不宽），同样前进到 `now` |
| 留痕 | `pool_events` 记 `roll_forward`：旧起点、新起点、**被挡在池外的决策条数**、原因 |
| 报告 | 池子报告里显示"中断重置 N 次"及最近一次时间 |

### 8.5 实测（模拟中断 2 小时）

把测试库起点设为 11-17、`last_scan_ts` 设为 2 小时前：

```
[中断保护] 起点 11-17 08:00:00 → 11-18 13:36:43；停机期堆积 124 条决策一律不入池（中断 120 分钟（阈值 10 分钟））
新增 0 条
```

124 条历史决策全部被挡在池外，池内 0 条样本。**这正是要的效果：宁可样本少，不可样本脏。**

生产池已按同一逻辑重启一次：起点 13:08:28 → 13:36:58（跳过 0 条，因为停机期线上本来就没产出）。
