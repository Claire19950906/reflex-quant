# 新闻驱动策略 — 结构与逻辑整理

> 依据 `backend/src_python/` 实际代码整理（2026-07 快照），文档目录：
> `docs/方案.md`（设计意图）、`docs/约定规范.md`（多证据约束）、`docs/新闻.md`（信源问题）、`docs/开发策略.md`（功能清单）。

## 0. 一句话定位

**实时新闻 → 双层过滤去噪 → LLM 宏观博弈推演 → 多证据风控闸门 → 信号落库 → 2 小时真实行情前向验证 → 学习回灌** 的事件驱动量化信号系统（Trident Agent MVP），主战场为 BTC / XAU / WTI。

## 2. 分阶段逻辑详解

### 阶段 0 — 新闻采集

| 信源 | 方式 | 实现 |
|---|---|---|
| FinancialJuice | WebSocket（Centrifugo 协议），毫秒级 | `engine/ingest.py::websocket_ingest` |
| TreeNews | `wss://news.treeofalpha.com` → POST 本地 webhook:9000 | `treenews_bridge.py` + `engine/webhook.py` |
| Telegram 等第三方 bot | POST JSON `{"text","source"}` → :9000 | `engine/webhook.py` |
| TechFlow / 东方财富 / 律动 | REST 轮询（15s，非主链路） | `config.py` URL + `scripts/news_ingestion_pipeline.py` |

采集原则（对应 `docs/新闻.md`）：**WebSocket 推送优先、拒绝轮询**；原始消息先落盘再解析，接收层不做阻塞计算。

### 阶段 1 — 入站清洗（ingest / webhook 共用管线）

顺序执行，全部通过才写库：

1. **HTML 清理** `_clean_html`；
2. **垃圾判定** `_is_content_junk`：内容黑名单（"无正文内容"等占位符）、纯账号名、过短且无金融关键词的文本；
3. **内容去重**：`sha256(text)[:16]` 作为 `[hash:xxx]` 前缀存库，`LIKE '[hash:xxx]%'` 幂等检查（在翻译前做，省 API 调用）；
4. **英文检测 + 前置翻译** `_translate_if_english`：激进英文判定（前缀/字母占比/连续英文词/金融词/数字英文混合），翻译兜底链 **Doubao → Gemini 2.5 Flash → DeepSeek**（OpenRouter），全部失败则原文入库；确保后续 LLM 推演 100% 中文输入；
5. **信源开关 + 每日配额** `news_sources.allow_ingest`：`paper_trading_settings.news_sources` 控制单个源开关，每日入库目标默认 300 条（上海时区）；
6. **双层过滤** `realtime_filter.evaluate_news`（见阶段 2）；
7. **写库**：`raw_news(status, is_noise, relevance_score)` + 时序事件 `news_events`。

### 阶段 2 — 双层过滤（`realtime_filter.py`）

**L1 关键词规则**（微秒级、零成本）：

| 命中 | 结果 |
|---|---|
| `JUNK_WORDS`（空投/教程/AMA/周报/上币公告/辟谣…） | `is_noise=1, status=FILTERED`，直接丢弃 |
| `CORE_WORDS`（美联储/CPI/非农/地缘/ETF/爆仓/特朗普…） | `is_noise=0, status=PENDING, relevance=0.90`，跳过 L2 |
| 都不命中 | 不确定 → 升 L2 |

**L2 LLM 二分类**（OpenRouter，默认 `deepseek/deepseek-chat`，3s 超时）：
- 输出 1 → PENDING（relevance 0.50）；输出 0 → FILTERED；
- **超时/无 key/解析失败 → 放行给 AI**（relevance 0.35），保守原则是"宁可多分析，不把可分析新闻当垃圾丢掉"。

> 设计要点：L1 用词表把高频确定项挡在微秒级，L2 只处理边界样本，避免每条新闻都花 LLM 延迟。

### 阶段 3 — AI 推演（`engine/ai_worker.py`）

**批处理节奏**：每秒 tick → `BEGIN IMMEDIATE` 原子认领 ≤10 条 `PENDING 且 is_noise=0` → 置 `PROCESSING` → 并发分析 → 单事务落库。

**每批注入 4 类上下文**（不是只喂新闻文本）：

1. **市场快照** `market_snapshot.get_snapshot`（Binance USDT 永续）：BTC/XAU 现价、24h 涨跌、资金费率、7d 趋势（Strong Bull/Bear…）、ATR(7d)、7d 区间；失败标 `unavailable` 不造数；
2. **宏观上下文** `macro_context.build_context` 四层：盘面结构（资金费率/基差/持仓量/多空比）、舆情（Fear&Greed）、美联储预期（NY Fed EFFR + ZQ 期货隐含利率）、资金流向（永续主动买卖比/可选 ETF 净流入）；
3. **历史绩效** `_build_performance_context`：近 90 天已结算信号按 `资产 × 方向 × prediction_type` 聚合胜率/平均 PnL（样本 ≥8 才显示），只作研究参考不强制；
4. **Hermes 分席写作 + 已结算技能**：新闻/宏观/风险/交易四席确定性简报，技能只从 settled WIN/LOSS 刷新（样本 ≥8），不下最终单。

**主模型**：当前 roster 为 Aiping `DeepSeek-V4-Flash-0731`（json_mode strict，45s 超时，429 退避 5/10/20s；strict JSON 解析失败会降级重试 prompt 模式）。README 中的 "Kimi K3" 为旧描述。

**推演框架（system prompt 摘要）** —— "宏观博弈推演"，反共识视角：

- 维度 A：叙事 vs 流动性 —— 不被"利好/利空"带偏，反问钱往哪流；地缘冲突推演美元流动性收紧还是溢出；
- 维度 B：拥挤度与派发周期 —— 高位长期利好质疑派发（Distribution Phase），极度拥挤多头=最大空头催化剂；
- 维度 C：跨资产抽血 —— 原油爆拉抽血黄金、美债暴涨抽血 Crypto；BTC 定性为**高 Beta 风险资产**（战争/危机中 SELL，无避险属性）；
- 强制四段式 CoT：`[驱动力] → [水位博弈] → [跨资产联动] → [反共识结论]`；
- 市场快照作为**价格验证层**：利多+已大涨+费率极端 → 警惕 SELL；趋势同向=continuation、反向=reversal 且置信度下调。

**输出 14 字段 JSON**：`reasoning_path / sentiment_score(-1~1) / suggested_action(BUY|SELL|HOLD) / reasoning / market_category(CRYPTO|GOLD|OIL|MACRO|OTHER) / target_asset / prediction_type(reversal|continuation|breakout) / event_phase(early|mid|late) / market_confirmation(positive|negative|unknown) / expected_horizon(intraday|1-3d|1w+) / invalidation_condition / event_strength(low|medium|high) / direct_catalyst / timeframe_match(intraday|swing|macro)`。

**解析三级兜底**：JSON 解析 → 截断 JSON 修复 → 正则提取 → 关键词启发式（利好/利空/观望），保证任何情况都有结果。

### 阶段 4 — 信号加工与风控（`_batch_persist` 单事务）

1. **方向-分数对齐** `reconcile_score_action`：HOLD+强分(|score|>0.3) → 抬成 BUY/SELL；方向与分数符号矛盾 → 以方向翻转分数；**分数严禁 0.0**（置 ±0.05 微偏）；
2. **VIP 加权**：命中 `VIP_KOLS`（Trump/Musk/Powell/FOMC/美联储/Vance/Bessent…）且方向非 HOLD → `|score| × 1.25`（封顶 1.0）；
3. **父子聚合**：同 `market_category + target_asset + suggested_action`、`|score| ≥ 0.25`、1 小时窗口内归并到已有 parent；`child_count+1`、分数更极端则 bump parent、30 分钟内同族数量记为 `cluster_size`（解决"同类新闻持续发布影响衰减/叠加"问题）；
4. **多证据闸门** `decision_guard.evaluate_decision`（见 §3.6）；
5. **策略过滤** `strategy_store.signal_matches`：阈值/资产过滤/事件强度/直接催化（见 §3.7）；
6. **建仓**（两套独立通道）：
   - **正式模拟盘**：`paper_trading_settings.is_running` + 赛道 `tracks`（crypto/gold/oil）匹配 + 闸门通过(可关) + 策略匹配 → 记 `entry_price/max/min`；
   - **快速模拟** `quick_sim`（独立 watcher，15s）：**所有** BUY/SELL 不经过闸门直接按真实行情建仓，默认 5 分钟结算，仅用于盈利率统计评测；
7. 写 `factor_snapshots` / `news_events` / `hermes_observations`，raw_news 置 DONE/FAILED，飞书卡片 + 控制台 consensus 输出。

### 阶段 5 — 前向验证（`engine/forward.py`，每 30s）

对 `settled=0 且 entry_price 非空` 的信号：

- 持仓周期默认 **2 小时**（可被策略参数 `holding_horizon_minutes` 覆盖，15–240min）；
- 每轮更新 `max_price/min_price`，支持策略参数 `trailing_callback_rate` 移动止损；
- 到期或触发止损 → 结算：计算 **MFE（最大有利偏移）/ MAE（最大不利偏移）/ MFE 到达时间**，按资产阈值 `IMPACT_THRESHOLD`（BTC/ETH/SOL=2.0%，XAU/GOLD=1.0%，WTI=1.5%）裁决：

```
A. MFE < 阈值 且 MAE < 阈值        → HOLD（市场没动，不是新闻驱动）
B. MFE ≥ 阈值 且 ≤45min 且 MFE>MAE → WIN（方向对、反应快）
C. MAE ≥ 阈值 且 MAE > MFE         → LOSS（方向错）
D. 其余（MFE 太慢/打平）           → HOLD（非新闻驱动）
```

- 落库 `exit_price / is_correct / mfe_pct / mae_pct / forward_pnl / mfe_time_mins` + `signal_performance` 时序表。

> 设计意图：**用"2 小时窗口内价格实际偏移"而非"事后涨跌"判定对错**，且要求 MFE 快速（≤45min）到达，过滤掉"方向蒙对但其实是别的行情"的情况。

### 阶段 6 — 学习回灌

- **绩效注入**：每次 batch 把近 90 天同类信号胜率/PnL 注入 prompt，LLM 可据此降档/升档；
- **Hermes 技能**：从已结算 WIN/LOSS 刷新 `hermes_skills`（样本 ≥8），随 prompt 回灌；
- **卡方校验** `evidence.py`：同类历史样本做卡方检验（df=1，最小样本 8），p 值大 → 置信度打折（p<0.05→×1.0，<0.20→×0.85，否则 ×0.70），过滤"LLM 脑补的历史规律"。

### 阶段 7 — 对外输出

| 出口 | 说明 |
|---|---|
| `api_server.py` :8000 | FastAPI：`/api/events`、`/api/events/stream`(SSE)、K 线、Excel 导出、Agent Chat（Text-to-SQL 数据副驾） |
| `frontend/` :3000 | Next.js 14 实时信号台 |
| 飞书群机器人 | `engine/alerts.py`，BUY 绿 / SELL 红 / 灰，fire-and-forget |
| `dashboard/` :8501 | Streamlit 离线复盘看板（直读 SQLite，不在实时链路） |

## 3. 核心决策逻辑（关键机制详解）

### 3.1 Score 锚定框架（LLM prompt 内 5 级）

| 区间 | 含义 | 典型事件 |
|---|---|---|
| ±0.05~0.15 | 弱信号，情绪扰动 | 官员口头表态、第三方评论 |
| ±0.15~0.35 | 轻度，有资金含义但间接 | 二级数据超预期、监管传闻 |
| ±0.35~0.55 | 中度，直接推动供需/风险偏好 | CPI/NFP 大幅偏离、交易所黑客 |
| ±0.55~0.75 | 强信号，直接催化+趋势共振 | FOMC 意外转向、ETF 获批、OPEC 减产 |
| ±0.75~0.95 | 极端，结构突变/黑天鹅 | 战争爆发、央行无限 QE、交易所破产 |

叠加规则：`direct_catalyst=true` → 上浮一档；`event_strength=low` 上限 ±0.35 / `medium` 上限 ±0.70；`market_confirmation=negative` → 下调一档；历史胜率 <30% 下调一档、>70% 上浮一档；与 1H 趋势同向 +0.05~0.10、反向 −0.05~0.10。

### 3.2 多证据闸门（`decision_guard.py` + `evidence.py`，对应 `docs/约定规范.md`）

7 个因子加权合成 `final_score`：

| 因子 | 权重 | 来源 |
|---|---|---|
| news_sentiment（AI 情绪分） | 0.30 | LLM sentiment_score |
| market_confirmation | 0.20 | LLM 字段 + 24h 涨跌 |
| trend（7d 趋势） | 0.15 | 市场快照 |
| volatility（1−ATR/10） | 0.10 | 市场快照 |
| funding（−资金费率/0.1） | 0.10 | 市场快照 |
| cluster_heat（同族密度） | 0.10 | 30min 聚合数 |
| historical_confidence（历史胜率偏离 50%） | 0.05 | 已结算样本 |

- `final_score ≥ +0.3 → BUY，≤ −0.3 → SELL`，否则 HOLD；
- **证据层**：因子 -1~1 映射为 0-10 证据分，可审计；
- **校验层**：卡方检验打折置信度（见阶段 6）；
- **反幻觉层**：多头新闻 + 空头盘面/极端资金费率 → 标记矛盾，每条扣 12 分置信度（上限 36）；
- 统一输出 `confidence 0-100`，**< 55 不出方向性结论**（降级 HOLD）。

### 3.3 策略层（`strategy_store.py`，回测与实盘共用口径）

参数：`signal_threshold`(0.3–0.9)、`notional_usdt`、`leverage`、`trailing_callback_rate`(0.1–5.0%)、`holding_horizon_minutes`(15–240)、`min_event_strength`、`asset_filter`、`require_direct_catalyst`。

内置种子策略：

| 策略 | 阈值 | 名义本金 | 杠杆 | 追踪止损 | 持仓 | 特点 |
|---|---|---|---|---|---|---|
| news-threshold（默认） | 0.5 | 30 USDT | 5x | 0.5% | 120min | 对齐实盘默认 |
| conservative | 0.7 | 15 USDT | 3x | 0.8% | 120min | 只吃 strong + 直接催化 |
| aggressive | 0.35 | 45 USDT | 5x | 0.3% | 60min | 低阈值紧止损 |

### 3.4 前向验证裁决阈值（`config.IMPACT_THRESHOLD`）

BTC/ETH/SOL = 2.0%，XAU/GOLD = 1.0%，WTI = 1.5%（即"新闻推动价格偏移多少才算有效"）。

### 3.5 其他关键常量

| 常量 | 值 | 作用 |
|---|---|---|
| `BATCH_SIZE` | 10 | 每批 AI 分析条数 |
| `_AGG_WINDOW_HOURS` | 1h | 父子聚合窗口 |
| `_AGG_MIN_SCORE` | 0.25 | 聚合最小 |score| |
| `VIP_SCORE_BOOST` | 1.25 | VIP 信号加权 |
| `CONFIDENCE_GATE` | 55.0 | 闸门置信度下限 |
| `MIN_SIGNIFICANCE_SAMPLE` | 8 | 卡方/绩效最小样本 |
| `QUICK_SIM_HORIZON_MINUTES` | 5 | 快速模拟持仓周期 |

## 4. 数据模型（schema 唯一权威：`db.py`）

| 表 | 角色 |
|---|---|

| `strategies` / `strategy_versions` | 策略库与版本（params JSON） |
| `paper_trading_settings` / `paper_trading_runs` | 模拟盘开关/赛道/运行快照 |
| `quick_sim_trades` | 快速模拟交易 |
| `hermes_observations` / `hermes_skills` | Hermes 学习闭环 |
| `macro_snapshots` | 宏观指标时序 |
| `backtest_runs` | 回测记录 |

## 5. 与 `docs/方案.md` 六大新闻问题的对照

| 方案要求 | 现状 | 落点 |
|---|---|---|
| ① 趋势/冲突类分类 + 打分 | ✅ 部分 | `prediction_type / event_phase / event_strength / timeframe_match` 字段；无独立 impact 0-10 字段，用 sentiment_score 锚定替代 |
| ② 事件重要程度打分 | ✅ | sentiment_score 5 级锚定 + 前向验证 IMPACT_THRESHOLD |
| ③ 新闻更即时 | ✅ | FinancialJuice/TreeNews WebSocket 主链路；原始消息先落盘再 AI |
| ④ 同类新闻影响持续发酵 | ✅ 部分 | 父子聚合（1h 窗口）+ cluster_size；**未实现**指数衰减系数 `decay_coeff / remaining_impact` |
| ⑤ 市场逻辑和叙事改变 | ⚠️ 近似 | 无 `narrative_shift` 字段；通过 prompt 反共识框架 + 市场快照交叉验证 + market_confirmation 近似处理 |
