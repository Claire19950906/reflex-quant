# Trident v170 数据通道统一口径

> **核心原则**：所有数据源共用同一套校验、定义、字段标准，禁止每个通道单独一套逻辑。
> 底层数据本身保持一致，不需要人工核对匹配；从根源杜绝口径冲突。
> 后续新增统计面板必须复用这套统一标准，禁止单独开发独立计算逻辑。
> **自动对账仅作为异常兜底告警**，不能用来修复底层逻辑缺陷（见 `id_reconcile` 模块）。

最后更新：v170 P0+ 增量交付（trade_uuid 全链路 + 应急对账）

---

## 1. 主键标准（身份 ID）

| 字段 | 角色 | 来源 | 用途 |
|---|---|---|---|
| `trade_uuid` | **全链路身份 ID**（跨 5 表唯一） | `ai_decisions.id` → UUID v5（namespace=DATA_PIPELINE） | paper ↔ reflection ↔ error ↔ quick_sim ↔ decision 串联 |
| `decision_id` | ai_decisions ↔ reflection 内部 FK | `ai_decisions.id` | 单次回溯 |
| `alert_id` | 单次对账事件指纹（去重 / 幂等写） | UUID v4 random | `id_reconcile_alerts` 主键 |
| `paper_trading_run_id` | 一次 paper run 范围 ID | `paper_trading.run_id` | 关联同一 run 内的所有决策 |

**强约束**：
- 任何新增数据通道**必须**接 trade_uuid（缺失→ missing_uuid alert）
- 跨表 JOIN 优先用 `trade_uuid`，`decision_id` 仅在 ai_decisions ↔ reflection 局部使用
- 不要直接用 `id`（无 schema 漂移保护）

---

## 2. 时间口径

| 维度 | 标准 | 说明 |
| 存储 | **UTC**（TEXT，ISO8601） | SQLite 全部时间字段统一 UTC |
| 前端展示 | **Asia/Shanghai（UTC+8）** | 所有 `<DateTime>` 组件必须 `fmtBeijing()` 转换 |
| 时段标注 | 同期数据必须标 `[模拟]` / `[实时]` / `[回测]` | 见 §3 |
| 范围 | 今日 / 近 7 天 / 近 30 天 / 自定义 | 所有面板必须支持这 4 个标准时段 |

**禁止**：
- 单点直接 `new Date(row.created_at).toLocaleString()` —— 必须走 `lib/time.ts` 的 `fmtBeijing()`
- 任何 SQL 用本地时区过滤（必须 `datetime('now')` + UTC 比对，或显式 `Asia/Shanghai`）

## 3. 类型维度（数据来源）

| 维度 | 标识 | 数据源 | 用途 |
|---|---|---|---|
| 实时信号 | `[实时]` | `ai_decisions` + 未 settle 的 `quick_sim_trades` | 跑道监控 / 实时决策流 |
| 模拟交易 | `[模拟]` | `quick_sim_trades`（settled=1） | 快速测评（B 块） |
| 真实持仓 | `[真实]` | `paper_trading.positions` + `trade_reflections_v2` | 历史真实交易复盘（A 块） |
| 回测 | `[回测]` | `backtest` / `experience_rules` | 策略回测 / 经验规则 |

### 3.1 K 线数据源路由（v2026.10.05 新增）
| 资产类别 | 主源 | 兜底 | 路由函数 |
|---|---|---|---|
| okx_swap（XAU/XAG/WTI/HG 等） | OKX 永续合约 | **Yahoo Finance v8 chart**（GC=F/SI=F/CL=F/HG=F 等） | `quote_sources.fetch_asset_candles_with_yahoo_fallback()` |
| binance_fapi（BTC/ETH/SOL） | Binance 永续 | （未实现 Yahoo 兜底） | `quote_sources.fetch_okx_candles()` 直接调用 |
| stock/index（DXY/VIX 等） | — | Yahoo Finance v8 chart | `quote_sources.fetch_yahoo_candles()` |

**路由原则**：
1. **OKX 优先**：实时性最好（延迟 ~1s）
2. **Yahoo 兜底**：当 OKX 不可达（SNI 阻断/无代理），自动降级
3. **都不行 → None**：不合成假 K 线，调用方决定如何处理
4. **统一输出格式**：`(ts_ms, open, high, low, close, volume)`（与 OKX 完全对齐）

**详见**：[`docs/Yahoo兜底运行手册.md`](./Yahoo兜底运行手册.md)

**联动复盘规则**：
- 选定时段后，**必须同时拉取**该时段内 `[实时]` 信号和 `[模拟]` 交易，按 trade_uuid JOIN
- 一条 trade_uuid 在同一时段内可能同时出现在 `[实时]`（产生时刻）和 `[模拟]`（settle 时刻），**不是重复**

## 4. 分类标准（market_category / event_type_code）

### 4.1 `market_category` 白名单（6 个，**禁止兜底**）
```
CRYPTO  GOLD  OIL  STOCK  MACRO  COMMODITY
```

> **v170 P0+ 修订**：删除 `OTHER` 兜底，新增 `COMMODITY`（白银/铜/农产品等小宗）。
> 不可分类 → `event_type_code='low_value'` + `quarantined_at` 时间戳 + alert 通知
> （用户反馈："不该出现『其他』兜底分类，有价值新闻需要正确归类"）

### 4.2 `event_type_code` 白名单（27 个，`dim_event_type`）

```
geopolitical_conflict  geopolitical_easing   rate_hike  rate_cut
macro_policy           macro_speech          cpi        cpi_release
nfp                    tips                  dxy        central_bank_gold
opec_cut               opec_increase         oil_inventory
crypto_etf             technology_breakthrough  chip_capacity
earnings               earnings_release      merger_acquisition
hack_attack            regulation_policy     ipo_listing
natural_disaster       pandemic_outbreak     supply_chain
trade_tariff           market_event
+ low_value (新增；非真分类，作为"无可分类"标记，由 id_reconcile 隔离)
```

**严禁**：
- ❌ `"other"` / `"其它事件"` / `"undefined"` 兜底（v170 P0+ 之前 _etc_default 默认值，已删除）
- ❌ LLM 自由字符串（必须 schema 校验，失败 → 重试或 quarantined）
- ✅ 实在无法分类 → 走 `low_value` 路径（v170 P0+ 新增）

### 4.3 target_asset 白名单
```
BTC ETH SOL  XAU XAG  WTI  CN_STOCK US_STOCK HK_STOCK INDIVIDUAL_STOCK
SKHYNIX  CNY USD EUR  NONE
```

`NONE` 仅用于**无可交易标的**的政策/峰会/外交新闻（行 2541 强制规则），不视作"分类失败"。

## 5. 判定状态（verdict / pending）

| 状态 | 判定结果 | 显示 |
|---|---|---|
| 已判定 | `WIN` / `LOSS` / `FLAT` | 正常徽章 + pnl |
| 待判定 | `pending` | 黄色徽章 + **卡住原因提示**（见 §6） |
| 失败 | `FAILED` / `HOLD` | 灰色徽章 + AI 拒绝说明 |

**判定卡住原因**（必填字段 `pending_reason`）：
- `no_price_data` — 时间窗内无 kline 数据
- `extreme_unsettled` — max_price/min_price 缺失
- `reflection_timeout` — reflection worker 超时（>30s）
- `data_quarantine` — 被 id_reconcile quarantine，冻结判定
- `model_retry_exceeded` — LLM 重试 3 次仍失败

### 5.1 重新判定流程（v180 P0+）

后端把"待判定"拆成 **"是不是 pending"** 和 **"能不能立刻补判"** 两层：

| 层 | 函数 | 职责 |
|---|---|---|
| 派生 | `history_review._derive_pending_reason(t)` | 给每笔 settled=1 交易产出 `pending_reason`；空字符串 = 已判定 |
| 单条 | `POST /api/history/news-trades/{news_id}/rejudge` | 对单条新闻下所有 pending 交易用当前最新行情重算 verdict |
| 统计 | `GET /api/history/news-trades/pending-count?hours=...` | 不修改数据，只统计窗口内 `{news_with_pending, pending_trades, pending_by_reason}` |
| 批量 | `POST /api/history/news-trades/rejudge-batch?hours=...&limit=...` | 对窗口内所有 pending 新闻去重后逐个调单条接口（limit 防爆） |

**前后端协作**：
- 前端 `review-history-panel.tsx` 顶部徽章 = `pending-count` 数据（`⏳ 待判定 N 笔 / M 条新闻`）
- 详情面板里只要 `hasPending` 就显示 `🔁 重新判定` 按钮
- 顶部徽章还内嵌 `🔁 批量重判` 按钮，走 batch endpoint（limit=50 上限）
- 结算价源复用 `api_server._quick_sim_price`（与 settle_trades 同源，保证行为一致）
- 批量任务里某一条抛异常不会中断整批，per_news 字段返回 `error` 标记

## 6. 字段一致性（必读）

下表列出**所有面板必须复用**的字段映射。任何新面板禁止重新定义。

| 字段名 | DB 列 | TS 类型 | 转换 |
|---|---|---|---|
| 时间戳 | `created_at` / `entry_time` / `settled_at` | `string` (ISO8601 UTC) | `fmtBeijing()` → 显示 |
| 主键 | `id` (单表) / `trade_uuid` (跨表) | `string` (UUID) | 直接展示 / `<UUIDLink>` |
| 标的 | `target_asset` / `asset` | `string` | `<AssetBadge>` |
| 方向 | `suggested_action` | `string` (BUY/SELL/HOLD) | `<ActionBadge>` |
| 判定 | `verdict` | `string` | `<VerdictBadge>` |
| 盈亏 | `forward_pnl` / `pnl_pct` | `number` | `fmtPct()` |
| 分类 | `market_category` + `event_type_code` | `string` + `string` | `<CategoryChip>` 双标 |
| 时段 | (派生) | `[模拟] \| [实时] \| [真实] \| [回测]` | `<DataSourceBadge>` |

**统一 import**（前端）：
```ts
import {
  fmtBeijing, fmtPct, fmtPrice,
  ActionBadge, VerdictBadge, AssetBadge, CategoryChip,
  DataSourceBadge, UUIDLink,
} from '@/lib/data-channel-standards'
```

## 7. 校验 / 告警 / 隔离

### 7.1 校验
- `db.py` 的 `assert_readonly_sql` + `dim_event_type` / `dim_market_category` enum 强约束
- ai_worker 的 Pydantic schema 在 INSERT 前校验 7 个 enum（见 ai_worker.py 行 1056-1075）

### 7.2 告警（`id_reconcile_alerts` 表）
| alert_type | severity | 含义 |
|---|---|---|
| `missing_uuid` | warn | trade_uuid 为空，破坏 history 完整性 |
| `orphan_reflection` | warn | reflection 的 decision_id 在 ai_decisions 已不存在 |
| `mismatch` | **critical** | UUID 串联后 entry_price/entry_time 不一致 |
| `low_value` | info | 27 个 event_type + 6 个 category 都无法归类 |
| `resolved` | info | 用户已手动解锁，写一条审计 |

### 7.3 隔离（quarantine）
- 错配 ≥ 0.5% 阈值自动打 `quarantined_at`
- Dashboard / XLSX 默认排除
- 一键重试：`POST /api/review/retry-verdict` + `POST /api/admin/id-reconcile/resolve`

新增任何统计面板，**必须**走以下标准组件：

| 面板类型 | 必复用 | 必查 |

| 时间选择器 | `<PeriodSelector today\|7d\|30d\|custom>` | UTC→北京转换 |
| 判定状态 | `<VerdictStatusBadge pending\|decided\|failed>` + pending_reason | 见 §5 |
