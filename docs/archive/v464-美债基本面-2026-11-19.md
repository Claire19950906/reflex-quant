## 一、为什么做美债

v460 把黄金/原油/美元/外汇/加密接进了 `decision_guard` 的 0.08 基本面权重，但**美债是 0 分**：
库里 FRED 已有 `dgs2/dgs5/dgs10/dgs30/t10y2y/tips10y/t10yie/hy_oas/baa10y`，COT 也有
`tbond/tnote2y/tnote5y/tnote10y` 四个期货持仓 —— **原料最全、逻辑最硬，却一个分量都没做**。
美债只以新闻标的出现（`dim_asset` 里没有债券代码），所以先做别名归一，再算分量。

## 二、分量口径（符号写死在代码里，可审计）

方向约定：**分数正 = 看多债券价格（收益率下行），负 = 看空债券价格（收益率上行）**。

### 长久期（UST / US10Y / US30Y / TLT / IEF / ZB / ZN）

| 分量 | 权重 | 数据 | 符号理由 |
|---|---|---|---|
| `real_yield` | 0.26 | `tips10y` 分位 | 实际利率越高，长久期现值折损越大 → 反向 |
| `real_yield_chg` | 0.10 | `tips10y` 20 日变化 | 每 +0.40pp 记满反向（快速上行=债券挨打） |
| `breakeven` | 0.18 | `t10yie` 分位 | 通胀预期越高，长端越被抛 → 反向 |
| `curve` | 0.16 | `dgs30 - dgs10` 分位 | **carry 视角**：越陡=期限溢价越高=做多久期的持有补偿越厚 → 正向 |
| `cot` | 0.20 | `tbond.cot_noncomm_net` 分位 | 投机净多越拥挤越反向 |
| `credit` | 0.10 | `hy_oas` 20 日变化 | 高收益利差走阔=风险偏好恶化→国债避险买盘 → 正向（每 0.60pp 记满） |

### 短久期（US2Y / SHY / ZT）

| 分量 | 权重 | 数据 | 符号理由 |
|---|---|---|---|
| `policy_rate` | 0.34 | `dgs2` 分位 | 2Y 是"现金替代"，票息补偿越厚越有吸引力 → 正向 |
| `real_yield` | 0.16 | `tips10y` 分位 | 同长久期反向 |
| `cot` | 0.24 | `tnote2y.cot_noncomm_net` 分位 | 反向 |
| `breakeven` | 0.14 | `t10yie` 分位 | 反向 |

**为什么长短久期分开**：一个 2Y 债不吃久期风险，实际利率与通胀预期对它的影响远小于政策利率；
用同一套 6 分量会给短久期品种一个"假精确"的读数。短久期不装 `curve` 也是同理（曲线是长端现象）。

**曲线为什么用 carry 而不是动量**：同一个"陡"，动量视角是"长端在跌=利空"，carry 视角是
"期限溢价高=持有补偿厚=利多"。两种视角都不算错，但**必须写死一种**，否则同一张表里两套符号
会互相抵消。本模块选 carry，并在 `detail` 里把理由写出来，方便复盘时判断是不是选错了。

## 三、硬门槛与硬缺口

- 沿用 v460 三道门槛：分量 <2 个、或独立数据族 <2 个 → `available=False`（不给 0 分装懂）；
  `_COMP_SOURCE` 把 `breakeven→t10yie`、`curve→curve`、`credit→hy_oas` 登记成独立族，
  防止"实际利率水平 + 实际利率变化"被当成两条独立证据。
- 三条永远不会被填的 gap 直接写进 `gaps`，让上层知道"这分数缺了什么"：
  - 拍卖需求（bid-to-cover / 间接投标占比）：未接入财政部 auction 数据；
  - 期限结构 carry/roll-down：缺债券期货或 ETF 日线，算不出持有收益曲线；
  - 海外持仓（TIC 报告）：未接入。

## 四、暴露出来的真问题：历史只有 38 天，分位是假的

跑通后发现所有 FRED 序列在库里都只有 **38 天**（最早 2026-10-03，建库起每天追加一条）。
也就是说 v460/v464 里所有的"历史分位 83%"其实是**"最近 38 天里的 83%"**——窗口太短会让分量
在几个月尺度上静默失真，而且从读数上完全看不出来（这是比"缺数据"更危险的一类缺陷）。

处理：新增 `backend/scripts/oneoff/backfill_fred_history.py`，走 FRED 官方 JSON API
（`/fred/series/observations`，支持 `observation_start` + `limit=20000`，和线上 `fred_feed`
共用同一个 key），回填 **3 年日频历史**，写进 `macro_snapshots`（`source='fred_csv'`、
payload 标 `backfill=True`），`_ms_series` 按天去重与实时行不冲突。

> `fredgraph.csv` 在这台机器上被 TLS 掐断（`UNEXPECTED_EOF_WHILE_READING` / read timeout，
> 14 条序列全灭），只作兜底；官方 JSON API 重试后 14/14 成功。

结果：**10,214 行**历史入库，14 条序列各 724~761 天（2023-11-20 → 2026-11-18）。
随后把 `_HIST_DAYS`（分位窗口）从 400 天提到 **1000 天（~2.7 年）**。

## 五、回填前后对照（所有依赖 FRED 分位的分数都变了）

| 资产 | 回填前（38 天窗口） | 回填后（~2.7 年窗口） | 主要变化原因 |
|---|---|---|---|
| UST 长久期 | −0.0898 | **−0.2150** | 实际利率 2.89% 在 3 年里是 98% 分位（不是 83%） |
| US2Y 短久期 | +0.5000 | **+0.5370** | 2Y 4.80% → 92% 分位 |
| XAU | −0.4569 | **−0.5549** | 实际利率分位抬升 + 美元走强 |
| USD | +0.4892 | **+0.6864** | 同上，且 2Y 分位 92% |
| EURUSD | −0.4892 | **−0.6864** | 美元镜像 |
| USDJPY | +0.0296 | +0.0296 | 利差与 COT 分位未变 |
| BTC | −0.2189 | **−0.0067** | 资金费率/未平仓分位窗口变长 |
| ETH | −0.7087 | −0.7525 | 同上 |
| WTI | +0.0637 | +0.0637 | 走 EIA/COT，不依赖 FRED 窗口 |

**这张表就是"为什么必须回填"的证据**：同一个 2.89% 的实际利率，38 天窗口认为"偏高但有限"，
2.7 年窗口认为"接近三年最高"——后者才是决策该看到的量。

## 七、测试

`backend/tests/test_ust_fundamental_v464.py` **9 条**（内存假库，不发网络）：

1. 实际利率高位 + 通胀预期抬升 → 负分，`real_yield`/`breakeven` 双双为负；
2. 镜像场景（实际利率低位 + 通胀回落 + 信用利差走阔）→ 正分；
3. 信用利差快速收窄 → `credit` 为负（避险需求下降）；
4. **同一个 2.89%，历史不同结论翻转**：0.2→2.89 的序列里是高位（负），5.0→2.89 的序列里是低位（正）
   —— 钉死"用分位不用绝对值"；
5. 曲线：陡的那个 `curve` 分必须更高（钉死 carry 视角）；
6. 短久期跟政策利率走、不装 `curve`、`duration='短久期'`；
7. 长久期 6 分量齐全 + 三条硬缺口（拍卖 / TIC / carry）都在；
8. 单族数据（只有实际利率）→ 判不可得，不硬凑；
9. 别名与路由：`美债→UST`、`10Y→US10Y`、`TLT/US2Y` 走 alt 且不报 `no_data`。

全量回归：**230 passed, 1 warning**（v460 基线 221 + 本版 9）。
