# W3：把审计接在决策前（已完成，shadow 模式）

> 目标：审计覆盖率 0.09% → 100%，且不改变任何交易行为。
> 结论：**516 / 516 = 100%**，单条 ~0.6ms（P50），判定与离线回放 0 差异。

## 2. 时机为什么关键

原来反思是 `com.trident.weekly_reflection.plist`（周一 09:00 周报），只跑一部分决策：
51 条错误覆盖 43 条决策 / 483 = **8.9%**，且时间跨度只有 17 小时（W3 之前的存档口径）。

现在审计发生在 **INSERT 之后、提交之前**，用**同一条连接**：
决策行还没 commit，只有这个连接看得见 —— 所以必须借用连接，不能新开（WAL 下还会互相等锁）。

代价：每条决策多 **0.55ms**（P50），P95 5.7ms，最慢 329ms 出现在 rejects 写多条 finding 的那条。


## 5. 开关（环境变量，重启生效）

| 变量 | 默认 | 作用 |
|---|---|---|
| `AUDIT_GATE` | `on` | `off` 完全关掉门禁 |
| `AUDIT_GATE_MODE` | `pretrade` | `full` 会纳入事后型码（E007/E016/E017/E018） |
| `AUDIT_GATE_ENFORCE` | 未设 | **预留，未接线**（见第 8 节）|
| `AUDIT_GATE_OUT` | `audit_out/gate` | reject 报告落盘目录 |

**只有 shadow：只审不改。** 真拦会改变正在跑的交易系统输出，
先用 shadow 把误报率、延迟跑成事实，再决定要不要真拦。

## 7. 副作用与回滚

**副作用**：`decision_errors` 现在包含 `source='audit_gate'` 的行，下游几处统计的分母会变——
`capability_scorecard`（按 error_code 统计命中决策）、`attribution_reviews` 的维度归类、
`meta_reflection_updater` 的 E020 计数。这些统计会**从"抽查样本"变成"全量"**，数值会动，方向是变准。

**回滚**（完全可逆）：

```sql
DELETE FROM decision_errors WHERE source = 'audit_gate';
DROP TABLE IF EXISTS audit_gate_log;
```

再把 `ai_worker.py` 那 8 行删掉、`AUDIT_GATE=off` 即可。改前整库备份在 `/tmp/pre-gate-backup.db`。
