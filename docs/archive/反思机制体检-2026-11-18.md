## 二、七个可优化点（按杠杆排序）

### P0-1 · 影子反思层在生产上是"0 样本"，不是"样本在积累"

| 项 | 内容 |
|---|---|
| 现象 | `shadow_reflections` 表 **0 行**，但水位已推进到 `2026-11-18T22:42:36` |
| 证据 | `--dry-run --since 2026-11-17` → **candidates 45**：`direction_ok 24 / wrong 20 / flat 1`。判据完全判得动，就是一条没入库 |
| 真因 | `shadow_reflections.run()` 每跑一次把 watermark 写成 **`now_ts`**（`_set_watermark(conn, now_ts)`），而取数是 `WHERE decided_ts >= watermark`。结算要等 4 小时，跑批间隔也是 4 小时（`StartInterval 14400`）——**水位永远跑在结算前面，样本被永久跳过** |
| 为什么 v413 没发现 | 它用 `--dry-run --since` 手工验证，绕过了水位；正式增量一次没跑通 |
| 改法 | ① 增量改按 **`exit_ts`**（或 `settled_at`）推进；② 加 48h 回看窗口，靠 `UNIQUE(source,source_id)` 幂等 upsert 兜住迟到结算；③ 不要再把 watermark 写成 `now` |
| 验收 | `--report` 从 `0` → **≥45**；之后每日 +10~12 条；`SELECT verdict,COUNT(*)` 出现 ok/wrong 两档 |

### P0-2 · 策略补丁把"同一批 5 笔交易"按 7 个错误码重复计了 7 次

| 项 | 内容 |
|---|---|
| 现象 | `policy_patch_queue` 8 条 pending：7 条 `error_code_pnl`，`sample_size` 全是 5，`cumulative_pnl_impact` 全是 **-266.75%**，只换了错误码（E001c/E014/E020/E021/E022/E024/E026） |
| 真因 | `review/reflection_policy_updater.py:160` 按 `error_code` 分组、`SUM(forward_pnl)`。同一批决策同时命中多个码 → 同一笔 pnl 被重复累加；且 5 笔样本、无对照组，置信度却按"亏损幅度"给到 0.6 |
| 影响 | 审的人会以为"7 个码各亏 266%"，实际是**同一批 5 笔、共 -53.35%/笔**。这是会被一抽查就穿的数 |
| 改法 | ① 每笔交易只归一个主码（或按"有码 vs 无码"配对比较，用**差值**不用求和）；② n≥20 且差值置信区间不跨 0 才入队；③ 同一 `source_reflection_ids` 只允许一条补丁；④ 把 #34–#40 标 `invalid` 或清掉 |
| 验收 | 同一批交易只产出 1 条候选；`cumulative_pnl_impact` 不再出现 7 条相同数字 |

另 1 条 `reflection_pattern`（#33，sample 50，理由"高频短语: 无"）同样是假的：
50 条"低分反思"全部来自 **171 条模板行**（`reflection_self_score=0.0`），"高频短语"当然算不出来。

### P0-3 · 模板反思污染了所有质量指标

| 项 | 内容 |
|---|---|
| 事实 | 171 条 `origin='template'`（HOLD）：`depth_score` **全部 = 4**、`reflection_self_score` **全部 = 0.0**、`evidence_strength_score` **全部 <1**、lesson 平均 88 字 |
| 后果 | ① `depth_score≥3` 这条门槛永远通过，"深度分"失去区分度；② 自评 0 分把"低质短语"补丁和所有均值拉平；③ 元反思按 layer/signal 分组时被模板灌满；④ 对外"189 条反思"里 90% 是模板 |
| 改法 | 所有**质量类、队列类、元反思类**查询统一加 `origin<>'template'`（或干脆把 HOLD 漏单记录迁到 `missed_signal_log`，反思表只留成交/影子样本）；模板行不再写 `depth_score` |
| 验收 | "反思条数"报两个数：`真实反思` / `漏单记账`；质量均值只按真实反思算 |

### P1-4 · "闭环回流"目前是三条假通路

| 通路 | 实际状态 | 证据 |
|---|---|---|
| `experience_applications` | **0 行** | 反思结论从未真正应用到某条决策 |
| `ai_decisions.insight_hit_ids` | 靠 `_auto_match_insights` 关键词 Jaccard 自动填 | 近 2 天 **233/565 = 41%** 有值，但 `experience_applications` 是 0；`trade_reflection_llm` 的 `applied_experience_ids` 13 条只被一个 router 读 |
| `bias_after_reflection` | 同一句模板换数字 | 近 2 天 152/565=27% 非空，样例全部是"single-source 应降 confidence 上限 0.5 → 权重应下调(-0.1…)，参考 pnl=-0.3xx" |
| `review_insights` 注入 | 106 条中 92 条 `observe_only=1`，可注入 5 条 | 5 条全是 `source_samples≤7`、`partial/param_rule` |

**改法（最小可用 A/B）**：按 `hash(decision_id)` 10% 分流对照组——treatment 注入该条 lesson，control 不注入，其余完全一致；用影子账本的 4h 命中做终点，累计到每组 ≥60 再谈"有没有用"。在此之前，**不要再把"命中率"当闭环指标**，并把 hit 来源写成 `model` / `auto`，auto 不计入任何比率。

### P1-5 · 判据和样本源错位：反思在"没有答案的地方"找答案

| 现象 | 真因 | 改法 |
|---|---|---|
| verifier 94% 判"不可分离" | HOLD 无 pnl、无当日行情，判据只能判"判不了" | 把 **可判定率** 做成一级指标（不是覆盖率）；终点用影子层 4h 真值，不用缺失的 pnl |
| LLM 反思 3 天只有 13 次调用 | 候选 SQL 要 `pnl<-0.5%` 且未做过深度反思；已结算亏损样本只有 15 条 | 样本源换成影子层（每天 12 条、天然有结算）；深度反思只对"方向判错"的样本跑 |
| 元反思 107 条全 `no_baseline_new` | 要求同 (layer,sub_layer,signal) ≥5 笔**已结算独立成交**，全库凑不齐 | baseline 改成"同资产/同方向/同 regime 的历史影子命中率"，用 Wilson 区间比，不做点估计；不达标**不写 cycle** |

### P2-6 · 调度"跑过"不等于"跑成"，且没有告警

- `reflection-verify` 今天 03:23 实际死于 `database is locked`（err 日志里有完整 traceback），
  `policy-update-daily` 04:17 死于"旧路径不存在"；两处修复都在**跑批之后**（文件 mtime 09:34）才落地，
  所以 `launchctl` 里 exit code 仍是 **2**，**至今没有一次成功的新证据**。
- `meta-reflection-daily` 03:47 正常返回，但 `cycle_written=false`——成功且无用。
- 改法：每个反思任务写一张 `heartbeat(scanned,written,error,at)`；连续 2 次 `written=0 且 scanned=0` 或 exit≠0 就告警。
  **判"是否生效"只看它自己的副作用计数**（v412 已经付过一次学费）。

### P2-7 · 33 个码没有边际度量，闸门也还没接

- `decision_errors` 672 次触发 / 385 条决策；近 7 天最多的是 E001h 185、E001a 84、E001c 61、E005 46、E028 43。
- E001c（`factor_ranking` 为空）、E014（八段不齐）是**格式/完整性**，不是"判断错了"；`audit_gate_log` 959 条全 `shadow`。
- 改法：建 `code → outcome` 台账——同一资产/同一 regime 下"有码 vs 无码"的 `forward_pnl` 差、n、置信区间；
  n<30 只记不判，连续 90 天无改善的码降 `info`。**下线一个码和新增一个码同等光荣。**

### E001c 的根因修复（v417，已上线）

上一轮判断"开闸会拦掉 75% 的方向单"，这一轮去查了那个 75% 到底是真的还是假的 —— 结论是**假的**：

| 环节 | 问题 | 证据 |
|---|---|---|
| 落库 | `factor_ranking` 用 `str(list)[:500]` 写入 → 存成 Python repr（单引号）且从第 500 字截断 | 抽查 id 11939/11919/11909/11816/11555 全是 `[{'factor': ...}]` |

### 补旁路审计：spool 补写装备门禁（v421，已验证）

### 八段合规：从 prompt 源头改起 + 落库前补齐（v422/v423）

追合规率时找到一个更隐蔽的源头：**精简通道的 prompt 用的是另一套段名**。
