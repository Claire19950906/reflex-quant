01

先定值班方式，再定页面

系统自动下单，人的角色从「操作者」变成「值班者」。页面不负责帮他找入场点，负责让他在十秒内确认系统正常、看懂刚发生了什么、决定要不要接管。

谁在用单人 / 小团队

单人操盘，偶尔有同伴看一眼。不需要协作、权限、多租户。任何为「别人也能用」做的妥协，最后都会变成主界面上的噪音。

什么时候用全天常开

页面长时间挂在副屏上；开盘前检查一次、盘中按流水巡检、收盘后复盘。它更像后台监控台，而不是一天打开三次的工具。

四个问题值班者要看的四件事

  • Q1系统在跑吗？现在在做什么？ 引擎心跳、自动下单开关、今日第几单、卡在五段链路的哪一步。
  • Q2仓位和订单对不对？ 持仓、挂单、成交、拒单、风控敞口、可用余额。
  • Q3市场为什么动、钱流向哪？ 归因 K 线、全部新闻源标注、资金地图、板块轮动。
  • Q4我们的大脑得出了什么、可靠吗？ 因果图谱、结论与置信、反思是否在跑、最近出了哪些错。

五条设计判断用来砍需求

  • 1自动执行，人管例外。 全局暂停常驻且一键可达；每笔自动单必须留下五段证据，缺一段就标黄。
  • 2所有动态走一条流水。 新闻、决策、门闸、下单、成交、拒单、风控、系统事件放在同一条时间轴上，靠筛选器分类，不靠十二张卡片分类。
  • 3数据全部可见，但不平铺。 原始指标、JSON、表格放抽屉，一次点击可达；主界面只留会改变判断的字段。
  • 4重要的东西必须画出来。 归因、资金、因果、反思四个模块各给一张能扫视的图；表格只做图的补充，不做主体。
  • 5层级靠字号和留白。 全站容器最多两层，同层不加阴影；红色只跟钱和破坏性操作走。
自动下单改变的是首屏任务：从「我该不该买」变成「机器刚才做了什么、现在要不要拦」。塔台不替飞机飞，但必须一直看着它飞、随时能叫停。

以后加功能往哪放默认往里收，不往外开

导航一旦允许自然增长，两年后一定回到 29 个页面。所以先把规则定死：一级导航 5+1 封顶，新功能按下面四级往里放，只有「值班方式变了」才允许动总图。

新东西是什么默认落位例子代价
又一种事件或状态运行台流水的筛选项资金费率告警、清算提醒、拒单原因加一个筛选值，0 个新页
同一条主列表的另一个切面页面内一级 tab期权链、逐笔成交、分账户持仓加一个 tab，单页 ≤5
单个对象的更多细节右侧抽屉 / 展开行五段链路、原始 JSON、参数历史不动导航
配置或一次性工具设置 / 后台密钥管理、税务导出、回测参数不进主界面
一套新的值班工作流先替换一个现有目的地多账户轮班、组合管理要重画总图，不能加第 6 个

放进去之前，先过五问答不上来就不做

  • 1它回答五个问题里的哪一个？ 运行、交易、复盘、情报、研究。答不上来，说明它是后台工具或纯装饰。
  • 2它是新答案，还是同一答案的新证据？ 新证据 → tab 或抽屉；只有真正的新答案，才允许讨论新页面。
  • 3不加它，值班会漏掉什么？ 说不出具体损失（漏单、延迟、误判），就先不做。
  • 4能不能做成一个筛选值或一个 tab？ 能，就不进导航；多数「新功能」到这一关就结束了。
  • 5它替代了现有的哪个入口？ 没有替代，就先排队，而不是先上线。
两条硬约束：一级导航 5+1 封顶，想加第 6 个必须合并或下线一个；新功能默认用 ?t= 参数挂在现有页面，只有外部脚本或书签依赖时才给独立路径，并放进后台。每次加功能，在 CHANGELOG 里同时写清「删了什么」。

反例：用「更多」下拉装新功能、把调试面板做成首页卡片、每加一个能力就开一条导航——这三件事就是现在 29 个页面的来源。

06

自动下单的五段链路

自动下单不是「把买入按钮自动化」，而是一条可回溯的流水线。界面要保证每一笔都能从结果倒推到原因，并且在任何一段都能被停住。

01决策信号 + 置信 + 失效条件证据：新闻 / 特征 / 模型评分
→
02门闸余额 / 敞口 / 冷却 / 新鲜度通过或被拒，都留理由
→
03下单品种 / 方向 / 数量 / 价格 / TIF挂单期可撤
→
04成交 / 拒单成交价 / 滑点 / 拒单码可平仓 / 可重试
→
05结算盈亏 / 持仓变化 / 记账只读，写入复盘

前端只渲染统一的 event 结构（时间、类型、品种、金额、证据链接），不为每一段单独建页；缺段即异常。

三级干预停在哪一层，影响多大

待确认
