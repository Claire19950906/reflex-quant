# v452 · 票池铺满 16/16：yfinance 兜底 + 同季同比 + 缺估值降音量（2026-11-18）

> 上一版结束时欠一件事：**覆盖 10/16**，缺 META/TSLA/MSFT/PLTR/SMCI/HUT。
> AV 当日配额 25/25 打满、FMP 三表对部分票直接 402，所以这一版不加配额，
> 而是把 **yfinance 季报三表**接成第三条腿（免费、不占 AV 限额）。

## 一、三件事，缺一不可

### 1) 三表加 yfinance 兜底（放在采集侧，不在决策链）

- `parse_yf_statements()`：把 `quarterly_income_stmt / quarterly_balance_sheet / quarterly_cashflow`
  映射成我们自己的行格式（revenue / gross_profit / operating_income / net_income / eps_diluted /
  total_assets / total_liabilities / total_equity / operating_cash_flow / capex）。NaN 一律留空，不写 0。
- `fetch_yf_statements()`：单票 12h 缓存，失败返回空、绝不抛。
- 接在 `fetch_pack()` 的逐票刷新里：**只有当这只票没有三表、或整列净资产为空时**才退 yfinance，
  FMP / AV 各一次失败请求之后自动接上。
- 另开 `--yf-fill T1,T2` 独立入口：只走 yfinance，**完全不碰 FMP/AV**（配额为 0 时也能补）。
  实测这一路补了 9 只、写入 62 行。

### 2) 跨源同季去重（否则 TTM 会被算双份）

同一季度现在可能有两条：AV 有利润表、没净资产；yfinance 有净资产、历史更短。
`_dedupe_rows()` 按"非空字段最多"选一条，平手按 `fmp > alphavantage > yfinance`。
**不去重的后果很具体**：近四季读到同一季度两份，TTM 营收直接翻倍。NVDA 就是典型（AV 8 期 + yfinance 6 期）。

### 3) 没有 TTM 序列时的同季同比

yfinance 只给 5–7 期，凑不出"近四季 vs 前四季"，所以新铺的 6 只票虽然有三表，
`earnings_revision` 却全是 None → 分数恒为 0，`available=False`。
这就是**假覆盖**：行数到了，结论没有。

`stmt_growth()` 用同季对比（Q3'26 vs Q3'25）：

- EPS 同季同比可得 → 直接用（`growth_basis=quarter_yoy_eps`）；
- EPS 缺、净利有 → 用净利的同季同比并**打 0.8 折**（EPS 含股本变化，净利不含）；
- 基期为负一律不算（负负得正会把"亏损扩大"读成增长）。

再加一道音量限制：**只有盈利面、没有估值分位时**，方向分 ×0.7 并标 `earnings_only`
—— 半张画面不该按满音量喊。

## 三、这一版**没有**做的事（避免自我表扬）

1. **PB 分位仍然不可用**：样本 0~3 天 / 门槛 60 天。`--yf-fill` 明确不补市值历史，不制造假长度。
2. **新 6 只没有估值分位**：`eq.pe` 快照只有 5 只有足够点数，其余要等按日累积。
   所以它们的分数是"纯盈利面"，已经用 ×0.7 降音量，但仍不该当完整的估值+盈利双确认用。
3. **events 里的 actual EPS 对新票是空的**：只有未来 1 条事件、没有实际公布值，
   所以走的是三表同季同比这条降档路径，不是 TTM。
4. **HUT 判不了**：yfinance 季度利润表为空（矿企披露口径不同），只有净资产与现金流，
   分数保持 `available=False`，宁可不出结论。
5. **影子账本仍是 0 样本**（门槛 30 笔）——权重 0.08 依然只是先验。
