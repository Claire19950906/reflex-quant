## 一、第一件：多周期读数接进复盘

此前多周期结算的数据只躺在表里，没有任何出口。补三个出口：

| 出口 | 用途 |
|---|---|
| `GET /api/decision/{id}/horizons` | 单条决策 → 15m/1h/4h/1d/5d 各周期的收益与判定 |
| `GET /api/horizons/stats?days=&asset=` | 按周期聚合：样本 / 胜数 / 胜率 / 平均净收益 |
| `python3 scripts/report_horizons.py` | 命令行看同一组数（无需起服务） |

**口径（关键）**：胜率分母只算 `status='settled'`。

`no_price`（历史库没有对应分钟的价）、`not_executable`（T+1 品种那个时点还不能平仓）
单列计数，**不算判断错** —— 否则"没取到价"会被计成"判断错"，反思会去改本来正确的推理。

实测输出（真实库，样本 2 条决策）：

```
周期       已结算    胜       胜率       平均净收益       平均原始    无价     不可执行
15m        2    0     0.0%      -0.30%     +0.00%     0        0 ⚠️
1h         2    0     0.0%      -0.30%     +0.00%     0        0 ⚠️
4h         1    0     0.0%      -0.83%     -0.53%     0        0 ⚠️
⚠️ = 样本少于 30，胜率区间很宽，先别当结论。
```

样本不足时脚本自己标 ⚠️ —— 这组数现在的意义是"管道通了"，不是"结论"。

## 二、第二件：把「方向错」与「节奏错」拆开

**问题**：一条 SELL 亏了，旧反思一律记「判断错」。但两种错的处理方式完全不同：

| 错因 | 表现 | 该改什么 |
|---|---|---|
| 方向错 | 5d 也亏 | 推理 / 证据 |
| 节奏错 | 短期亏、5d 赚 | 入场时点（不要推翻方向） |
| 成本侵蚀 | 原始涨跌全为正、净收益≈0 | 成本与持仓筛选 |
| 周期不可执行 | 1d/5d `not_executable` | 周期选择，不是判断 |

**实现**（`horizon_reflection.py`，纯函数 `classify`）：

判定优先级（宁缺不猜）：
1. 1d/5d 有 `not_executable` → `horizon_mismatch`（不判判断错）
2. 5d 结算过用 5d 判方向，退 1d
3. 长周期也亏（≤ −0.5%）→ `direction_wrong`
4. 短期最差 ≤ −0.5% 且长期 ≥ +0.5% → `timing_wrong`
5. 原始涨跌全为正但净收益 < 0.2% → `cost_drag`
6. 长期无结算、短期有 → `partial`；全无读数 → `no_data`

落库 `decision_horizon_reflection`（decision_id 主键，幂等覆盖写），
挂在 `multi_horizon_settle.run_once` 末尾（判定失败只记日志，不阻断结算）。
