# S3 因果链方向命中率归因（2026-11-17）

> 结论先行：**S3 的 49.2% 不是"洞察准不准"的读数，是"这一个月在跌"的读数。**
> 去掉 UP/DOWN 的类别偏置后是 49.9%（n=1570），等于抛硬币；
> 任何基于 S3 的"洞察变准/变差"判断都不成立。

## 2. 拆成两个方向，问题立刻现形

| 预测方向 | n | 方向命中率 | 5 日前向收益均值 |
|---|---|---|---|
| UP | 824 | **37.1%** | −2.191% |
| DOWN | 746 | **62.6%** | −2.234% |

**两个方向的前向收益均值都约 −2.2%。** 也就是说：这个窗口里标的整体在跌，
不看预测、随机猜 DOWN 也会比猜 UP 准。S3 把两个方向的命中率按各自样本量加权，
于是得到一个既不是"准"也不是"不准"的中间数 49.2%。

按品种拆，同一个标的同时给出两个方向，命中率差异更大：

这是同一段下跌行情里，顺向的链全中、逆向的链全错。

## 3. 去掉偏置后：没有方向能力

新增参考口径 **R4 平衡准确率**（UP 命中率与 DOWN 命中率的算术平均，
不按样本量加权）：

```
R4 = (37.1% + 62.6%) / 2 = 49.9%   (n=1570, 782/1570)
```

49.9% ≈ 50%。**因果链的方向判断在统计上与抛硬币无差别。**
分手看：XAU 53.5%（微弱正偏），WTI 48.0%（负偏）—— 两个品种都没有可下注的边际。

## 4. 归因：三个原因，按影响排序

| # | 原因 | 证据 | 性质 |
|---|---|---|---|
| 1 | **窗口是单边行情** | 两个方向的前向收益均值都 −2.2%；窗口只有 29 天且截止 11-09 | 口径问题，不是能力问题 |
| 2 | **没有 regime 条件** | 同品种两个方向命中率差 20–37pp，说明链只表达"触发词→方向"，不读市场状态 | 建模缺口 |
| 3 | **结果表停在 11-09** | epoch 于 11-15 重置后 S3 的样本没有更新；当前读数其实在描述重置前的旧窗口 | 数据管道缺口 |

第 3 条要单独说明：S3 现在读的是 **11-09 之前的结算**，而决策库已重置到 11-15 之后。
所以这条指标和 S12/S15 那些"当日读数"不在同一个时间平面上，
把它和它们并列看会得出错误结论。

## 5. 结论与动作

**结论**：S3 不能用来证明或否证"细节洞察能力"。它现在同时混了三种东西：
行情方向、链的方向偏置、以及一个已经过期的样本窗口。

**动作**（按顺序）：

1. **报告口径**：S3 一律与 R4 并排展示（已落地，`capability_scorecard.py` 的 R4）。
   单看 S3 会被类别偏置带偏。
2. **按 regime 切分**：新增 S3-up / S3-down 两段（上涨窗口 / 下跌窗口各自的命中率），
   只有在两段都过半才算方向能力成立。这一步需要结算样本跨过两种行情，
   当前单窗口数据做不到。
3. **让链表达状态**：`causal_chains` 增加 regime 条件（趋势/波动分档），
   同一触发词在不同 regime 下允许给出不同方向 —— 这是"细节洞察"真正该做的细活。
4. **修结果表管道**：`causal_chain_outcomes` 的结算要跟着新 epoch 走，
   否则这条指标永远在描述过去。

不建议做的事：**不要因为 49.2% 去调模型权重或改方向偏好表**。
在没有 regime 切分之前，任何调参都只是在拟合这一段下跌行情。
