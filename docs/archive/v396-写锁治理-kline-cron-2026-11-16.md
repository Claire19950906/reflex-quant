# 写锁治理：kline 聚合 cron 从「17 分钟 85% CPU」到「20 秒 3 秒 CPU」

## 一、症状

`cron_kline_aggregate.py`（每小时跑一次）长期占着 SQLite 写锁：

- 2026-11-16 实测一次进程跑了 **16:53 分钟、85% CPU**
- 期间 bridge 启动被 `database is locked` 卡了 **6 分钟**都起不来（必须 kill 该进程才恢复）
- api 启动也会被饿死在 `Waiting for application startup`

## 二、误判与实测

第一反应是「补 K 线」那部分慢（6 品种 × 3 周期 × 5 天 tick）。实测直接否掉：

```
dry-run 整轮 0.25s，aggregate 只占 0.1s
```

真正的耗时在**后面那个 ohlcv_daily 阶段**：

```
真跑一轮（限时 120s / 硬 180s）：
  kline 阶段 0.4s
  然后卡住 → 180s 硬超时被杀，期间 user 时间 62.87s
```

分步实测：

| 步骤 | 耗时 |
|---|---|
| `build_rows()` 读 kline_bars 1d（100,273 行） | 8.0s |
| `asset_alias.canonical()` 归一 100,084 行 | 0.5s |
| 同日去重 | 4.0s |
| **`executemany` 把 100,084 行全量 upsert 进 ohlcv_daily** | **60s+ CPU、并长持写锁** |

真凶：**每小时把 10 万行「历史日线」全量重写一遍**。日线历史不会变，只有最近几天会刷新。

## 三、改动（4 处）

1. **ohlcv 只写窗口内**：以 `MAX(ohlcv_daily.ts)` 为基准，默认只写最近 3 天（`OHLCV_UPSERT_WINDOW_DAYS`）；
   空表首跑才全量铺底。实测写入从 100,084 行降到 **几十行**。
2. **分批提交**：每 2,000 行 commit 一次并 `sleep`，写锁按毫秒级释放（原来是单事务攥住）。
3. **硬超时**：看门狗线程到点 `os._exit(0)`。**不能用 `SIGALRM`** —— 本机实测信号被屏蔽，
   `signal.alarm(1)` 在 Python 里也照样睡满 4 秒不中断。默认 `KLINE_HARD_TIMEOUT_S=300`。
4. **tick 只读一次**：1h/4h/1d 三个周期复用同一批 `market_ticks`（原来扫 3 遍）。
   保留旧接口 `aggregate_ticks()` 做兼容，新增 `fetch_ticks()` / `aggregate_rows()`。

另外加了**耗时审计日志** `~/.trident/log/kline_aggregate.log`（launchd 的 out.log 会被别的输出淹没）：

```
2026-11-16 19:14:10 kline=0.2s ohlcv=0.9s total=20.7s inserted=0 updated=0 ohlcv_rows=100084 cut_short=0
```

## 四、验证

| 指标 | 改前 | 改后 |
|---|---|---|
| 整轮时长 | 17 分钟（未收敛） | **11–21 秒** |
| user CPU | 62s+（180s 时被杀） | **3.1s** |
| ohlcv 写入行数 | 100,084 | **窗口内数十行** |
| 写锁持有 | 数分钟 | 每批 2,000 行毫秒级 |
| 超时保护 | 无（只有循环内软检查） | 硬超时 300s（看门狗线程必杀） |

- 新增 `tests/test_kline_aggregate_v396.py` 5 例：OHLC 语义、新老接口逐桶一致性、
  非正价/窗口过滤、硬超时确实掐断进程（子进程实测 <5s 退出）、perf 日志可写
- 相关子集（kline/agg/schema/settle）：**190 passed**
- plist 已写入 `KLINE_MAX_RUNTIME_S=180` / `KLINE_HARD_TIMEOUT_S=300` / `OHLCV_UPSERT_WINDOW_DAYS=3`
  并 bootstrap 重启，RunAtLoad 立即跑一轮：`total=20.7s`，正常退出

## 五、还没解决的

- `build_rows()` 仍然每轮扫 10 万行日线（约 8–19s）。要再压下去得改成"只读最近 N 天 + 增量索引"，
  但它现在已在可接受范围，先不动。
- 历史日线窗口外的缺口（>3 天）不再自动修复；确实需要补历史时，用
  `OHLCV_UPSERT_WINDOW_DAYS=99999` 显式跑一次。
