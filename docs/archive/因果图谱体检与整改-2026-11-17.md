## 一、一句话结论

因果图谱**结构是对的、数据是假的**。它有三层，三层都在"自说自话"：

1. **录入层**：753 条因果链 **100% 是 auto 生成、人工 0 条**；48% 的触发词里混着 JSON 字段名
   （`Asset`、`verdict`、`partial`、`market_event`），237 条洗完词后一个关键词都不剩（永不可能触发）。
   按名字前 12 字判重，冗余 333 条（44.2%）。
2. **输出层**：`confidence` 750/753 条等于 **1.0**（常量）；`hit_count/miss_count` 全库为 0；
   方向命中率 UP 35.8% / DOWN 62.8% / BOTH 93.3% —— BOTH 是**幅度**口径被当成方向口径在报。
3. **决策层**：`chain_prior` 读证据恒为 `(0,0)`，`aggregate_direction` 恒 `UNKNOWN`、否决 0 次 ——
   图谱对交易决策**实际影响为 0**。边权重也不是 0–1（contradicts 均值 16.5 > causes 5.0）。
   节点更脏：36 个品种只有 10 个有 core，BTC 唯一的 core 是**列名** `historical_confidence`，
   ETH 是 `cluster_heat`，WTI 是新闻标题「美sec批准多资产3倍杠杆etp(含原油)」。

一句话：**图谱是"看起来有"，不是"用得上"。** 这次把三层全部改了。

## 三、录入侧：脏在哪、怎么修的

### 3.1 触发词清洗（已有脚本，只是从没跑过）

- `backend/scripts/chain_ingest_cleanup.py`：扫 `trigger_words/trigger_keywords`，
  把 `Asset/verdict/partial/market_event/expected_direction/trigger_ref` 这类**字段名**当噪声词删掉。
  dry-run 命中 362 条待净化、237 条会变成零关键词；`--apply` 实删 2270 个噪声词。
  审计：`backend/runtime/chain_cleanup/cleanup-20261117-064519.jsonl`。
- `chain_inert_rebuild.py --apply`：0 条需要停用（零关键词的链本来就没在跑）。

### 3.2 去重合并（新写 `backend/scripts/chain_dedup_merge.py`）

- 按 `name` 前 12 字 + 同资产聚类，17 组、32 条冗余，保留信息量最大的一条（命中数/证据/描述长度）。
- **踩坑**：直接 `UPDATE causal_chain_outcomes SET chain_id` 撞
  `UNIQUE(chain_id, trigger_ts, trigger_ref_id)` → 必须先删目标链上的冲突行，再重指（26 条）。
- 结果：`enabled 392 → 361`，可回滚（脚本默认 dry-run，审计 `dedup-20261117-064746.jsonl`）。

### 3.3 入库三道校验（`causal_graph._upsert_node`）

新生成的"核心驱动"最容易出的三种烂数据，全部在**入库那一刻**拦：

| 规则 | 拦什么 | 例子 |
|---|---|---|
| `_is_schema_label` | 列名/JSON 字段名当驱动 | `historical_confidence`、`cluster_heat`、`news_sentiment`、`funding` |
| `_looks_like_event` | 新闻标题冒充"底层原因" | 「美sec批准多资产3倍杠杆etp(含原油)」→ 降级为 `condition` |
| `_foreign_asset_label` | 别的品种的专有别名当本品种驱动 | AAPL 的驱动写成「黄金短期方向」、CN_BOND 写成「原油风险溢价」 |

- 跨品种规则**只对股票/外汇/债券生效**：`_COMMODITY_FAMILY={XAU,XAG,WTI,BRENT,COPPER,CPI}` 不做拦截 ——
  「原油供给冲击传导至金价」是真结构，拦掉就把对的也杀了。
- 同样：不是删，是**降级**（`is_core=0, kind='condition'`）。它可能是某次触发链的真实条件，
  只是不配当这个品种的底层原因。

### 3.4 AI 兜底不再冒充"已学知识"（`engine/ai_worker.py`）

原来 `_fallback_business_knowledge_drivers(asset)` 无论有没有知识，都会吐一套
「美元反向 / 实际利率反向」通用宏观框架，前端看起来像"系统学到了"。改成 `allow_generic=False`：
学到知识才返回，否则 `None`，让上层显示"无知识"而不是假的。
实测：AAPL/MSFT/COPPER 返回 `None`，BTC 返回 2 条，XAU 返回真实 3 条。

### 3.5 覆盖度补齐（新写 `backend/src_python/kg_coverage_fill.py`）

- 只挑 core=0 的品种，走 `causal_graph.run_reasoning`（LLM 5-why）+ 上面三道校验，每次 `--max N`。
- **踩坑**：`run_reasoning` 返回 `{"reasoned": [名字列表], "detail": {asset: 结果}}`，
  `reasoned` 是 list 不是 dict —— 直接 `.items()` 崩。
- 补出来的"未知品种"驱动会被校验大量拦掉（实测 CN_BOND 的 3 条全是原油/加密，全拦）。
  因此加 `runtime/kg_coverage_giveup.json`：补完 0 条存活的品种 14 天内不再重试，别每天烧配额。
- 实测补齐：AAPL / AMZN / BRENT / BTC / CNY（部分），活跃 core 101 → 107，覆盖 11 个品种。

## 四、输出侧：假数字怎么变成"有刻度的数字"

### 4.1 置信度不再恒等于 1.0（`chain_steps_verify.py`）

原来 `confidence` 是常量 1.0，因为写入逻辑只写 `hit/miss`，从不写置信度；且 BOTH 链的"命中"
（幅度够不够）被直接当方向对。

新口径（三个常量写在文件头，测试锁死）：

| 场景 | 规则 | 效果 |
|---|---|---|
| `expected_direction=BOTH` | `confidence ≤ CONF_BOTH_MAX = 0.55` | BOTH 不再能靠"会动"刷到 0.95 |
| 无样本 / 样本 <5 | `confidence ≤ CONF_UNVERIFIED_MAX = 0.50` | 450 条无样本链从 1.0 掉到 0.5 |
| 有方向 + 有样本 | Beta(2,2) 后验均值 `(hit+2)/(n+4)` | 5/5 不再是 1.0，而是 0.78；幂等，重复跑不衰减 |

实测（连跑 4 轮后）：下调 119 条、基本不动 634 条；691 条落 0.5–0.7、58 条 <0.5、
4 条 0.7–0.9、**0 条 ≥0.9**；`hit_count>0` 的链 245 条。

### 4.2 方向命中率拆开报（`GET /api/causal/quality`）

```

{

 "chains_both_direction":372, "chains_n_ge_12":3, "chains_weak_3_11":244,
 "avg_confidence":0.502,
 "direction_breakdown":[
   {"direction":"BOTH","n":396,"hit_rate":1.0,"note":"幅度口径，不是方向命中"},
   {"direction":"DOWN","n":686,"hit_rate":0.679,"note":"方向命中"},
   {"direction":"UP","n":772,"hit_rate":0.334,"note":"方向命中"}],
 "outcome_status":{"PENDING":1109,"HIT":737,"HIT_WEAK":383,"MISS":734,"NEUTRAL":22,"EXPIRED":1}

```

**这张表本身就是一个结论**：DOWN 67.9% vs UP 33.4% —— 系统标"看涨"的链，
用它的方向做交易是**反的**；标"看跌"的才有超额。这是链方向标错 or 新闻触发口径偏，
待定（见"仍未做"）。

### 4.3 决策侧闸门：从"全不输出"到"分级输出"（`chain_prior.py`）

| 档位 | 条件 | 能不能否决交易 |
|---|---|---|
| strong | `n ≥ 12` 且 Wilson 下界 > 0.5 | 能（`min_posterior 0.60`） |
| weak | `3 ≤ n < 12` | **不能**，只在 prompt 里标注"仅参考" |
| none | `n < 3` | 不参与 |

- `aggregate_direction` 新增 `UP_WEAK / DOWN_WEAK / WEAK_MIXED`：旧口径下证据不足直接 `UNKNOWN`，
  决策侧永远读不到任何链；新口径给"方向 + 弱标记"，让下游知道"有这么个东西，但别当真"。
- `posterior` 改取 `chain.confidence`（原来取 `weight`，而 weight 恒 1.0 → 假 1.00）。
- `match_by_headline` 的 SELECT 补 `confidence`、加 `AND COALESCE(active,1)=1`（停用的链不会再被召回）。
- `build_prompt_block` 分「已验证档 / 候选档」两段，weak 段落明写"不得作为否决理由"。
- 实测：XAU 标题「中东冲突升级 黄金避险买盘增加」命中 3 条 weak 链 →
  `aggregate_direction=DOWN_WEAK`、`conflict_veto(SELL)=None`、`posterior=0.5`（不再假 1.00）。

### 4.4 状态口径对齐

`active=0` 却 `enabled=1` 的 135 条链仍在被检索/被统计。已统一停用（`enabled=0`），
现在 `enabled=191` 与 `/api/causal/quality` 的 `chains_effective=191` 一致。

## 六、这次顺手抓到的一个生产级故障（重要）

改造过程中所有写库操作突然全部 `database is locked`，连 `BEGIN IMMEDIATE` 都立刻失败。
定位：`com.trident.binance-flow-cron`（pid 32065）跑成了 `R` 状态、存活 32 分钟，
**持有一个未提交的写事务**（在长网络 IO 期间没有把事务收掉），把整个 801MB 主库的写锁占死。
杀掉该进程后写锁立即释放。

- 影响面：整个系统（引擎/新闻入库/决策）在这段时间都无法写库；
  `engine.err.log` 里已有 `[source_status] DB persist skipped ... database is locked`。
- 同类风险：凡是"一个事务里夹着网络请求"的 cron 都会这样。建议加一道守卫
  （`com.trident.wal-checkpoint-cron` / `service-guard` 已有类似的巡检框架），本文件先记录现象。

判断口径的定义（本节全部沿用）：

- **基准率 p₀** = 该品种近 60 天、任意 5 个交易日窗口里上涨的比例（实测 XAU 29.1% / WTI 44.2% / BTC 25.0% / ETH 19.6%、库整体加权 36.5%）。
- **超额 lift** = 命中率 − p₀（同品种、同方向）。
- **达标（strong，可作方向依据）** = 样本 n≥12 **且** lift≥10pp **且** 单侧二项 p≤0.05。

| 显著性 | 单侧 p≤0.05 | `MAX_P_VALUE_FOR_STRONG = 0.05` |

## 二十二、v422：否决的「影子模式」—— 先记录，不动下单

### 22.1 为什么这么做

v421 已经证明：图谱 1786 次注入只有 88 次进了决策，`chain_prior.conflict_veto`
在生产代码里**零调用**。要让它真正约束方向，只能接进 `ai_worker` 决策路径 ——
那会改变真实下单，属高风险。

折中方案：**拿已落库的历史决策离线跑一遍否决逻辑**，把"如果当时接入了会怎样"记下来。
engine 一行不改、不重启、不影响任何一笔交易。

### 22.2 做法（`scripts/shadow_veto_replay.py`）

1. 取近 N 天 `suggested_action IN ('BUY','SELL')` 的决策，连同 headline；
2. `chain_prior.match_by_headline(conn, asset, headline)` → 该品种命中触发词的链；
3. `chain_prior.conflict_veto(priors, action)` → 是否有"方向相反的 strong 链"；
4. 写 `causal_veto_shadow`（`decision_id` 唯一键，可反复增量跑）。

踩到两个坑，都修了：
- **新闻表同一 `news_id` 有多份转载**，直接 JOIN 会把一条决策放大成多行 → 否决率被重复计数。
  改为子查询 `GROUP BY news_id` 去重后再关联（修正前 80 行/否决 12，修正后 **39 行/否决 5**，前者是假数）。
- `is_correct` 列历史上有 `1/0` 和 `'WIN'/'LOSS'` 两种写法，统一归一化。

### 22.3 当前结果（近 30 天，2026-11-18）

| 项 | 数值 |
|---|---|
| 方向型决策（BUY/SELL） | 39 条 |
| 会触发否决 | **5 条（12.8%）** |

只要持续累积到 10~15 条已结算的否决，就能判断这套否决是"过滤噪音"还是"乱杀单"。
