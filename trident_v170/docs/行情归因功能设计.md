# 行情归因功能设计（草案 v1）

> 状态：设计对齐稿（未实施）。目标：把「行情异常识别 + 指标计算 + 因果归因」接入现有 Trident 引擎，产出可解释、可复盘、可回灌决策的行情归因能力。

## 0. 目标与范围

**目标**：当任一监控资产（BTC/ETH/SOL/XAU/XAG/WTI + 美股）出现异常波动时，系统能
1. 自动识别异常点（时间锚）；
2. 用多指标刻画「行情正在怎么发生」；
3. 归因出「为什么发生」，并把结论回灌 `ai_worker` 决策。

**非目标（本迭代不做）**：
- 不替换 `abnormal_detector` 既有 3m 异动口径，而是扩展；
- 不追求 HFT 级实时（现状民用上限 ~500ms–1s 新闻、分钟级 K 线）；
- 不新建交易执行/风控逻辑（决策闸门仍在 decision_guard / paper_trading）。

## 1. 现状盘点

### 1.1 已具备（直接复用，不重复造）

| 模块 | 能力 |

## 2. 总体架构：三层解耦

```
[数据采集层] quote_sources / macro_context / coingecko_feed / coinpaprika_feed
      │  OHLCV + OI + funding + 宏观 + 市场宽度
      ▼
[指标求实层 NEW] technical_indicators.py（纯函数，确定性）
      RSI / MACD / BOLL / ATR / MA / 量价标签 / OI变化率 / 相对强弱 / 全板块联动度
      │  输出结构化「技术面事实快照」
      ▼
[异常签名层 EXTEND] abnormal_detector.py（扩成多因子规则引擎）
      单资产异动 → 扩展为：全板块联动 + RSI背离 + 量价背离 + OI骤变 + funding极端
      │  triggered + anchor_ts + 命中的因子签名
      ▼
[语义归因层 REUSE] asset_graph.py（5-why 归因） + history_review（复盘）
      把「指标事实 + 异常签名 + 宏观/新闻事件」→ 因果链 → 回灌 ai_worker 决策
```

**核心原则**：
1. 指标是「果」、归因靠「因」——技术指标描述价格行为，真正的「为什么」由新闻/宏观/资金面（asset_graph）回答；
2. 指标算成**结构化事实**喂给 LLM，不让 LLM 自己读原始序列（会算错、会背书）；
3. 分层可独立上线，任何一层失败不拖垮主流程（fire-and-forget）。

## 4. 归因维度框架（谁 / 什么 / 时机 / 情绪 四层）

在现有「客观世界 / 新闻事件 / 美元美债」之外，增补成四层因果框架，映射进 `asset_graph` 的因子节点（扩 `_INDICATOR_ALIASES`）：

- **① 谁在交易（人物）**：机构 vs 散户 vs 做市商 vs 巨鲸
  → 区分手段：CFTC 商业(套保) vs 非商业(投机)、ETF 资金流、链上大额转账、多空比极值、OI 变化方向
- **② 什么在驱动（原因）**
  - 流动性：实际利率、美元 DXY、美联储政策预期、QT/QE、日元 carry 平仓、美债期限利差
  - 跨市场传导：美股(NVDA/COIN/MSTR 等加密相关股)、risk-on/off、黄金原油、加密内部轮动(BTC→ETH→山寨，看市占率)
  - 资金面：稳定币净流入流出、现货 ETF 净流入、交易所净流入流出、DeFi TVL
  - 衍生品结构：资金费率极值、OI+价格组合、基差、期权 max pain/gamma、交割日
- **③ 什么时机（日历/微观结构）**：月末/季末/年末结算、美股盘前/盘中/收盘、亚洲 vs 欧美时段、节假日休市、期货期权交割日
- **④ 什么情绪**：恐慌贪婪极值、社交/搜索热度、聪明钱 vs 散户

## 6. 需对齐确认的决策点

1. **阈值口径**：RSI 超买/超卖(70/30?)、背离判定窗口、全板块异动的「大面积」阈值(≥X% 资产同向?)、量比是否沿用 `abnormal_detector` 的 1.5×。⚠️ 铁律 6：阈值属产品决策，需你拍板，不夹带在重构里。
2. **是否落库留历史**：指标是否写入 DB（→ 需 `db.py` 加表并走 `migrate()` 幂等），还是每 tick 实时算、不入库（零 schema 变更）。
3. **数据源 key**：清算/爆仓、链上是否愿意接 key，或先只用币安公开 forceOrders。
4. **prompt 注入方式**：指标以「结构化 dense 摘要」注入 ai_worker，还是仅在异常触发时才注入归因（后者更省 token，推荐）。
5. **接入范围**：先只覆盖 XAU(黄金) 主战场，还是 BTC/ETH/XAU 全上。
