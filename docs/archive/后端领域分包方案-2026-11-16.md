# 后端领域分包方案（src_python 扁平结构治理）

> 状态：**方案文档，尚未改动运行时代码**。本文给出模块 → 领域包的映射、分批迁移节奏与风险清单，确认后再逐簇落地。
> 生成日期：2026-11-16

## 1. 现状与问题

`backend/src_python/` 当前为一层扁平结构：

- **421 个 `.py` 模块**平铺在同一目录；
- **约 1239 条本地模块间导入**，全部为同级扁平 `import db` / `from market_classifier import ...`；
- **103 个测试文件**把 `src_python` 直接加入 `sys.path` 后扁平导入；
- `api_server.py` 内存在 **7 处按扁平模块名动态加载**（`importlib.import_module("dollar_index_feed")` 等），另有 1 处按文件路径加载 `run_reflection.py`。

既有子包：`engine/`、`routers/`、`repository/`、`migrations/`、`market_sentiment/`。

被广泛依赖的共享底座（迁移时**必须留在最上层或公共包**，避免循环导入）：

| 模块 | 被引用次数 | 角色 |
|---|---|---|
| `db` | 111 | SQLite 连接 / schema / SQL 安全门 |
| `config` | 37 | 唯一配置入口（.env / 密钥 / 阈值） |
| `external_data` | 29 | 外部数据通用封装 |
| `source_status` | 18 | 数据源健康状态 |
| `epoch_gate` / `dim_tables` / `asset_alias` / `quote_sources` 等 | 2–4 | 横切工具与字典 |

## 3. 分批迁移节奏（建议）

每一批只迁一簇，迁完立即跑测试，全绿再进下一簇。

1. **批次 0 — 基线固化**：跑通并记录相关测试基线（本次已验证 169 个后端用例 + 670 个前端用例通过）。
2. **批次 1 — 公共底座 `common/`**：先把 `config`、`db` 等最底层模块归入公共包，确立包内相对导入范式；底座改动影响面最大，单独一批。
3. **批次 2 — `feeds/`**：边界最清晰、被引用面相对窄，作为物理分包的首个业务簇验证流程。
4. **批次 3 — `news/`**。
5. **批次 4 — `signals/`**。
6. **批次 5 — `decision/`**。
7. **批次 6 — `reflection/`**。

每批标准动作：
- 新建子包目录与 `__init__.py`；
- `git mv` 移动模块；
- 修正包内导入（扁平 → 包内相对导入或顶层包导入）；
- 同步改 `api_server.py` 动态加载点；
- 跑对应测试子集 + 全量回归。

## 4. 必须同步处理的改动点（风险清单）

### 4.1 运行时导入
- 同包内：`import db` → 包内相对导入或顶层包导入；
- 跨包：`import market_classifier` → `from signals import market_classifier`（按最终归属）；
- 保持 `config`、`db` 在 `common/`，避免被多个领域包反向依赖造成循环。

### 4.2 动态加载点（`api_server.py`）
以下按扁平名加载的模块，迁入子包后必须改成包路径或先在顶部 `import`：

- `__import__("cross_asset_context")`（10080 行）
- `importlib.import_module("dollar_index_feed")`（17517）
- `importlib.import_module("treasury_yield_feed")`（17522）
- `importlib.import_module("silver_feed")`（17527）
- `importlib.import_module("sector_etf_feed")`（17532）
- `importlib.import_module("coinglass_free")`（17537）
- `importlib.import_module("earnings_calendar")`（17542）
- `importlib.util.spec_from_file_location("run_reflection", ...)`（11628，按文件路径加载，迁移后需更新路径）

### 4.2.1 定时任务 wrapper（仓库外，必须同步）
本机 `~/.trident/wrappers/*.sh` 与 `scripts/*.plist` 经 wrapper 启动后端模块。部分 wrapper **按文件路径直接调用 `backend/src_python/<module>.py`**，模块一旦迁入子包，这些路径会失效，必须同步更新。

- 仓库内 `scripts/*.plist` → 调用 `~/.trident/wrappers/run_*.sh`；
- wrapper 内记录被启动模块的 `.py` 绝对/相对路径；
- 分包前须拉清单：列出所有 wrapper 引用的 `src_python/*.py`，分包后逐条改为新包路径；
- 注意：wrapper 位于仓库外（`~/.trident`），不在 git 跟踪范围，改动需在部署机上同步。

> 本次搬迁已修正 3 处因 oneoff 迁移而失效的 wrapper 路径：
> `run_degenerate_audit.sh`、`run_fix_decision_reasoning.sh`、`run_intraday_from_ticks.sh`。

### 4.3 测试
- 103 个测试文件顶部的 `sys.path.insert(.../"src_python")` 保持不变（src_python 仍是路径根）；
- 测试内的扁平 `import opt_metrics` 等，需随模块归属改为包导入；
- `tests/conftest.py` 全局注入 src_python 的逻辑保留。

### 4.4 入口与部署
- `engine.py`（`python src_python/engine.py`）、`api_server:app`（uvicorn `--app-dir src_python`）、`bridge_server.py`、`treenews_bridge.py` 的启动方式不变；
- 部署脚本 `scripts/run_api.bat`、`build_demo_image.sh` 中的 `api_server:app` 启动命令保持兼容；
- `scripts/oneoff/` 下一次性脚本的 `sys.path` 自举已指向 `parents[2]/"src_python"`，模块分包后无需改动路径根。

### 4.5 被测试钉住、暂不移动的模块
以下模块被 `tests/` 直接扁平导入，在导入方式改造前保留在 `src_python` 根，避免测试断链：
`opt_metrics`、`opt_direction`、`opt_sector_beta`、`opt_move_shape`、`opt_weight_diag`、`opt_asset_cover`、`opt_weight_shadow`、`backfill_core_slow_moves`、`backfill_critical_moves`、`backfill_reflection_a_subclass`、`fix_polluted_outcome_pct`、`repair_orphan_decision_refs`、`recompute_b_labels`、`relabel_failed_insights`、`scan_text_ts_columns`。

## 5. 为什么不一次性大改

- 1239 条扁平导入 + 103 个测试 + 7 处动态加载集中在一次提交，回归面过大，且模块间存在双向/多向依赖；
- 按批次逐簇迁移，每批都有独立可回滚的测试基线；
- 底座 `common/` 先行，能显著降低后续各簇的跨包依赖复杂度。
