### 1.2 旧版在 XAU 上的实际行为（改之前实测）

| 指标 | 旧行为 | 问题 |
|---|---|---|
| `obv` | **IndexError: list index out of range** | `volumes()` 用 `_clean` 压缩空值，序列从 2623 缩到 120，OBV 却按 2623 索引 → 必崩 |

HG（0% 覆盖）反而"诚实"：MFI/VWAP 返回 None、vol_zscore None、regime「样本不足」——
说明**部分缺失比全缺更危险**，因为它能凑出一个数。

### 1.3 修法

`technical_indicators.py` 新增：

| 新增 | 作用 |
|---|---|
| `VOLUME_MIN_COVERAGE = 0.80` | 覆盖率下限常量 |
| `volumes_full(candles)` | **保留长度**的成交量序列（无效位 None），与 K 线逐根对齐 |
| `volume_availability(candles)` | 体检门：返回 `available / coverage_pct / n_valid / n / note` |

接入点：

- `obv`：改用 `volumes_full`，无效量按 0 累加（不再错位），覆盖不足返回 `[None]*n`；
- `mfi` / `vwap`：覆盖不足返回 `[None]*n`；
- `vol_zscore` / `vol_break`：覆盖不足返回 `None`；
- `volume_regime`：覆盖不足返回 `regime="成交量不可用"` + `available=False` + `coverage_pct`；
- `snapshot`：新增 `volume_availability` 字段，让 AI worker / 因果图谱知道"这只标的没有量"。

## 4. 比值型指标：给分母加下限

### 4.1 抓到的假信号

MSFT 留出段 `C/A = 4.667` —— 看着像"连续等风险版把收益改善了四倍"。
真相：留出段满仓策略 CAGR 只有 1.09%、MDD 34.91%、**Calmar 0.03**。
任何策略除以 0.03 都会变成"大幅改善"。

### 4.2 两道门

| 门 | 阈值 | 作用 |
|---|---|---|
| `MIN_MDD_FOR_CALMAR` | MDD ≥ 0.5% | 回撤太小时 Calmar 本身不可信 → `calmar=None` |
| `MIN_BASE_CALMAR_FOR_RATIO` | 基准 Calmar ≥ 0.30 | 分母（基准策略）太弱时比值不可比 → `None` + 写明原因 |

### 4.3 改后

| 标的 | 原来 | 现在 |
|---|---|---|
| MSFT | C/A = 4.667 | **不可比**（基准 Calmar 0.03） |
| META | 大正值 | **不可比**（基准 −0.37） |
| NVDA | 大正值 | **不可比**（基准 −0.32） |
| TSLA | 大正值 | **不可比**（基准 −0.17） |

滚动窗口同样过滤基准过弱的窗：98 窗 → **65 窗**，胜率 26.5% → **30.8%（20/65）**。

**结论没变**：仍远低于 50%，连续等风险版不上线。变的只是"分母不再被噪声放大"。

## 口径备忘

- 「不可用」不是「没有值」：`None` + `available=False` + `note` 三者同时给，才算说清楚。
- 全缺（HG 0%）比部分缺（XAU 4.6%）安全 —— 部分缺会凑出数字。
- 比值型的敌人是**分母**，不是分子。分母弱于 0.30 一律判不可比。
- 翻转检验 ≠ 时间外检验；滚动胜率才是最终判据（v479 教训）。

# 附 · 第二轮优化（A–D 落地）

## A. 管线级跳过：不再白算一遍再返回 None

`IndicatorPipeline.run` 现在先问 `pipeline_skip_reason`：

| 输入 | 行为 |
|---|---|
| 有量 | 照常计算 |
| 无量 + 在 `_VOLUME_GATED` | 直接返回 `{"skipped":"no_volume","coverage_pct":..,"n_null":..,"n_zero":..,"note":..}` |
| 无量 + `volume_profile` | **照常算**（它 v409 就有 TPO 兜底，`weight="tpo"`） |

好处：XAU 那种 2623 根的标的，不用先把 obv/mfi/vwap 各扫一遍再返回 None；
下游拿到的也不是裸 None，而是带原因的 dict。

## B. 证据改深拷贝

`risk_profile` 返回的 `sizing_evidence` 以前是模块级 dict 的**引用** ——
任何调用方写一句 `r["sizing_evidence"]["verdict"]="ok"`，之后**所有**读数都会被污染。
现在 `copy.deepcopy`，并加了测试 `test_sizing_evidence_is_deep_copied` 锁这条。

顺带把证据里的滚动数字同步成 v480 口径：26.5%（26/98）→ **30.8%（20/65）**。

## C. 空值与零值分开报（这条带出了新问题）

`volume_availability` 现在分开统计 `n_null` / `n_zero`。
**零值比空值更隐蔽** —— 它看着像"有量"，实际是缺失被写成 0。

| 标的/周期 | 空 | 零 | 说明 |
|---|---|---|---|
| XAU 1d | 2503 | 0 | COMEX 不发布，结构性缺失 |
| HG 1d | 2590 | 0 | 同上 |
| WTI 1d | 45 | **78** | 缺失被写成 0，最隐蔽 |
| XAU 5m | 0 | **579** | 全表都是 0 |
| WTI 1m | 0 | **2778** | 一半以上是 0 |
| XAU 1m | 0 | **2515** | 同上 |

## 顺带修了间隔体检自己的一个 bug

## E. 台账分层评估：项目已经做过，结论是否的

我上一轮把「分层评估」当成待做项，查了 `reports/indicator_ledger/latest.json` 才发现

| 指标 | 数值 |
|---|---|
| 单侧 5% 通关格数 | 217 |
| 纯随机预期 | 132 |

| Bonferroni 阈值 | 4.12σ |
