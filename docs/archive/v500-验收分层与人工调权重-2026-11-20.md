## 一、验收清单分五档（原 26 项只有 PASS/FAIL）

问题：8 个 FAIL 里 7 个是"样本没到门槛"（真实开仓 1 笔、outcome 0 条、反思 10 条），
和"端点没接线"打同一个红叉；每次迭代都要人肉分辨，而且改代码修不好。

| 状态 | 含义 | 要不要动代码 |
|---|---|---|
| ✅ PASS | 硬判据全达标 | — |
| ❌ FAIL | 逻辑/口径/接线坏了 | **只有这类要改** |
| ⏳ INSUFFICIENT | 链路在跑、口径能算，样本没到判定门槛 | 不改，等数据 |
| ⚠️ WARN | 达标但样本偏少 | 看趋势 |
| ⏭️ SKIP | 前置条件不具备 | 正常 |

每项 ⏳ 带三字段：`need`（等什么）/ `have`（现在多少）/ `watch`（数据到了看哪个数算不通）。
实测：8 FAIL → **15 PASS · 0 FAIL · 7 ⏳**（7 项全是等数据）。

同时修正三处误导性诊断：
- #2 写"决策链路从不写权重" → 实际 `decision_writer` 已写 `trigger_kind='insert'`（v488）；
- #6 写"worker 无调度、表恒空" → 实际 cron 在跑、`event_kline_impact` 1900+ 行；
- 文档 #3 标"3 个写权重端点" → 代码里从未有过（`policy_overrides` 孤儿表）。

## 三、人工调权重（验收 #3）

`POST /api/signal-weights/override` / `GET /overrides` / `POST /override/{id}/revoke`

- 只允许乘法系数 0.5~2.0，乘积再夹 0~1，`weight_tier` 重算；
- 必须写 `reason` + `actor`；`ttl_hours` 可自动过期；撤销保留行；
- 生效时 `weight_explain` 追加 `| manual_override ×1.20 (#3 by claire: ...)`，
  `components.manual` 记系数，建/撤写 `audit_log`；
- 优先级：品种精确 > 全品种，方向精确 > 全方向，同级取最新；
- 失败安全：表缺失/读失败/过期/撤销/不匹配 → 回退原值，不阻断决策。

## 四·B 产能脉搏（每次迭代都看的那一行）

```

     ⚠ 主通道短输出 42%（minimax/MiniMax-M3，2852 次） — 不建议用于主分析
```

对齐"保产能、不限速、严禁零产出空烧 token"：方向产出是产能，短输出是空烧。

`max_tokens` 实际由 ai_worker 的 `MINIMAX_MAX_TOKENS`（默认 4000）统一覆盖，
改 config.py 的 extra_body 对正式分析路径无效（已实测确认，故未改）。
