# 交易可用性改造（v477 / 2026-11-19）

> 目标：把「能看、能分析」的系统改成「能下单、能平仓、账能对上」的模拟盘；
> 实盘只留适配位，不接真钱。验收标准不是「有交易按钮」，而是下面四件事同时成立。

## 一、验收口径（四条硬标准）

1. **一个账户只有一个口径**：现金、已实现、浮盈、权益四处数字必须能由持仓行重算出来，
   账上缓存只作展示，不作依据。
2. **手续费双边入账**：开仓按名义计一次，平仓按名义再计一次，`realized_pnl` 记净额。
3. **拒单必须可解释**：每一笔被拒都要落 `trade_audit_log.reason`，写清是哪道闸、
   哪个数字越界，而不是一句 `RISK_REJECTED`。
4. **止损要真的平仓**：`stop_price` 触发时写 `closed`、写 `exit_price`、写净盈亏、
   更新账户，而不是只在前端画一条线。

浮盈 +8.90 · 未入账开仓费 0.00

对账只剩 **一条 block：R7 杠杆**。这不是账错，是**仓位真的满了**：
4 笔 × 5000 USDT 名义 = 20000，权益约 9975，已经超过 `MAX_GROSS_LEVERAGE_PCT=200`。
所以现在的系统会拒绝一切新开仓，只能减仓或等权益涨过 10000。

- 手动平掉 1 笔（约 5000 名义），杠杆回到 150%，新单自然放行；
- 或在 `backend/.env` 调高 `MAX_GROSS_LEVERAGE_PCT`（不建议超过 250）。

## 七、第二波：杠杆不是死锁 + 实盘硬武装

### 7.1 满仓 → 减仓 → 新仓成交（已实跑）

`python3 scripts/v477_leverage_release_check.py`（临时库）输出：

| 步骤 | 结果 |
|---|---|
| 造 4 笔满仓（20402 名义 / 权益 9983） | 杠杆 204.3%，超 200% 上限 |

所以 R7 只是「仓位满了」，不是「系统坏了」：减一笔就恢复开仓能力。

### 7.2 实盘适配位：不武装就拒单

`build_default_executor` 在 `live_dry / live_real` 下必须同时满足三条，否则换成
`RefusingAdapter`（只写 `reason`，永不成交）：

1. `BINANCE_API_KEY` + `BINANCE_API_SECRET` 都有值；
2. `live_real` 还要 `LIVE_TRADING_ACK=I_UNDERSTAND_REAL_MONEY`（防手滑开关）；
3. 单笔 `BINANCE_NOTIONAL_USDT` ≤ `LIVE_MAX_NOTIONAL_USDT`（默认 1000）。

旧行为是「缺密钥就回退 Mock」——看起来在跑，实际没下单，容易被当成「实盘已接通」。
现在改为显式拒单：`ADAPTER_SKIPPED` + `live_not_armed:missing_api_key,...`。

### 7.3 真钱与纸钱分账

`canonical` 把 `subaccount ∈ {live, live_dry, live_real}` 的持仓排除在模拟权益之外，
并输出 `n_live_segregated`；对账给 `R12_LIVE_SEGREGATED` 提示。
实盘要真正上线，还需要一张独立的实盘账户表（本金、保证金、可用余额、强平线），
这一步没做，所以现在**不要**把实盘模式当成可用。

## 八、第三波：止损不再依赖引擎 + 日亏限额 + 对账告警

### 8.1 止损独立守护（P0）

原状：`stops.enforce` 只在 `trade_executor.tick()` 里跑，引擎一挂/一暂停（今天 16:34、17:52
各发生一次），持仓止损就完全停摆。

现在：`src_python/stops_daemon.py` 独立进程，30s 一轮，只做「触发止损 → 平仓」，不开新仓；
每 5 轮跑一次账户对账。`stops.enforce` 加了跨进程文件锁（按库路径 hash），
引擎与守护同时扫也不会重复平同一笔仓。

安装为 launchd 常驻：`~/Library/LaunchAgents/com.trident.stops-guard.plist`
（`launchctl list` 可见，日志 `~/.trident/log/stops_guard.out.log`）。
`pause_data.sh` 会把它一并纳入暂停清单，`resume_data.sh` 会一并拉起。

### 8.2 日亏限额（P0）

`DAILY_LOSS_LIMIT_USDT=200`（本金 2%，已写入 `backend/.env`，0=不限）。
T2 口径，不是 quick_sim 口径：日初权益取当日 00:00 前最后一条 `account_snapshots`，
没有则取当日最早一条；当日亏损 = 日初权益 − 当前权益，同时看今日已实现净盈亏。
命中即 `PREFLIGHT_DAILY_LOSS` 拒新单，已有持仓仍可止损平仓；80% 给 `DAILY_LOSS_NEAR` 预警。

### 8.3 对账告警

守护每 5 轮把 `reconcile` 的 block 写进 `t2_alerts`（`feature_id=account_reconcile`），
同 code 24h 去重，问题消失时自动 `resolved_at`。R7 满仓已落了一条。

### 8.4 验收

### 8.5 现在的阻塞不在代码，在暂停

### 8.6 补充：暂停不是故障，是另一个会话装的「暂停守卫」

17:59:28 又被压回了一次。查清原因：不是引擎崩，也不是本会话的脚本，
而是 v478 另一条工作线装的：

- `com.trident.pause-guard.plist`（17:59 安装，常驻）
- `~/.trident/wrappers/pause_guard.sh`：每 60s 巡检，只要 `DATA_PAUSED` 存在

所以「恢复采集」与那条工作线直接冲突：我一 resume，它下一次巡检就压回。

## 9. 数据源补强（v491）：美股、原油现在真有源了

### 9.1 先定位"没数据"的真因

- 美股：`ASSET_ROUTE` 把 NVDA 等路由到 `yahoo`，但 Yahoo 在国内经常 429 / SSL 断连
  （实测 NVDA 要 8.6s 才成功一次，CL=F 直接空，GC=F 触发 90s 熔断）。
- 原油：`WTI` 的 `symbol=None`（OKX 没有原油永续），而
  `fetch_asset_candles_with_yahoo_fallback()` 里有 `if not sym: return None` ——
  **在问 Yahoo 之前就返回了**，所以永远走不到 `CL=F` 兜底。
- 报价侧：`feeds/domestic_quotes.py` 本来就有腾讯/新浪多源，但只覆盖 NVDA/AMZN/META/SKHYNIX。

### 9.2 改了什么

| 文件 | 改动 |
|---|---|
| `feeds/quote_sources.py` | 去掉 `symbol=None` 早退；新增 `fetch_daily_multisource()`：商品→新浪外盘日线优先，美股→Yahoo 失败转腾讯日线，韩股→Naver 日线→腾讯 |
| `feeds/domestic_quotes.py` | 腾讯报价从 4 个品种扩到 17 个（TSLA/AAPL/MSTR/MSFT/GOOGL/COIN/PLTR/SMCI/MARA/RIOT/MU/US_HYNIX + XAG/OIL/GOLD）；新浪加 XAG/OIL/GOLD |
| `api_server.py` | `_candles_for_asset()`：`domestic_spot` 先取真 OHLC（`CL=F`/新浪日线），拿不到才退回单点现货价；`yahoo` 日线走多源 |
| `scripts/check_quote_sources.py` | 新增行情源体检脚本（`--assets` / `--json`），逐品种打印 报价来源+耗时、K 线来源+根数 |

### 9.3 实测结果（2026-11-19 晚，本机直连）

| 品种 | 报价 | 日线 |
|---|---|---|
| WTI / OIL | 腾讯 `hf_CL` 82.8（约 0.3–0.8s） | 新浪外盘 CL 日线（约 1.3–2.8s，5 根） |

### 9.4 还差的（要真数据才能验收）

1. 以上都是"单次请求成功"，不是"连续 24h 稳定率"——需要引擎跑起来后看 `source_status` 成功率。
2. 原油只有**日线 + 现货价**，没有分钟 OHLC；日内策略在 WTI 上仍然只能等新浪分钟线或买商业源。

## 11. 账户级风控（v493）：相关性分桶 + 连亏熔断

**相关性分桶**：`cluster_of()` 把同向品种当一个下注。

| 桶 | 成员 |
|---|---|
| crypto_major | BTC / ETH / SOL |
| crypto_equity | MSTR / COIN / MARA / RIOT |
| metals | XAU / XAG / GOLD / SILVER |
| energy | WTI / OIL / BRENT |
| us_tech | NVDA / MSFT / GOOGL / AAPL / AMZN / META / TSLA / PLTR / SMCI |
| memory | SKHYNIX / US_HYNIX / MU / SAMSUNG |

新单后同桶名义 > `MAX_CLUSTER_WEIGHT_PCT`（默认 80% 权益）→ `PREFLIGHT_CLUSTER`；
85% 给 `CLUSTER_NEAR_CAP` 预警。

**连亏熔断**：最近 3 笔全亏、且最后一笔在 60 分钟内 → 新开仓拒 `PREFLIGHT_LOSS_STREAK`；
平仓不受影响（出口不能被堵）。阈值 `CONSECUTIVE_LOSS_LIMIT` / `CONSECUTIVE_LOSS_PAUSE_MIN`。

**顺手修的真 bug**：`market_ticks` 同一秒两根 tick 时，`ORDER BY ts DESC` 可能取到旧价。
实测 BTC 止损因此没触发。六处查询统一改成 `ts DESC, rowid DESC`。

## 12. 告警去噪（v494）：只有"该更新却没更新"才算过期

- `trading_health.build()` 新增 `market_state`（逐品种 age/开市状态/原因）与
  `stale_open_markets`；只有**开盘品种**超过 `HEALTH_TICK_STALE_SEC`（默认 300s）才进
  `TICK_STALE_OPEN` 告警。休市品种、库里只做新闻/归因的 A股/ETF（`classify=unknown`）不再算过期。
- `acceptance_check.py` 的"行情"项同样只看开盘品种，输出形如
  `5 个在交易 · 最新 6s 前 · WTI/XAU/BTC/ETH/SOL · 39 个休市`。
- `source_status` 补登腾讯美股（报价+日线）、新浪外盘、Naver 韩股、Yahoo chart。

顺手修的真问题：`.env` 里 `KEY=90   # 说明` 这种行内注释被简易加载器整行塞进 `os.environ`，
导致 `feeds.quote_sources` 在 import 期 `int()` 抛错 → 行情路由整体变 `unknown`。
现在加载器会剥掉未加引号值后的注释。

cd frontend

launchctl bootout gui/$(id -u)/com.trident.frontend
mv .next-prod .next-prod.bak-$(date +%H%M) && mv .next-prod.new .next-prod
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.trident.frontend.plist
