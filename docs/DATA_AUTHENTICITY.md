# 数据真实性规范（Data Authenticity Contract）

> 本文件是 Trident 的**数据宪法**：任何代码、脚本、报表、前端数字、AI 结论，
> 只要与真实行情/真实账本对不上，就是缺陷，不接受"看起来合理"作为解释。
>
> 版本 v396（2026-11-16） · 触发背景：WTI 报价冻结 22.5 小时 + 结算价取到 6 天前日线，
> 系统连续产出 3 笔"在不存在行情上发生的交易"，账面从 -0.13 变成 -215.28 而无人察觉。

---

## 0. 一句话原则

**不确定就空着，没数据就报废，绝不用任何东西填空。**

系统的可信度不取决于它产出了多少数字，而取决于**每一个数字都能被第三个人用 SQL 复现出来**。
宁可展示"0 笔有效样本"，也不展示"3 笔看起来正常的假样本"。

## 1. 六条铁律（违反即事故，不分大小）

| # | 铁律 | 典型反例（本项目真实发生过） | 代码位置 |
|---|---|---|---|
| **A1** | **不猜价**：任何价格必须有 `source + ts`，取不到就返回 `None` | `price_at()` 取 6 天前日线给 20 分钟仓位结算 | `db.price_at` |
| **A2** | **不补价**：缺口不得插值/前后填充/用"最近一个价"顶替 | 用 12 小时前的现价给过期仓结算 | `quick_sim.settle_trades` |
| **A3** | **不跨源拼价**：入场与出场必须能被同一条行情序列解释 | 入场用冻结 tick 88.985，出场用日线 86.43 | 审计 S1 |
| **A4** | **不占位**：`0` / `None` / 空字符串不得作为"有效值"参与统计 | `pnl=0_占位`，被当成"打平"计入胜率分母 | `sample_quality_filter` R3 |
| **A5** | **单一真值源**：账户、报表、前端、导出必须读同一张表同一口径 | 前端按 5000 名义金额算 -215.28，账本按 100 算 -4.31 | `api_server._paper_metrics` |
| **A6** | **口径可追溯**：每个对外数字必须能回答"哪张表、哪条 SQL、哪个时刻" | "胜率 33.3%" 无分母说明，无法判断含不含废弃样本 | 报表必须写分母 |

## 2. 四条口径标准（写进所有报表）

### 2.1 有效样本 = 已结算 且 非 ABANDONED

```
有效样本 = quick_sim_trades WHERE settled=1 AND verdict <> 'ABANDONED'
```

- `ABANDONED` 是**合法结果**，不是失败：它表示"这段时间没有可信行情，这笔不该被评价"。
- 废弃样本**不进分母、不进均值、不进胜率**，但**必须单独计数并展示**。
- 任何报表若无法拆出"废弃数"，视为该报表不合格。

### 2.2 绩效一律"扣费后"

- 结算落库的 `pnl_pct` 是**净值**（已扣 `cost_bps`）。
- `gross_pnl_pct` 是毛值，仅用于归因"策略有没有 alpha"与"成本吃掉多少"。
- **唯一允许被称作"策略有效"的条件**：有效样本 ≥ 60 且扣费后均值 > 0 且胜率显著高于 50%。
- 样本 < 60 时，报表必须打印：`有效样本 N 笔 < 60 门槛 → 当前数字不构成任何结论`。

### 2.3 结算时刻 = 到期时刻

- 结算价取 `due_ts = entry_ts + horizon*60` 的价，**不是**扫描当刻的价。
- `|exit_ts - due_ts| > 宽限期(60min)` → 这笔不是这个 horizon 的结果，判为违规（审计 S2）。
- 超宽限期仍取不到到期价 → `ABANDONED`，不允许回退到"现在的价"。

### 2.4 账实相符

```
Σ(quick_sim_trades.pnl_usdt WHERE settled=1)  ==  最新 sim_equity_snapshots.realized_pnl
```

差值 > 0.01 USDT 即违规（审计 S5）。三处（账本 / 快照 / 前端接口）必须同时对上。

## 3. 行情可信度门槛（数据能不能用来交易）

| 检查 | 判定 | 处置 |
|---|---|---|
| 报价年龄 | 最后一笔 tick 距今 > `QUOTE_MAX_AGE_MINUTES`(15) | 不建仓（R10） |
| 报价冻结 | 窗口内 tick ≥ 20 笔且只有 1 个价 | 不建仓（R10），审计 S3 报警 |
| 分钟线断档 | 1m 相邻间隔 ≥ 30 分钟 | 该时段不结算、不建仓；审计 S4 报警 |
| 日线兜底滞后 | 距到期 > 24 小时 | 视为无价（`PRICE_AT_DAILY_MAX_LAG_SEC`） |

> 为什么"冻结"比"缺失"更危险：缺失会报错，冻结不会。
> 冻结的行情看起来一切正常——有价、有时间戳、能算出盈亏，只是那个价不存在。

## 4. 三道守门机制（不是文档，是代码）

### 守卫：假数据（`src_python/fake_data.py` F1–F7，v403）

上面的六条铁律解决"该怎么算"，这一道解决"库里不许存在算不出来的东西"。
判据只有一条：**这个值能不能被真实观测复现**。不能 → 置 NULL 或删行，禁止填一个合理值。

| 代码 | 形态 | 处置 |
|---|---|---|
| F1 | 降级行 `evidence_confidence=0`（没算过，被当成"低分"） | 置 NULL |
| F2 | `impact_score=5.0` 且无门卫证据（默认值被当成"影响力 5"） | 置 NULL |
| F3 | `trade_reflections_v2.confidence_at_time=0` 占位 | 置 NULL |
| F4 | 引用降级决策的模拟成交（违反 R11） | 删行 + 重算净值快照 |
| F5 | 影子样本引用降级决策 | 删行 |
| F6 | `demo/mock/synthetic` 源的行情或新闻 | 删行 |
| F7 | 决策指向不存在的新闻（孤儿） | 删行 |

```bash
cd backend/src_python
python3 fake_data.py            # 审计（只读）
python3 fake_data.py --guard    # 有假数据退出码 1（已挂在每日 07:12 班次）
```

### 第一道：建仓闸门（`sample_quality_filter.pre_trade_check` R1–R10）

在 `quick_sim.open_trades()` 里逐条调用，任何一条不过就不建仓，并写 `quality_rejections`。

- R1 gate 通过 · R2 非 HOLD · R3 非占位 · R4 白名单 · R7 置信度 · R8 兄弟决策 · R9 未被拒签
- **R10（v396）报价健康**：冻结 / 过期 → 拒绝
- **R11（v396 P3）分析降级**：`analysis_degraded=1`（LLM 空返回 / 服务端兜底 / 只有摘要）
  的"方向"不是判断，一律不许建仓。实测 3 笔成交里 2 笔来自降级路径（v403 已删除，现存 1 笔真实成交）。

### 第零道：新闻预路由（`news_router.py`）

在进 LLM **之前**把交易池外的个股公告分流：无任何交易池/宏观关键词
（BTC/黄金/原油/美联储/CPI/中东…）+ 有公司行为标记（公告/财报/回购/辞职/中标…）
+ 有公司主体标记（公司/董事/股东/【…】/「公司名：」）→ `status=FILTERED`、
`gate_verdict=池外个股`，不进分析队列。宁可漏判多花 token，不可误杀真信号。
开关 `NEWS_POOL_ROUTER`（默认 on）。

### 第二道：结算审计（`src_python/data_authenticity.py`）

| 规则 | 内容 |
|---|---|
| S1 | 结算价 vs 到期价偏差 ≤ 0.5%，且到期时刻必须取得到行情 |
| S2 | 结算时刻与到期时刻偏差 ≤ 宽限期 |
| S3 | 报价冻结（1 个价 + 多笔 tick） |
| S4 | 1m 线断档 ≥ 30 分钟（仅对可交易品种硬判定） |
| S5 | 账实相符（账本 vs 净值快照） |
| S6 | 已结算行必须带 `cost_bps`，否则"扣费后是否为正"无法判定 |
| S7 | 到期超宽限期仍挂着未结算的仓位 |

```bash
cd backend/src_python
python3 data_authenticity.py              # 人看
python3 data_authenticity.py --write      # 写 reports/health/data_authenticity_YYYY-MM-DD.md
python3 data_authenticity.py --json       # 机器读
python3 data_authenticity.py --fail-on-bad  # 有违规退出码 1（cron / CI 用）
```

已挂进每日 07:12 的 `run_funnel_report.sh`，与漏斗日报同班次产出，不依赖人记得去查。

## 5. 新增数据源 / 新指标的准入清单（Checklist）

引入任何新行情源、新指标、新报表之前，逐条打勾；**缺一条不许上线**：

- [ ] 数据有唯一 `source` 标识与写入时刻 `ts`，且 `ts` 是**事件时间**不是入库时间
- [ ] 单位、时区、复权/未复权口径写进代码注释，并与现有序列一致
- [ ] 缺失时有明确返回（`None` / 空集），**没有任何默认值顶替**
- [ ] 与已有同源数据做过一期对账（偏差阈值写明）
- [ ] 引入的指标能追溯到原始表，报表里能点回 SQL
- [ ] 如果参与交易决策：接入 R10 / S3 / S4 判定
- [ ] 附带一条"坏数据"测试用例（冻结 / 缺口 / 异常值至少一种）

## 6. 违规处置流程（发现假数据之后的固定动作）

1. **停止扩散**：先让产出假数据的路径 fail-closed（加闸门或改 `None`），再谈修复。
2. **定界**：用审计脚本 `--dry-run` 列出受影响的全部行（不是"大概几笔"，是 id 列表）。
3. **留证**：`--apply` 前自动备份 DB 到 `backend/backups/`（带时间戳），备份路径写进文档。
4. **退回**：把污染结算置 `ABANDONED`（`settled=0 / exit_price NULL / pnl NULL / verdict ''`），
   同步清 `ai_decisions.is_correct`、`signal_performance` 对应行——**三张表必须一起退**。
5. **重算**：按正确口径重结，重建 `sim_equity_snapshots`（先清后建，避免 note 残留旧值）。
6. **对外改口**：重生成日报 / 成绩单 / 前端口径，并在 `CHANGELOG.md` 写清"旧数错在哪、错多少"。
7. **防止复发**：补一条回归测试 + 一条审计规则（缺一不可）。

> 第 4 步的三张表联动是最容易漏的地方：只退 `quick_sim_trades`，
> `ai_decisions.is_correct` 与 `signal_performance` 仍带着假结论参与准确率统计。

## 6.5 文本质量：长 ≠ 啰嗦（`text_quality.py`）

置信度折扣只对**重复**生效：重复句字数占比 ≥15% 才罚，上限 25%。
长度本身不罚——「推演完整」是证据充分的表现，不是缺点。
（v396 前按字数罚，实测把全库唯一一条 BTC SELL 从 17.9 压到 20 分闸门以下。）

## 7. 明令禁止（写代码时看到就该拒绝）

1. `if price is None: price = last_known_price` —— 用旧价顶替
2. `ORDER BY ts ASC` 取"最近一根" —— 方向反了就是 6 天前的价
3. 用 `try/except: pass` 包住取价/结算失败 —— 静默丢数据等于造假
4. 报表里出现没有分母的百分比（"胜率 33.3%"）
5. 把 `0` / 空字符串当作"没有数据"，或反过来把"没有数据"写成 `0`
6. 前端自己算一遍盈亏（必须调接口，接口必须读账本）
7. 用估算/插值/推算填补缺口后**不加标记**直接入库
8. 在文档或对外材料里写"已验证"而没有可复现的 SQL 或测试

## 9. 术语

- **有效样本**：`settled=1 AND verdict<>'ABANDONED'`
- **废弃（ABANDONED）**：到期无可信行情，该笔不评价、不计入任何统计
- **毛收益 `gross_pnl_pct`**：不含成本的价差收益
- **净收益 `pnl_pct`**：扣掉 `cost_bps` 后的收益（落库、报表、胜率一律用它）
- **冻结**：窗口内多笔 tick 同一个价
- **断档**：相邻两根 1m 线间隔超过阈值
