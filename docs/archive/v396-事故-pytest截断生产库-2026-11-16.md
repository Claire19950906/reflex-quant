# 事故记录：一次 pytest 把生产库的表截断了（2026-11-16 18:51）

> 结论先行：**是我的操作错误，不是系统 bug。** 已从 17:11 备份完整恢复，
> 损失的是 16:55–18:32 之间写入的 16 条决策（累计 494 → 478），
> 其余（19,214 条新闻 / 3 笔仓位 / 18,750 条质量拒绝记录）全部回来。
> 已加硬防护：pytest 今后默认跑独立临时库，碰不到生产库。

## 一、发生了什么

`llm_schema` 改完之后，我在 `backend/` 目录直接跑：
```
python3 -m pytest -q -k "schema or valid or ai_worker or decision or completeness or label"
```
325 passed —— 但同一时间，生产库 `backend/trident_event_bus.db` 被改成了：

| 表 | 事故前 | 事故后 |
|---|---|---|
| `raw_news` | 19,214 | **6** |
| `ai_decisions` | 494 | **4**（id 11946–11949，news_id 8000–9002） |
| `quick_sim_trades` | 3 | 1 |
| `quality_rejections` | 18,750 | 18,887（未受损） |

那 4 条决策的 `news_id` 是 `8000/8001/8002/9000` —— **测试夹具的编号**，
不是真实新闻 id。`created_at` 全部是 `2026-11-16 10:51:58`（UTC 写入格式），
和真实决策的 `+08:00` ISO 格式都不一样。

判断成立：**部分用例的 fixture 对"默认 DB 路径"执行了删除/重建**，
而我恰好是在生产库所在的目录里跑它们。

## 二、怎么发现的

原本是去核对"新决策的 `missing_fields` 是否如实记录了空字段"，结果发现：
- `SELECT COUNT(*), MAX(created_at) FROM ai_decisions` 返回 `4 | 2026-11-16 10:51:58`
- 18:32 那批 11920–11928 全部查不到
- `raw_news` 只剩 6 行

不是我预想的"schema 改坏了"，而是库被换了。

## 三、恢复

1. `launchctl bootout` 掉 engine / bridge / api（先停写）
2. 把被污染的库整份移走留证：`backups/trident_event_bus.CORRUPTED_by_pytest_20261116_1851.db`
3. 从最近一份干净备份恢复：`backups/trident_event_bus.before_void_20261116_171151.db`
   （恢复前先验：478 决策 / 19,214 新闻 / 3 仓位 / 18,750 质量拒绝，一致）
4. `launchctl bootstrap` 起三个服务，`/api/health` 200

**损失**：16:55–18:32 的 16 条决策（含 18:32 那批 8 条）。
其中 5 条是 `target_none` 降级、3 条是有真实推演的标的判断 —— 属于可再生的分析产物。
不可再生的历史（新闻原文、仓位、质量拒绝、快照）无损失。

## 四、防护（已落地）

`backend/tests/conftest.py` 顶部加硬闸：

```python
if not os.environ.get("TRIDENT_DB_PATH"):
    _TEST_DB_DIR = tempfile.mkdtemp(prefix="trident_pytest_db_")
    os.environ["TRIDENT_DB_PATH"] = os.path.join(_TEST_DB_DIR, "trident_event_bus.db")
```

- 只要没显式给 `TRIDENT_DB_PATH`，pytest 一律指向独立临时库
- 想针对真实库跑检查，必须显式 `TRIDENT_DB_PATH=/abs/path pytest ...`（自己承担风险）
- 顺手修了两个"依赖生产库里真实 tick 才通过"的用例（`test_quote_health_frozen` /
  `test_r10_blocks_frozen_quote`），改成自己插真实时钟的 tick —— 测试不该依赖生产数据

验证：加闸后重跑 `test_data_authenticity_v396.py` + `test_p3_gates_v396.py` +
`test_llm_schema_optional_v396.py` = **36 passed**，随后查生产库仍是 478 决策 / 19,322 新闻
（新闻数是引擎在跑，正常增长）。

## 五、这条要写进铁律

> **任何会写库的动作（测试、脚本、审计）默认只能碰独立库或只读生产库。**
> 需要写生产库的，必须显式声明路径 + 先备份。

这不是"运维细节"，它和数据真实性是同一条线：
**一个能一键清空自己历史账本的系统，不配谈可审计。**
