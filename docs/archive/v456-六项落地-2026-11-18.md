## 1) 口径漂移体检 —— 第一次跑就抓到真 bug

新增 `backend/scripts/fundamental_drift_check.py`（只读，写 `reports/fundamental_drift/latest.json`）。

三问：
| 问 | 判据 | 为什么 |
|---|---|---|
| 推导通道**有没有点** | 0 点 = FAIL | 港股首轮就是这么静默归零的（`REPORT_DATE` 写成 `REPORTDATE`，0 个点、0 报错） |
| 推导最新 PE/PB vs 供应商当期 | ≤5% OK，>25% FAIL | 中间档留 WARN + 证据，不制造告警疲劳 |
| 原始快照是否 >7 天没更新 | 超期 FAIL | 抓取链断掉不会有报错，只会让分位慢慢失真 |

**首跑：OK 21 / WARN 0 / FAIL 5。** 逐个核对后：

| 票 | 偏差 | 定性 |
|---|---|---|
| META | PB **+39.9%** | **真 bug**（见下） |
| TSLA | PB +22.0% | 供应商口径差异：我方分母 89.3B（SEC 2026-10-22 申报）vs 供应商隐含 110.2B |
| NVDA | PB +16.4% | 同上：我方 229.0B（SEC 2026-08-26 申报）vs 供应商隐含 266.0B |
| RIOT | PB +5.0% | 同上（2.1B vs 2.4B） |
| 00700.HK | PB +7.0% | 港股 BPS 与收盘不同步（我方当日收盘 vs 供应商 BPS 时点） |

### 抓到的真 bug：净资产取到了"更旧的那张表"

`_equity_asof` 原来按**已知日**排序。但 SEC 的 companyconcept 会把**往年对比期**
一起塞进后来的申报里 —— 实测 META 的 `2025-06-30` 净资产出现在 `2026-10-22`
那份 10-Q 的 XBRL 中。于是这一行"已知日"比 `2026-09-30` 那期更新，
按"已知日最新者胜"就把**旧报表**当成最新一期：

```
净资产被取成 195.1B（2025-06-30）+ 市值 1582B → PB 8.11
实际应为      272.4B（2026-09-30）           → PB 5.81（= 供应商 5.80）
```

修法：**可用性按已知日判、挑哪一张按期末排**。顺带修掉第二个问题 —— 期末最新那行
恰好没有净资产时会挡住有数的旧行（AAPL 的 `2026-09-30` 空行 vs SEC 的 `2026-09-26` 112B）。
现在改成"在**可用且有正净资产**的行里取期末最新的那张"。

修后：META +39.9% → **0.2%**，整体 **OK 22 / WARN 4 / FAIL 0**。
（WARN 那 4 条按上述定性属于供应商口径，不是我们的数据错 —— 证据都写进了 json。）

## 2) prompt 瘦身：同一批数字不进第二遍

`render_prompt_block` 里 FRED 层原来是**全量展示、不截断**：33 组读数逐条进 prompt。
但宏观已经通过 `macro_equity_regime` 的 4 个无量纲驱动（rate / risk / usd / curve）
进了**权重**，prompt 再列 33 行等于同一批数字的第二份拷贝 —— 模型容易拿它另起一套结论。

改成：10 个关键刻度（10Y / 2Y / 10-2 / VIX / HY OAS / DXY / CPI / 核心CPI / 失业率 / TIPS）
+ 一行「宏观驱动→板块倾斜」（与权重同一个函数算出来的），其余折叠成一句计数。

- 体积：实测同样 33 项、同样元信息，**534 → 216 字符（约 −60%）**，且写明了
  "另有 N 项已折叠、其信息已折算进倾斜行"，模型不会误判成"没有数据"。
- 开关：`TRIDENT_FRED_PROMPT_MODE=full` 可退回原样（排查"是不是我压过头了"用）。

## 3) 同业分组自动化：新票不再没有锚

原来 `SECTORS` 是**手写 26 只**：新票进来就没有同业锚（`available=False`）。
现在：**人工分组（优先） → 缓存 → 现场识别**三级。

- 识别用 `industry` 关键词映射（semiconductor / software / internet content / auto manufacturers…），
  命中不了具体行业就归 `gics:*` 粗桶，并在结论里标 `coarse` —— 精度不同，必须让人看得见。
- **yfinance 的 `.info` 在本机间歇 SSL 失败**（实测 ASML/MRVL/SHOP 全部识别不了），
  所以加了 **SEC SIC 兜底**（`submissions/CIK*.json` 的 `sicDescription`，走已验证的 data.sec.gov 通道）。
  修后：`ASML → semis`、`MRVL → semis`、`SHOP → software`（标记为 `auto`），半导体组从 8 只扩到 10 只。
- 识别结果落盘 30 天（`runtime/peer_cache/sectors.json`），决策链只读盘不发网络请求。
- cron 预热名单扩成「人工分组 ∪ 已识别 ∪ 决策名单」，实测 **命中 24 只 / 缺失 5 只 / 已归组 29 只**。
  拿不到行业的一律**不猜**，宁可仍走"无同业锚"。

## 4) MSTR 这类财库票：PB 不再参与判断

它净资产主要是 BTC，PB 0.7x 反映的是"市值贴着币价"，不是"股票便宜"。拿它做分位，
等于用币价变化冒充估值变化，会把一只高溢价杠杆票打成"极便宜"。

- 自身：`pb_excluded` 命中即跳过 PB 分量，`valuation_basis` 里不再出现 `pb`，
  并在 evidence 写清原因；PE 仍照常参与。
- 同业：财库票的 PB **不进同业中位数**（实测某组中位数 5.0 → 剔除后 5.5，回到真实可比水平）。
- 影响：`--coverage` 的"估值分位"从 16 只变 **15 只**（少的正是 MSTR）。
  PB 原始数据仍在库里（`MSTR:253天✓`），只是不再参与打分 —— 可审计，不删数据。

## 5) 离线 A/B：先补埋点，再谈胜负（不编数）

原计划直接跑 A/B，但先确认了一个硬前提：**`ai_decisions` 没有标的代码列**
（只有 `target_asset` / `asset_impact` / `asset_route` 等文本字段）。也就是说
"决策当时算的是哪只票、那只票当时多少分"根本没落库 —— 历史 900 条决策无法与
"当时的基本面"对齐，硬跑只能靠事后回填 = 假验证。

所以先补埋点，再做回放：

- `fundamental_shadow.record()` 现在额外写一张 `decision_fundamental_snapshot`：
  `decision_id / ts / asset / ticker / fund_score / valuation / peer_rel_score /
  macro_tilt / pb_excluded / sizing_mult / components`。老库自动 `ALTER` 补列。
- `backend/scripts/fundamental_ab_replay.py`：用**当时记下的分数**（不重算）+ 决策后真实收盘，
  比"含基本面"与"不含"的方向收益，门槛 **30 个样本**，不足就输出
  `verdict=insufficient` 并写明原因。
- 首跑：**可用样本 0 → insufficient**。这是诚实的现状，不是失败：从今天起每个公司标的
  决策都会留底，窗口（10 天）走完后自然会有第一批样本。

## 6) 基本面进仓位：先做成影子，不碰实盘

现状是"基本面只影响方向分（0.08），完全不影响下注大小" —— 一只估值最贵 + 盈利下修的票
和"最便宜 + 上修"的票下注一样大，这是明显的信息浪费。但直接改仓位是改交易逻辑，
没有证据就动手，代价不对称。

所以这一版只做**影子**：`sizing_multiplier = 1 + 0.20 × fund_score`，截到 `[0.80, 1.20]`，
基本面不可用时恒为 1.0，逐条记进 `sizing_mult` 列 —— **不改任何实际下单**。
等 A/B 攒够样本，再决定要不要放开（到那时只需把这一列接进下单链路）。
