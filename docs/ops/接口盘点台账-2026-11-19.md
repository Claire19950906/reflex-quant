## 口径与限制（先读，避免误删）

1. **静态字符串匹配**：前端模板 / 动态拼接（`${var}`、循环拼路径）无法完全展开，
   「零引用」是**候选清单**，必须人工复核后再决定下线。
2. **后端运行时注册**：部分路由按配置注册、或由 bridge 薄转发兜底，静态抽取可能漏。
3. **健康检查 / 探针 / 排障端点**：即使前端零引用，也可能被 launchd cron、watchdog、
   监控探针调用；下线前先全仓（含 `scripts/`、`*.sh`、`.plist`、`.md`）搜路径引用。
4. **重复路由不等于冲突**：见下节分类，多数是迁移后旧壳未删，需确认兜底链路。

### 第二轮核对要点（删任何一条之前必做）

1. **函数级复用**：后端 worker/cron 常 `import routers.<模块>` 后直接调函数，不发 HTTP，静态路径扫描看不到。
   对真候选先 `grep -rn "routers.<模块>" src_python scripts cron` 看是否被 import。
2. **动态路径**：前端模板 `${var}`、循环拼路径、上传返回 URL 等静态串扫不到，需在页面/组件里人工确认。
3. **内部探针**：cron wrapper、watchdog、`master_keeper`、coinglass 等可能打健康/信号端点。
4. 确认无上述复用后，再按"下线前置流程"走 smoke + 前端测试 + 人工过页面。

## 下线一个端点的前置流程（强制）

1. 全仓搜路径：`grep -rn "<路径>" --include=*.py --include=*.ts --include=*.tsx --include=*.sh --include=*.plist --include=*.md`；
2. 核对 `scripts/`、`docs/ops/进程模型清单`、launchd plist、cron 任务是否调用；
3. 若是 A 类薄转发壳：比对壳内兜底分支是否有 routers 侧缺失的逻辑，确认后再删壳；
4. 删除后跑 `pytest -m smoke` + 前端 `vitest run`，并人工过一次对应页面；
5. 新端点必须在本台账 JSON 里登记（路径 / 方法 / 实现文件 / 前端引用位置）。

## 新增端点登记规范（P2-2 收尾项）

- 后端新路由优先落在 `routers/`，bridge_server 只保留必要兜底；
- 端点路径与前端 `lib/api*.ts` 的封装一一对应；
- 合并到 `endpoint-inventory` 台账前，在代码注释标注前端引用文件。
