## 1. 两个闸门

### 1.1 下单前：`execution_guards.check_new_entry()`

位置：`trade_executor._process_one()`，风控通过之后、`adapter.place_order()` **之前**。
拒绝就写 `trade_audit_log(status=risk_rejected)`，不会产生成交。

| 规则 | 默认 | 行为 |
|---|---|---|
| 同品种已有 open 同向仓 | 拒绝 | `portfolio_guard:duplicate_open:ETH:short:51` |
| 同品种已有 open 反向仓 | 拒绝 | 执行器没有“先平后开”的原子逻辑，反向只会变对锁；`ALLOW_HEDGE=1` 可放 |
| 单品种名义 / 权益 | 50% | 超了先缩单；缩到不足 100 USDT 直接拒绝 |
| 总名义 / 权益 | 100% | 当前已 3.5 倍，任何新单都会被拒，直到敞口降下来 |
| 开关 | `DUP_ENTRY_GUARD=enforce` | `shadow` 只标注放行，`off` 关闭 |

### 1.2 开仓后：`stops.py`

- `trade_executor._mirror_to_t2()` 写持仓时调用 `auto_stop_price()`：
  空单 `entry × 1.02`、多单 `entry × 0.98`（`AUTO_STOP_PCT=2.0`）。
- `TradeExecutor.tick()` 每轮**先扫止损，再处理新决策**：
  多头 `mark <= stop` / 空头 `mark >= stop` → `store.close_position()`，
  写 `realized_pnl`、更新 `t2_account`，并记一条 `t2_interventions(kind=auto_stop)`。
- 存量无止损持仓可人工补挂：`python3 stops.py --backfill --once`。
  本次已给 7 笔存量仓补挂，补挂价均未触发，当前平仓 0 笔。

## 3. 配置

```bash
DUP_ENTRY_GUARD=enforce      # enforce / shadow / off
ALLOW_HEDGE=0                # 同品种反向开仓是否允许
MAX_ASSET_WEIGHT_PCT=50      # 单品种名义 / 权益
MAX_GROSS_LEVERAGE_PCT=100   # 总名义 / 权益
PORTFOLIO_GUARD_MIN_USDT=100 # 缩单后低于此值直接拒绝
AUTO_STOP_ENABLED=1
AUTO_STOP_PCT=2.0
```

## 4. 边界

- 止损平仓按**最新 tick 价**成交，不模拟滑点；真实模式必须把止损单挂到交易所，
  本模块的纸面平仓不能替代交易所止损。
- 存量 7 笔是按“入场价 ±2%”补挂的，不是按策略原始止损位——因为原始止损位从未记录。
- 组合闸只拦 `trade_executor` 这条路径；手工往 `t2_positions` 写仓不经过它。
- 当前总敞口已超上限，新信号会被**持续拒绝**，直到止损触发或人工平仓把敞口降到 100% 以下。
  这是有意的“先降风险、再谈开仓”，不是故障。
