## 3. 「检查过还会错，说明系统有大漏洞」

### 3.1 为什么会这样（机制层面，不是态度层面）

我上一轮的三次口径错误（出队速率、PENDING 过滤、旧存量当现状）有一个共同点：
**我在用「看起来对的数字」代替「能自证的数字」**。系统也一样：

| 病灶 | 具体表现 |
|---|---|
| 一个标记装两种事实 | `FILTERED` 同时是「判了噪音」和「超龄没人认领」 |
| 一个 0 装两种含义 | `evidence_confidence=0` 同时是「算过没信心」和「根本没算」 |
| 数字能算、但没人断言 | 源停了三天没有任何告警，直到有人问「怎么没新闻」 |

所以「代码检查一遍没问题」必然没用 —— 检查的是代码，坏的是**数据语义**。

### 3.2 修法：把断言写成代码（`pipeline_guard.py`，v420）

9 条断言，只读，一次跑完，任一条不满足就说「哪条链路坏了」：

| # | 断言 | 今天实测 |
|---|---|---|
| ① | 近 1h 入库 ≥ 近 7 天均值的 30% | 正常（21 条/h，门槛 21） |
| ② | 被否新闻必须带理由（`filter_reason` 或 `gate_verdict`） | **断链 1184 条** |
| ③ | 判了「可交易」就必须被放行 | **断链 92 条** |
| ④ | 积压 ≤50 或决策 ≥3/h | 正常（积压 54，8/h） |
| ⑤ | 结构化字段缺失 ≤50% | **断链 95.8%** |
| ⑥ | 置信度 0 必须能归因 | 异常 155 条 |
| ⑦ | `routing_miss` ≤20% | **异常 46.1%** |
| ⑧ | 无 error 源、无沉默源 | **异常 49 个** |
| ⑨ | 影子账本在增长（说明有测量） | 正常（15 条） |

②③ 打中的正是「旧代码残留」—— 守卫不知道日期，它只知道**这两条不该成立**。
这就是「以后把同类问题全揪出来」的可执行版本：不靠人记得检查什么，靠断言跑。

## 4. 修复优先级（按「能多产出多少真信号」排）

| 级别 | 修什么 | 依据 | 预期 |
|---|---|---|---|
| **P0** | 结构化输出缺失（95.8%） | 降级路径把字段留空 → 方向分 0 → 置信度 0 | 置信度能真算出来，闸门才有意义 |
| **P1** | 品种路由覆盖率（46% routing_miss） | 词典只认 BTC/ETH/XAU/WTI 等少数 | 决策才可能变成交易 |
| **P2** | 源健康（49 个 error/沉默） | eastmoney_ann 停 3 天、fred/finnhub 50%+ 失败 | 入库量与广度回升 |
| **P3** | 守卫进日常（定时跑 + 告警） | 现在只有手动 CLI | 断链当天就被发现 |

## 5. 边界

1. 守卫**只读**，不改库、不改决策链。
2. 阈值集中在 `THRESHOLDS`，改门槛是一处改动。
3. 「算不出来」一律报 unknown，不报 ok —— 把「不知道」当「没问题」是这类工具最危险的错法。
4. ②③ 两条今天为「断链」，是历史存量；重启后新写入已为 0。守卫按窗口统计，不给历史开绿灯。
