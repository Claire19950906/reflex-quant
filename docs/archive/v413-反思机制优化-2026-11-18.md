## 四、影子层怎么判对错（口径写死，别再改）

| 项 | 定义 |
|---|---|
| `claimed_direction` | 系统当时声称的方向（`shadow_ledger.direction` / `shadow_degraded.direction`） |
| `realized_direction` | 4 小时窗口内价格实际走的方向（`UP` / `DOWN` / `FLAT`） |
| `verdict` | `direction_ok`（一致）/ `direction_wrong`（相反）/ `flat`（几乎没动，可能假 tick）/ `insufficient`（无结算价） |
| `flat` 判据 | `|move_pct| < 0.01%`，与 `shadow_degraded_collect` 的 `FLAT_PCT` 对齐 |
| `reflection_effective` | 1 = 方向被价格证实；0 = 被否证；**NULL = 判不了（不当 0 用）** |
| `attribution` | 固定 `none`：**只判"对不对"，不做"为什么"** —— 归因可以后补，"对不对"必须先有 |

### 刻意不做两件事

1. **不做 LLM 归因**。原因见第一节：LLM 那条支路 3 天 13 次调用、63% 超时。在"对不对"都判不了的时候叠加归因，只是多一层文本。
2. **不回填历史积压**。按现行口径：*数据采集中断后恢复，以恢复时刻为新起点，不处理停机期堆积的历史数据*。首次运行只写水位（`2026-11-18T13:51:53`），旧 72 条不追溯。要追溯只需一条命令：
   `python3 shadow_reflections.py --commit --since 2026-11-01`

## 十、第二批：三项「都做」的落地结果（同日下午）

### ① LLM 归因支路：真因不是「模型不行」，是「兜底烧时间 + 没样本」

| 发现 | 证据 |
|---|---|
| 5 次失败**全部**来自本地兜底 | `ai_call_stats`：`local/qwen2.5:3b-reflect` 5 条 `network_error/ReadTimeout`，耗时 90007 / 90013 / 90039 ms（卡满 90s 超时） |
| 主模型本身是好的 | `minimax-reflect/MiniMax-M2.7` 今日 6 次 ok，4–28s |
| 为什么兜底 | `quota` 熔断器 `fail_threshold=1, open_seconds=1800`——一次 429 就封 30 分钟，然后每次都往下掉到本地 3B |
| 3 天只有 13 次调用的真原因 | **不是超时**。候选 SQL 要求 `pnl_pct < -0.005`（只反思亏损单）且 `llm_depth_reflection=''`，全库已结算亏损样本≈0 → 队列本来就是空的 |

改动（`engine/ai_worker.py::chat()`）：

- `purpose='reflection'` 时**默认不再兜底本地 3B**（`REFLECTION_ALLOW_LOCAL=1` 可恢复）；
- 允许兜底时把超时压到 ≤25s（3B 要么 25s 内答，要么永远答不出来）；
- `float(m.get("timeout", 60.0))` → `float(m.get("timeout") or 60.0)`，容忍配置里的 `timeout=None`。

实测（把池子只留本地 3B）：

```
[chat:reflection] all models failed; last_err=qwen2.5:3b 本地兜底对 reflection 关闭（…）
```

**立即返回，不再有 90s 久等。** `gate` / `advisor` 两个高频通道的本地兜底没动。

> 加量这件事仍然做不了：没有已结算的亏损样本，把模型换得再好，队列还是空的。真正的样本来源是新加的影子层（见第三节）。

### ② 撤掉「不可测」经验：两处注入一起堵

注入有两条路，之前谁都没过滤 `observe_only`：

| 路径 | 位置 | 改法 |
|---|---|---|
| 单品种专项 | `ai_prompts.load_recent_insights_block` | SQL 加 `AND (?=1 OR COALESCE(observe_only,0)=0)` |
| 全局分区 | `review/review_agent.build_active_insights_section` | 同上，**只过滤 `kind=1`**；`kind=0` 硬铁律 5 条原样保留 |

顺带修掉一处口径分裂：prompt 里的样本门槛**写死 1**，而 `config.REVIEW_INSIGHTS_MIN_SAMPLES=5`——同一件事两套门槛，实测 32 条里有 17 条样本只有 2~4 却照样注入。现统一读 config（`INSIGHTS_MIN_SAMPLES` 可覆盖）。

实测：

|---|---|---|
| 单品种路径注入条数 | 32 | **0** |
| 全局分区软启发行数 | 28 | **1**（`EX#1288` WTI 仓位规则，7 样本、可测） |
