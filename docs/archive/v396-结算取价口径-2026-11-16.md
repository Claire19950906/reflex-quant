# v396 · 结算价取到了 6 天前的日线（2026-11-16）

> 一句话：`db.price_at()` 的日线兜底用 `ORDER BY ts ASC` + 6 天回看窗口，
> 取到的是窗口里**最老**的一根日线。WTI 1m 线断档时，两笔 20 分钟仓位被
> 11-10 / 11-11 的收盘价结算，凭空造出 -3.17%/笔，胜率、权益、反思样本全被污染。

## 一、现象

| 仓位 | 品种 | 方向 | 入场 | 结算价 | 记的盈亏 |
|---|---|---|---|---|---|
| #258 | WTI | BUY | 88.980 | 86.430 | -3.17% |
| #259 | WTI | BUY | 88.985 | 86.430 | -3.17% |
| #260 | WTI | SELL | 88.483 | 86.420 | +2.03% |

同时前端账户显示 **9,784.72 / -215.28 USDT**，而漏斗日报和 `sim_equity_snapshots`
显示 **9,995.69 / -4.31 USDT**。两个数字都"看起来对"。

## 二、根因

### 1. 日线兜底方向反了（代码 bug）

`db.price_at()` 第三步：

```python
# 旧
("SELECT close FROM ohlcv_daily WHERE asset=? AND ts>=? AND ts<=? "
 "ORDER BY ts ASC LIMIT 1", (a, t - 6 * 86400, t + tol))
```

窗口 `[t-6天, t+5分钟]` + `ORDER BY ts ASC` = **窗口里最老的那根**。
2026-11-16 02:40 / 04:55 两笔到期时，WTI 的 1m 线整段不存在
（实测 11-15 全天 0 根、11-16 从 07:00 才开始），于是兜底取到了
11-10 收盘 86.43 和 11-11 收盘 86.42 —— 与到期时刻相差 **6 天**。

### 2. 数据侧：WTI 报价长时间冻结/断档

| 数据 | 事实 |
|---|---|
| `market_ticks` WTI = 88.985 | 从 11-15 08:14 到 11-16 06:49 共 **22.5 小时**、7,160 个 tick 同一个价 |
| `ohlcv_intraday` WTI 1m | 11-15 全天 0 根；11-16 只有 07:00 之后 |
| 结算价 86.43 | 在 1m 线里只出现过 1 次（11-11 09:23） |

冻结报价 + 分钟线断档 → 结算器拿不到到期价 → 落到日线兜底 → 撞上上面的方向 bug。

### 3. 账户口径分裂（代码 bug）

`_paper_metrics()` 一律用 `strategy_params.notional_usdt`（5000），
而结算账本 `quick_sim_trades.notional_usdt` 是 100：

```
前端：5000 × (-4.3056%) = -215.28 USDT
账本： 100 × (-4.3056%) =   -4.31 USDT
```

同一批交易、同一套库，两个"正确"的账户余额。

## 三、修复

| 文件 | 改动 |
|---|---|
| `src_python/db.py` | `price_at()` 日线兜底改 `ORDER BY ts DESC`；新增 `PRICE_AT_DAILY_MAX_LAG_SEC=86400`，滞后超上限一律返回 `None`（不猜价） |
| `src_python/quick_sim.py` | 超宽限期（`QUICK_SIM_SETTLE_GRACE_MINUTES=60`）拿不到到期价 → 直接 `ABANDONED`，不再用"现在的价"给 12 小时前的 20 分钟仓位结算 |
| `src_python/api_server.py` | `get_replay_signals` 带出 `qs.notional_usdt`；`_paper_metrics` 优先用该笔仓位自己的名义金额 |
| `scripts/audit_stale_settlements.py` | 新增：逐笔核对"结算价 vs 到期时刻价"，支持 `--dry-run` / `--apply`（自动备份，退回可疑结算） |
| `tests/test_quick_sim_settle_due_price.py` | +4 个回归用例（最近日线、拒绝 6 天老价、断档不伪造盈亏、过期不用现价） |
| `tests/test_paper_metrics_notional_v386.py` | +3 个用例（仓位名义金额优先 / 缺省回退 / 0 不算） |

## 四、重算结果

| 项 | 修复前 | 修复后 |
|---|---|---|
| #258 / #259 | -3.17% ×2（假亏损） | `ABANDONED`，不计入统计 |
| #260 | +2.03% WIN | **-0.13% LOSS**（到期价 88.335，扣 30bps 成本） |
| 累计盈亏 | -4.31 USDT（日报）/ -215.28（前端） | **-0.13 USDT**，两处一致 |
| 权益 | 9,993.66 / 9,784.72 | **9,999.87** |
| 胜率 | 1 胜 2 负 33.3% | 0 胜 1 负（有效样本只剩 1 笔） |

> 结论要说清楚：修复后**没有"变好看"**，只是把 3 笔假结果还原成
> 1 笔真结果 + 2 笔无效。有效样本从 3 掉到 1，这恰恰是当前系统真实的状态。

## 六、运维注意

进程的代码不会自动重载。本次改动后必须重启 **engine / bridge(8100) / api_server(8000)**；
其中 bridge 是结算的实际执行者（`quick_sim.run_cycle` 由它托管），只重启 api_server 不生效。
