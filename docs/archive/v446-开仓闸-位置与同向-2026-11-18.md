# v446 · 开仓闸：位置分位 / 同向确认（2026-11-18）

> 触发：用户「有没有什么实用的新功能」→ 从 11-18 复盘里挑出最贵的两条（追极值、未同向）做闸。
> 原则：**先验证、再上线**。验证结果推翻了其中一条，所以最终交付的是「读数 + 可开关」，不是「默认拦单」。

## 0. 一句话

**两道闸都做出来了，但只有「同向确认」在 1 小时档站得住（+0.15pt/笔，|t|=3.28），
「不追极值」在 1 小时档是反向的（-0.21pt，|t|=3.76）。两者放行组都仍是负期望，
所以默认影子模式：只标注，不拦单。**

## 1. 为什么是这两条

11-18《判断能力对市场》里两个最刺眼的数：

| 现象 | 原口径 | 结论 |
|---|---|---|
| 11 笔里 5 笔进在区间极值，贡献 **96% 亏损**；入场位置与盈亏 r=0.69 | 20 分钟实盘 | 像是"追顶/追底" |
| `pre_confirm=1` 命中 80%，`=0` 只有 25%（n=13） | 4h 影子账本 | 像是"同向才做" |

两条都只有十几笔样本，必须放大验证再决定要不要写进决策链。

## 2. 验证：2030 笔历史信号，分 20m / 1h / 4h

样本与《能不能赚钱》同一批（`t2_sim_trades` 已结算）；位置只用**决策前已收盘**的 K 线；
出场用同一套 `exit_at`（尾部未走完 / 空洞超 2 周期一律跳过）；净收益扣 30bps。

### 2.1 主表（净收益 / 笔）

| 持有期 | 合格样本 | 全样本 | 位置闸：拦 → 放 | 同向闸：拦 → 放 | 两道一起 |
|---|---|---|---|---|---|
| 20m | 419 | **-0.292%**（胜率 13.8%） | -0.279 → -0.296（-0.017pt，|t|=0.53） | -0.275 → -0.312（**-0.037pt，反向**） | -0.272 → -0.358（-0.086pt，反向） |
| 1h | 391 | **-0.335%**（胜率 18.7%） | -0.176 → -0.383（**-0.207pt，|t|=3.76 反向**） | -0.401 → -0.250（**+0.152pt，|t|=3.28**） | -0.339 → -0.323（+0.016pt，几乎无差别） |
| 4h | 419 | **-0.496%**（胜率 33.9%） | -0.467 → -0.506（-0.038pt，反向） | -0.467 → -0.532（-0.064pt，反向） | -0.475 → -0.568（-0.094pt，反向） |

读法：位置闸在 1h 拦掉的那 91 笔均值 -0.176%，比放行的 300 笔 -0.383% **更好**——
也就是说"追极值"在 1 小时尺度上不是错误，而是动量。20m 上它没有差别，4h 上也没有。
**11 笔的 r=0.69 是小样本噪音，不能升级为规则。**

同向闸在 1h 是唯一有正贡献的：拦掉"未同向"的 220 笔（-0.401%），留下 171 笔（-0.250%），
差 +0.152pt，|t|=3.28。但**放行组仍是 -0.25%/笔**——它只是少亏，不是能赚。

## 3. 最终做了什么

| 交付物 | 路径 | 说明 |
|---|---|---|
| 核心模块 | `backend/src_python/entry_guard.py` | 位置分位、30 分钟同向、回踩价、影子回放、2030 笔验证；tick/K 线不足一律 `available=False` |
| 只读端点 | `backend/src_python/routers/guards.py` | `/api/guards/entry/config`、`/check`、`/shadow`、`/scan`（10 分钟缓存） |
| 决策链接入 | `decision_guard.evaluate_decision` | 结果里新增 `entry_guard` 读数；默认 shadow，不动作 |
| 前端页 | `frontend/app/guards/page.tsx` + 导航「开仓闸」 | 三道闸对照表、位置分桶、单条实时读数 |
| 测试 | `backend/tests/test_entry_guard.py` | 14 passed：位置边界、tick 不足、同向、影子/生效、方向收益 |
| 开关 | `.env.example` | `ENTRY_GUARD_MODE=shadow|enforce|off` 等 6 个 |

### 3.1 三档模式

| 模式 | 行为 | 什么时候用 |
|---|---|---|
| `shadow`（默认） | 只把位置/同向写进决策结果，**不拦单** | 现在。攒证据、看读数 |
| `enforce` | 触发规则时把 BUY/SELL 降为 HOLD，`hold_reason` 写明理由 | 只在把持有期切到 1h+ 后考虑，且只开同向闸 |
| `off` | 不计算、不挂读数 | 排障或压测 |

### 3.2 硬规矩（代码里写死）

1. **不许前视**：位置只用决策前已收盘的 K 线；实时 tick 也只取 `ts <= 决策时刻`。
2. **取不到就不判**：20 分钟窗口少于 5 个 tick → `available=False`，既不拦也不放。
3. **不拿"没数据"当"安全"**：缺数据不会让 `block=False`，只会让结论变成"不可判"。
4. **样本 <30 不下结论**：`_gate_verdict` 直接返回"样本不足"。

## 4. 怎么用

```bash
# 回放验证（约 20 秒；只读，不发网络请求）
cd backend/src_python && python3 entry_guard.py --signals --days 60

# 单条检查
python3 entry_guard.py --check BTC SELL 1794964908

# 端点
curl 'http://127.0.0.1:8000/api/guards/entry/check?asset=BTC&action=SELL'
curl 'http://127.0.0.1:8000/api/guards/entry/scan?days=60'
```

前端：`/guards`（导航「更多 → 交易 → 开仓闸」）。

**注意**：新端点与页面需要重启 `api_server` 才生效；引擎不重启也能跑，但决策里的
`entry_guard` 读数要等引擎下次加载。

## 5. 诚实边界

- 2030 笔是**历史模拟信号**，不是实盘；同向闸的 +0.152pt 只是样本内，仍需样本外验证。
- 30bps 成本下，所有组都是负期望；闸门只能改变"亏多少"，不能把符号变正。
- 位置闸在 1h 的"反向"是显著的反向（|t|=3.76），这不是"没测出来"，是**测出来不能这么做**。
- 没做：分品种阈值、按波动率自适应的窗口、把同向闸与持有期绑定（先把读数跑一段再说）。
