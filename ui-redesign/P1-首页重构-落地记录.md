## 改了什么

### 1. 新增顶部结论区（4 张 KPI）

新文件：`components/quant/account-kpis.tsx`

| 卡片 | 取值 | 口径 |
|---|---|---|
| 总权益 | `account.current_equity_usdt` | 与模拟盘页同一接口 `/replay/positions` |
| 已实现盈亏 | `account.realized_pnl_usdt` + 相对起始权益的 % | 红=亏 绿=赚（沿用语义色） |
| 胜率 | `settled` 里 `is_correct` 为 WIN / LOSS 的比例 | 徽标写「已结算 N 笔」；样本为 0 时显示「—」不估算 |
| 活跃信号 | 传入 events 中**今天**的 BUY / SELL 条数 | 多空分开计数 |

不新增后端接口，前端也不自己乘价格算钱。接口没回来时显示「—」+ 一行「账户快照计算中 / 接口暂不可用」，**不显示假 0**。

### 2. 新增「当前持仓」表

新文件：`components/quant/positions-table.tsx`

- 取 `settled != 1` 的持仓，最多 8 行：品种 / 方向（多·空）/ 入场价 / 现价 / 浮盈亏（USDT + %）。
- 表尾一行：保证金占用、可用余额。
- 空态文案：「当前没有未平仓的持仓 —— 模拟盘开仓后，这里会逐笔显示入场价、现价与浮盈亏。」
- 右上角「去模拟盘 →」。

这是首页**第一次有持仓视图**（此前只有一张账户总额卡）。

### 3. 账户卡去重

`components/quant/paper-equity-card.tsx` 新增 `hideValue` prop（默认 `false`，不传即旧行为）。
首页传 `hideValue`：只保留权益曲线 + 已实现/浮盈亏/可用/占用，把「权益大数字」让给顶部 KPI，避免同一屏出现两个 9,784.72。

### 4. 页面顺序

`components/quant/live-desk.tsx`：

```
全局时段条
KPI 行（新增，跨两列）
┌ 左：实时事件流 ─────────┬ 右：市场分类 → 纸面账户曲线 → 当前持仓（新增） → 4 张状态卡 → 图表/对话 → 信号台账 ┐
复盘战绩 / 错误归因 / 错过信号（保持原样，默认折叠）
```

### 5. 一并修掉的布局 bug（都是本次截图暴露的）

| 位置 | 问题 | 修法 |

| `gatekeeper-filter-stream.tsx` | 双列流第二列溢出面板被裁，长 URL 撑破单元格 | 两列容器加 `min-w-0`，正文 `min-w-0 break-words` |

## 已知问题 / 取舍

1. **密集持仓态没验证到**：当前账户 `持仓 0 笔`，8 行表格的饱满排版只能在真实开仓后看。
2. **KPI 与持仓表各自轮询** `/replay/positions`（60s 一次，另加账户卡 120s 一次）。三个组件同一接口共 3 个轮询，代价可接受；后续若要省请求，应把取数提到 LiveDesk 用 context 下发。
3. **事件流仍是全量展开**（`showAll=true` 默认）。本次只做了「结论上提」，没有把事件流改成摘要流；如果下一步要让首屏只留 4–6 条，需要动 `event-bus.tsx` 的默认 `showAll`。
4. 后端本轮挂过一次（`master_api.py` 卡在启动），期间截图全是降级态；恢复后重拍，KPI/曲线/持仓均为真实数据。
