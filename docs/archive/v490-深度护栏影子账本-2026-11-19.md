# v490 · 深度护栏进影子账本：先记账，不急着给权重（2026-11-19）

> 一句话：`gm_down / opm_down / negative_fcf / rev_down / ...` 现在会跟着决策一起落库，
> 但**不参与打分**；等有 60 笔可评估样本、flagged/clean 各 ≥20，才谈"该不该折半盈利修正"。

---

## 一、为什么先记账

v488/v489 把美股和 A/H 的深度读数补齐了，但它们只进解释。要给它权重，必须先回答：

> 被 `gm_down` / `negative_fcf` 标记的票，之后 10 天是不是真的跑得更差？

没有这个证据就加权重，和 0.08 本身"先验拍出来"是同一个问题。
所以这版只做三件事：落标签、写评估脚本、把门槛写死。

## 二、落库：`decision_fundamental_snapshot` 加三列

| 列 | 来源 | 说明 |
|---|---|---|
| `depth_flags` | 美股 `components.depth_flags`；A/H 顶层 `flags` | JSON 数组，只保留风险标签 |
| `depth_zone` | `components.earnings_zone` / `depth_earnings_zone` | `peak / mid / trough` |
| `depth_points` | `components.depth_points` 或 `n_quarters` | 参与计算的财报期数 |

标签白名单：

```
gm_down, opm_down, negative_fcf, high_leverage, negative_equity,
rev_down, np_down, roe_down
```

**不进来**的：`growth_premium`、`earnings_window`、`low_cash_quality`、`earnings_peak`
—— 这些是状态标签，不是"生意在变差"；混进来会让 A/B 的 flagged 组失去含义。

迁移是幂等的 `ALTER TABLE ADD COLUMN`，不重建、不删历史行。
已有 15 行（v490 之前）的 `depth_flags` 保持 `NULL` —— **不回填**：
用今天的读数补昨天的决策，等于用事后信息伪造"决策当时就知道"，A/B 会失真。

## 三、评估脚本：`scripts/fundamental_depth_ab.py`

口径：

- 只用决策当时落库的 `depth_flags`，不重算；
- 前向收益用 `ohlcv_daily` 的 +10 天收盘（与 v454 主判据一致），缺行情就剔除；
- **顺手修了行情符号映射**：`ohlcv_daily` 美股存裸 ticker（`AAPL`），旧 A/B 写 `US_STOCK:AAPL`，
  永远查不到 → 0.08 的 A/B 也会永远 0 样本；
- **目前只能结算美股/商品**：`ohlcv_daily` 没有 A/H 日线，A/H 样本会进 `no_price` 桶，
  等 A/H 日线落库后才参与比较（不拿实时价倒推历史收益）；
- 分两组：`flagged`（有任一深度护栏）vs `clean`（无护栏）；
- 比较平均前向收益、中位数、下跌比例；
- **门槛：总可评估 ≥60，且 flagged/clean 各 ≥20**；不到判 `insufficient`。

当前真实库：

```
快照 15 行，基本面可用 6，有 ticker 0
可评估 0 / 60
结论 insufficient
```

这不是脚本失败，是样本还没产生：现有 15 行多是 BTC/XAU 这类非公司标的，
没有 ticker 就没有前向个股收益。只有等真实公司决策（US_STOCK / CN_STOCK / HK_STOCK）
落库并走完 10 天，样本才会开始累积。
