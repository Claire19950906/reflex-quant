# v475 · 2026-11-19 可信度门槛闸：低可信度的分数不够格开仓

## 一句话

v472–v474 让"分数可信度"能被打折地参与方向分、能决定仓位乘数。但它一直没回答最前面的那个问题：
**这个分数够不够开仓**。v475 把门槛也接上——可信度低，门槛抬高，同分数下更容易落在 HOLD。

## 一、机制

```
penalty = min(0.10, 0.10 × (1 − conf))          # 只收紧，不放宽
buy_min_effective  = buy_min_calibrated  + penalty
sell_min_effective = sell_min_calibrated + penalty
```

- conf = 1.0 → penalty 0（门槛不动）
- conf = 0.44（COIN）→ **+0.056**
- conf = 0 → 封顶 +0.10
- **conf 不可得（老数据/无基本面）→ 0**，v321 的纯校准行为逐位不变

**为什么封顶 0.10**：基本面在 `DIRECTIONAL_WEIGHTS` 里只占 0.08。一个权重 0.08 的因子不该有能力否决一条由新闻+趋势+结构共同支撑的信号。0.10 的幅度是"需要更强证据"，不是"一票否决"。

**为什么做权重打折之外还要做门槛**：这是两件事。
- 权重打折回答"**这个分数算多少**"（连续，影响 magnitude）；
- 门槛收紧回答"**多确定才准开**"（离散，影响 binary 决策）。

只做前者，会出现"分数被压小了、但压小后的分数刚好还在门槛上"的偶然开仓。

## 二、顺带修掉一处不一致（v475 的真正重点之一）

v472 的"权重按可信度打折（0.6~1.0 倍）"原来**只对 alt 生效**，公司票在 v474 拿到 `confidence` 之后仍然拿满 0.08。也就是说：**COIN 被标了高分歧，但权重一分没降**——标出来了却没管。

v475 把它打到公共路径：

| 票 | conf | 原来权重 | 现在权重 |
|---|---|---|---|
| COIN | 0.44 | 0.080 | **0.0621** |
| AAPL | 0.76 | 0.080 | 0.0723 |
| AMZN | 0.85 | 0.080 | 0.0752 |
| BTC | 0.57 | 0.0624（v472 已折） | 0.0624（不变） |

## 三、实测：31 个品种，今天**没有一个动作被翻掉**

先纠正一个我原先写错的事实：**生产 `buy_min` 是 0.1725**（不是 v474 报告里测试夹具用的 0.35）。所以门槛的绝对位置比我想的低。

**这说明机制是对的，不是没生效**：这些品种要么分得很开（USD +0.686 / SOL −0.751），要么本就中性（COIN +0.067）。真正会翻的，是那种"分数刚好压线、可信度又低"的形态——今天没有，不代表机制没用。

## 四、可审计性

`result["thresholds"]` 现在同时留三个数 + 一个附加状态：

| 字段 | 含义 |
|---|---|
`buy_min` / `sell_min` | 配置原始值 |
`buy_min_calibrated` / `sell_min_calibrated` | v321 分组校准后 |
**`buy_min_effective` / `sell_min_effective`** | v475 可信度收紧后（真正生效的那个） |
`confidence_penalty` | 收紧量本身 |
`action_before_confidence_gate` | **闸门前的动作** —— 有它才能证明"这次 HOLD 是被可信度拦下的，还是本来就不够" |
`confidence_gate` | conf / penalty / changed_action（penalty=0 时为 None） |

## 五、验证

`tests/test_confidence_gate_v475.py` 5 条：
penalty 的单调性与封顶；低可信度确实抬高 buy/sell 双向门槛；**公司票权重现在也被打折**（0.0621 = 0.08×(0.6+0.4×0.44)）；
**无可信度时逐位不变**（effective == calibrated、gate 为 None、权重 0.08）；alt 侧原行为未被重构改掉。

全量回归 **301 passed, 1 warning**。

## 六、实现中的一个真错误（如实记录）

第一版把 `_f_w`（打折后的权重）的计算放在了 `_fund_info` 字典构造**之后**，结果 `weight_effective` 读到一个未赋值的局部变量，`UnboundLocalError`，5 条测试里 4 条当场红。
修正方式是把权重计算上移到 `_is_alt` 判定之后、所有使用之前。

## 七、现在的完整链路

```
数据 → 分量 → 分数 → 分歧度/可信度
                        ├─ 权重打折（0.6~1.0×，v472/v475 两侧通用）
                        ├─ 仓位乘数打折（0.75~1.0×，v473）
                        └─ 开仓门槛收紧（+0~0.10，v475）   ← 本轮新增
                                  ↓
                              落库审计
```

**基本面这条线，从"有读数"到"读数能改变开不开仓"，至此走完。**
