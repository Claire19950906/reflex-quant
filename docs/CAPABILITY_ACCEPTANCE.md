## 1. 定位

与 `gub_capability_audit.py` **互补, 不是替代**:

| 脚本 | 验什么 | 现状 |
|---|---|---|
| `gub_capability_audit.py` | 验「**有没有**」— 端点 200 + 返回非空 | 15 项 12 PASS / 3 WARN, 但断链项照样 PASS |
| `capability_acceptance.py` | 验「**对不对**」— 硬阈值 + 数据契约 + 调度存在性 | 断链项判 FAIL |

本脚本共 **26 项**:

- **能力项 1–15 + 4B** — 与 gub #1..#15 对应 (信号评估 / 权重 / 共识 / 心理反应 / 因果 / 事件K线 / 三维反思 / 归因 / 实时交易台 …); `4B` 是 v310 P1 从原 4 拆出的「心理预期与市场反应」子项
- **数据契约 C1–C8、C10** — 共享表、调度覆盖、结算率、事件积压、cron 完成率、端点↔库自洽、回填就绪度、枚举残留、worker 注册
- **只读断言 C9** — 校验本脚本自己没改库 (写探针被 SQLite 拒绝 + authorizer 全程拦截写尝试)

### 铁律

- **只读**: SQLite 一律 `file:...?mode=ro` 打开, HTTP 只发 GET, 绝不写库
- 不碰生产 DB (`backend/trident_event_bus.db` 及 `.bak`)
- 纯巡检脚本, 运行时模块不会 import 它 (不会被 launchd / uvicorn 加载)

## 2. 用法

```bash
cd backend/src_python
python3 capability_acceptance.py                # 人读表格
python3 capability_acceptance.py --json         # 机读 JSON
python3 capability_acceptance.py --only 6,7,C3  # 只跑指定项
python3 capability_acceptance.py --no-http      # 离线, 只查 DB
python3 capability_acceptance.py --strict       # WARN 也算失败
```

退出码: `0` = 无 FAIL · `1` = 有 FAIL (`--strict` 下 WARN/⏳ 也算) · `2` = 用法/环境错误

状态口径 (2026-11-20 起):
- ✅ PASS — 硬判据全达标
- ❌ FAIL — 逻辑/口径/接线坏了，**只有这一类需要改代码**
- ⏳ INSUFFICIENT — 链路在跑、口径能算，但样本没到判定门槛；附 `need / have / watch`（等什么、现在多少、数据到了看哪个数）
- ⚠️ WARN — PASS 但样本不足以让结论稳健
- ⏭️ SKIP — 前置条件不具备

所有阈值集中在 `THRESHOLDS` 字典 — **改验收口径只改这一处**, 不散落在各 check 里。
每条 check 都回答三件事: `criteria` (硬标准) / `measured` (实测) / `fix` (该动哪个文件)。

## 4. v310 P1 口径修正 (本轮)

旧口径会把**没成交的决策**、**结算后回填的权重**、**恒等乘子**都算成"能力已实现"。
本轮修了 3 处, 修完 3 个假绿灯变成 FAIL/WARN:

### 4.1 能力 1 — 准确率的分母必须是**真实成交**

旧判据 `COUNT(status='settled')` 把 `decision_type='REJECT'` (闸门拦截, 从未成交) 也算进
"可结算样本": **1974 条拒绝记录**把分母从 25 撑到 2006。一条没成交的决策证明不了任何
"交易信号准确率"。现在 ENTRY / REJECT 分开统计:

| 指标 | 值 | 说明 |
|---|---|---|
| 真实开仓命中 | **20/32 = 62.5%** (95% 下界 45.3%) | 分母 = 25 条 ENTRY + 7 条 quick_sim |
| 闸门拒对率 | 1945/1974 = **98.5%** | 拒绝后市场与原方向相反 |
| 同向基础概率 | **98.5%** | 该方向信号事后反向的基础概率 |
| **闸门增量识别力** | **+0.05pp** | 拒对率 ≈ 基础概率 → 闸门只是碰上了行情 |
| 全样本方向命中 | **45/1999 = 2.3%** | 全部结算信号的方向准确率 |

### 4.2 能力 2 — 权重必须是**决策时点**的权重, 且要有标定力

- `signal_weight_history` 16,609 行里 **12,757 行是事后回填** (`backfill_trade` / `cron_react`),
  其中 trade 空间 2,007 行**全部**是 `backfill_trade` (1999/2007 的 `computed_at` 晚于结算时间)。
- 拿结算后回填的权重跟结果求相关 = **循环论证**。
- 代码级证据: `evaluate_and_persist_trade()` 的**唯一调用方**是离线脚本
  `backfill_trade_decision_weights.py`; 实时链路 `decision_engine.py` 里**没有 signal_weight**。
- 现在只认 `trigger_kind='insert'` 的事前权重: 与可判定真值配对**仅 5 条**, ρ=+0.447 (n=5, 无统计意义)。

### 4.3 能力 4 / 4B — 共识与心理**分开判**, 且必须有可核验输入

旧判据 `mult_active = max(consensus_variants, reaction_variants) >= 2` —— **两者取或**,
一个在动就整体放行。现拆成两个独立子项:

| 子项 | 判据 | 实测 | 结论 |
|---|---|---|---|
| 4 共识 | 乘子取值 ≥2 且 多模型共识填充率 ≥10% | 共识乘子**恒 1.0**; `extra_models_consensus` **0/4380** | FAIL |
| 4B 心理/反应 | 反应乘子取值 ≥2 且 同行评审 ≥10% 且 有证据的 belief ≥10 | 反应乘子 3 个取值; 同行评审 **53/4380 (1.2%)**; belief **0/14 有证据** | FAIL |

> 注意: 反应乘子**本身在动** (1.0 / 0.9 / 0.7, 只覆盖 2.8% 的行), 4B 失败点在
> 同行评审与 belief 证据链为空 —— 心理维度没有可核验的输入。

### 4.4 能力 10 — 因果图谱真命中率仍未达标, 但闭环已接通

已评估 257 (HIT 123 / 弱命中 50 / MISS 84) → 真命中率 **0.4786** (< 0.50), 方向命中率 0.6732。

**v310 P1 已把权重回写闭环接通** (原状态: `causal_weight_feedback.py` 无调度注册, 且
`MIN_SAMPLES=8` 高于每链最多 2 个已结算样本 → 189 条链**全部**跳过, 模块是纯 no-op):

| 修的问题 | 改法 |
|---|---|
| 样本阈值不可达 | `MIN_SAMPLES=8` → `MIN_CHAIN_SAMPLES=2` + **分层先验** (族 → asset → 全局) |
| credit 公式错 | `HIT_WEAK` 从计 1.5 改为计 **0.5** (全局先验 0.770 → **0.576**) |
| 权重语义冲突 | weight 在下游是 **stated confidence** (夹到 [0,1]) → 改写 `posterior`, 区间 `[0.10, 1.00]` |
| 无调度 | 新增 `com.trident.causal-weight-feedback-cron` (每小时) + wrapper + 审计日志 |

首轮回写: **68 条链**按证据更新 (0.4491 / 0.5991 / 0.6491 / 0.6949 / 0.7949),
121 条 (n=1) 样本不足不动; 第二轮 **0 改动** (幂等收敛)。

### 4.5 三个退化族 —— 是系统性问题, 不是链质量

按 (asset, expected_direction) 分族后, 命中率出现极端分化:

| 族 | 样本 | 命中率 |
|---|---|---|
| XAU\|UP | 54 | **0.0** |
| XAU\|DOWN | 39 | **0.974** |
| ETH\|BOTH | 22 | **1.0** |

UP 全错 / DOWN 全对这种互补形态, 更像**方向标注或评估口径的系统性问题**, 而不是链本身好坏。
因此实现里对命中率落在 **[5%, 95%] 之外**的族**不做族先验**, 回退到 asset 级 / 全局先验,
并单独上报 `degenerate_families` —— 避免把一个 bug 放大进权重系统。

**这 3 个族需要单独排查** (方向标注 `expected_direction` 的推导 / `actual_pct_5d` 的取值口径),
修好之后族先验才能真正起作用。
