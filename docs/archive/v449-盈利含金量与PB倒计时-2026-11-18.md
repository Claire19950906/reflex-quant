# v449 · 盈利含金量 + PB 倒计时（2026-11-18）

> 这版只做两件小事，都围绕同一句话：**别让"看起来对"的数字替数据说话**。
> 一是给盈利加一把现金流尺子（防应计利润撑起来的高增长），
> 二是把 PB 的"不可用"变成看得见的天数倒计时（不补历史，从今天起攒）。

## 一、盈利含金量（OCF / 净利）

### 为什么加

EPS 与净利都是会计口径：应收、存货、资本化利息都能把利润做漂亮，而现金没进来。
现有 `earnings_revision` 由 EPS 同比（0.65）+ 预期差（0.25）+ 一致预期抬升（0.10）拼成，
**三项全是利润表口径**，没有一项看现金。财报质量的经典红旗就是"净利涨、经营现金流不涨"。

### 规则（只判"差"，不奖励"好"）

```
TTM OCF / TTM 净利（近四季求和）
  ratio < 0.60  → 盈利修正 ×0.5，标 low_cash_quality
  ratio ≥ 0.60  → 不动（不额外加分，否则同一份"盈利不错"的证据被用两遍）
```

三个失真守卫，任一命中就不判：

| 守卫 | 理由 |
|---|---|
| 近四季 OCF 任一季缺失 | 不拿三期拼"TTM"（COIN 就是这一类：8 季净利齐、OCF 全缺） |
| TTM 净利 ≤ 0 | 亏损股已走 `loss_maker_readout`，不重复 |
| TTM 净利 < 1% 营收 | 分母趋零：0.1 亿净利配 10 亿现金流会算出 100 倍 |
| ratio > 3.0 | 多为一次性营运资本释放（预收款/延付），不代表持续含金量 |

只折一次：与周期折半（`peak_earnings`）可以叠加，但各自只作用一次 ——
强周期峰值 + 含金量差时，盈利修正最多被折到 1/4，不会出现"折上折"到 0 的情况。

### 实测（10 只覆盖票）

| 票 | TTM OCF/NI | 判定 |
|---|---|---|
| NVDA | 0.70 | 合格（不折） |
| GOOGL | 0.76 | 合格 |
| MU | 1.06 | 合格 |
| AAPL | 1.10 | 合格 |
| AMZN | 1.25 | 合格 |
| COIN / MSTR / CLSK / RIOT / MARA | 不可得 | OCF 缺失或净利 ≤0 → 不判 |

**诚实结论：这一版在当前 10 只票上不改变任何分数。** 它是护栏，不是当下的 alpha 来源。
之所以还是上线：新票进来（尤其美股中小盘、加密矿企转盈利阶段）时，
"利润转正但现金流没跟上"是最常见的坑，等踩到再补就晚了。

## 二、PB 倒计时（不补历史）

### 之前为什么是 0/10

不是公式错，是**天数不够**：

- `eq.pb` 快照库里只有 **3 天**（2026-11-16 → 11-18），按日去重后 n=3；门槛 60 天 → 静默；
- 倒推路径（市值 ÷ 净资产）里，NVDA/COIN/RIOT 缺净资产、MU/CLSK 市值全 NULL、MSTR 市值恒定。

按「**数据采集中断后恢复，以恢复时刻为新起点，不处理停机期堆积的历史数据**」的口径，
这一版**不做历史回补、不用价格×股本倒推往年 PB**，只保证：
每天照常落 `eq.pb` 快照，攒满 60 个**不同日期**才允许出分位。

### 把缺口变成倒计时

`python3 scripts/cron_equity_fundamentals.py --coverage` 新增一行：

```
[PB 倒计时] 按日样本（门槛 60 天）: AAPL:2天, AMZN:2天, CLSK:0天, COIN:3天,
            GOOGL:2天, MARA:0天, MSTR:0天, MU:0天, NVDA:3天, RIOT:3天
```

- 口径：`max(市值÷净资产 的按日点数, eq.pb 快照的按日点数)`；
- 修了一个"看起来更糟"的假读数：原先把已关闭的连接复用，异常被吞成 0 天，
  现在单开只读连接，数对了（2~3 天而不是全 0）；
- 按 60 个交易日估，**约 2027 年 2 月中旬**陆续越过门槛；在那之前 PB 一律不参与估值分。

## 四、边界

1. **含金量只有一个季度粒度**：TTM 求和，看不出单季恶化；
2. **金融股/加密矿企的 OCF 口径差异大**：矿企的 OCF 含算力资产处置，别跨行业横比；
3. **PB 仍需 60 个交易日**，且依赖 `eq.pb` 快照每天不断；断一天只是少一天，不补；
4. 权重 0.08 依然没有结论 —— 影子账本还在攒样本（门槛 30 笔）。
