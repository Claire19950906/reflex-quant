## 二、五处改动与口径

### 2.1 净资产通道：SEC companyfacts（免配额、季频、带申报日）

新增 `src_python/sec_fundamentals.py`。

```
端点   https://data.sec.gov/api/xbrl/companyconcept/CIK{cik:010d}/us-gaap/{tag}.json
UA     必须带联系人（reflex-quant research z2132743607@163.com）
取值   StockholdersEquity → 缺失时 StockholdersEquityIncludingPortionAttributableToNoncontrollingInterest
       → 再缺则 Assets − Liabilities（标 derived）
去重   同一 period_end 多条按 `filed` 取最新（重述以最新申报为准）
缓存   company_tickers.json 7 天 / 每个 concept 1 天
```

关键点：**每个数都带 `filed`（申报日）**。v448 把「季末」当已知日是错的 ——
季末之后、申报之前，市场还不知道这份报表，用它算历史 PB 就是前视（最多提前 6 周）。
`equity_known_date()` 一律取 `max(period_end, filed)`。

首跑：`inserted=78 / updated=28 / skipped=86`，16 只全部有净资产（AAPL 20 期、MU 20 期、NVDA 26 期）。

### 2.2 市值通道：已公布股本 × 已公布收盘（推导，不回填采集）

新增 `src_python/equity_mktcap.py`，表 `equity_mktcap_daily(ticker, day, shares, close, mktcap_usd, source)`。

```
历史股本   yfinance get_shares_full(start=...)   （AAPL 27 点 / MU 51 点 / COIN 32 点 / MARA 23 点）
收盘       优先本库 ohlcv_daily；不足 60 点才向 yfinance 要历史
前向填充   取「≤ 该日」的最后一个股本点 —— 绝不用当前股本回填历史
缺历史     只给「今天」一个点，标 shares_current×close
```

MARA 一年从 3.704 亿股增发到 3.874 亿股 —— 这就是「不该拿当前股本回填历史」的实证。

> **和「不补采集积压」的边界**：用户定的是**采集中断后以恢复时刻为新起点，不补停机期堆积的数据**。
> 这里不是重放采集，是**两个已公布真实数相乘**（口径与 PE「收盘÷已公布 EPS TTM」同源），
> 行内 `source` 一律写 `derived`，可被审计区分。

首跑：`{'tickers': 16, 'rows': 4610, 'no_shares': 0, 'no_close': 0}`，每票 251~263 个交易日。

### 2.4 同业可比（新增 `peer_valuation.py`）

```
分组      semis(8) / mega_tech(5) / crypto_miner(6) / crypto_asset(3) / ai_growth(4)
倍数      本系统快照 eq.pe / eq.pb 优先 → yfinance trailingPE / priceToBook（缓存 6h）
相对分    rel = 自身中位数比 - 1；得分 = -(rel)/0.5，截 ±1（便宜为正）
拒绝结论  组内有效样本 <2（不含自己）→ available=False
热路径    build(allow_network=False) 只读库+缓存；网络补数在 cron `--peer-warm`
```

因子接线：自身分位存在时 `估值 = 0.7×自身 + 0.3×同业`；自身缺失时 `0.85×同业`。
理由：同业是**横截面锚**（同一时点、同一生意），历史分位是**时间锚**（同一家公司、不同估值环境），
两者互补但不能互相替代，所以给同业 0.3 而不是 0.5。

实测：NVDA `semis 同业 7 只可比 → -0.4147`（PE 高于同业中位）、MU `+1.0`（低于同业）、
AAPL `mega_tech 4 只 → -1.0`、COIN `crypto_asset 2 只 → +0.7359`、MSTR `+1.0`、AMZN `+0.4706`。

### 2.5 宏观 → 板块倾斜（新增 `macro_equity_regime.py`）

33 组 FRED 压成 4 个无量纲驱动，再乘板块敏感度：

```
R（利率压力）  = Δ10Y(20 交易日) / 0.30pp，截 ±1
K（风险偏好）  = (18 - VIX)/8 与 高收益 OAS 反向变动 合成
D（美元压力）  = DXY 20 日变动% / 2%
C（曲线）      = -(10Y-2Y)/0.5（倒挂越深越负）
tilt = -wR·R + wK·K - wD·D - wC·C，截 ±1
```

接线：`score = clamp(score + 0.15 × tilt)`，并把 `macro_tilt / macro_sector / evidence` 写进 components。
上限 0.15 是硬约束：宏观 33 组本身滞后、且不该盖过公司自身读数（fundamental 权重才 0.08）。

实测（2026-11-18）：`rate +0.433 / risk -0.507 / usd +0.361 / curve -0.600` →
`semis -0.293 / ai_growth -0.345 / mega_tech -0.327 / crypto_miner -0.433 / crypto_asset -0.429`。
即当时（10Y +0.13pp、VIX 22.9、HY OAS +0.16pp、DXY +1.1%）对久期与高 beta 一律压分。

## 五、诚实边界（这一版没解决的）

1. **权重 0.08 仍是先验**。影子账本 0 笔适用样本 → 只能 `insufficient`。v454 做的是"让它能被验证"，
   不是"证明它有用"。
2. **同业分组是人工写死的**（5 组 26 票）。新增票不进组 = 没有同业锚，宁可 `available=False`
   也不猜同行。
3. **宏观倾斜上限 0.15** 是保守设定：33 组 FRED 的滞后性没解决，只是从"背景板"变成"可复现的偏移"。
   传导系数（`SECTOR_SENSITIVITY`）同样是先验，尚未回测校准。
4. **MSTR 这类财库票**：净资产含 BTC 公允价值，PB 0.58 不代表便宜，当前仍参与打分 —— 需要产品决策，
   建议后续按 `treasury_vehicle` 标记屏蔽 PB。
5. **A股/港股基本面未动**：仍是 8 条读数的空壳（`--cn-auto` 只做反解+抓取），本版没碰。
6. **`_PRIMARY_HORIZON` 3 天 → 10 天是口径变更**：季报级变量的信息衰减以周计，3 天窗口测的是噪声。
   这条改动会让"账本满 30 笔"的等待时间从约 1 个月拉长到约 2 个月。
