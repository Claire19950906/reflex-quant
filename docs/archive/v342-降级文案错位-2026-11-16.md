# v342 · 降级文案跟着品种走（2026-11-16）

## 一、实测到的矛盾

只读核对主库（`trident_event_bus.db`）：

| 项 | 数 |
|---|---|
| `ai_decisions` 总数 | 272 |
| 其中 HOLD | ≈100%（BUY 仅 2） |
| `sentiment_score = 0` | 231 / 259（89%） |
| `market_confirmation = unknown` | 258 / 259 |
| **核心品种文案错位** | **93 / 168（55.4%）**<br>XAU 43 · WTI 40 · BTC 10 |

所谓「文案错位」：品种是 XAU/WTI/BTC，记录里却写着

> 目标资产 NONE…**该标的\\*\\*不在\\*\\*核心监控清单（BTC/XAU/WTI/ETH/SOL），按非交易信号处理**

一句话：**它在声称自己不该被分析，而它分析的正是核心品种。**

## 二、根因（不是判定 bug，是文案没跟着走）

1. LLM 返回空/被截断 → 走降级兜底 `degraded_reasoning_template`
2. 此刻 `target_asset` 还是 `NONE` → 文案按「品种不在核心范围」写（当时是对的）
3. `ASSETFIX`（NONE → 副品种提升）或 `MAINFIX`（八段实际讲的是另一个品种）改了
   `target_asset`，**但没重写文案**
4. 落库：品种是 XAU，文案是 NONE

后果不是分数错，是**归因错**：反思会据此把「LLM 空输出」学成「品种不在监控范围」，
E 码归因连带失真——这也是"89% 情感分为 0"看起来像"模型判断无方向"的真实原因之一。

## 三、修复（只改文案与归因，不碰判定）

新增 `rerender_degrade_text_for_asset(result, asset)`：

- 触发条件：`reasoning_path` 里带 `目标资产 NONE` 或 `**不在**核心监控清单`
- 品种在核心清单 → 重写为「该品种在核心监控清单内，本次按**分析降级**记录（LLM 空输出/截断）」
- 品种确实不在清单（如 NVDA）→ 明说「确实不在核心监控清单」，不伪装
- **不动** `suggested_action` / `sentiment_score`（有专门用例锁死）

接线两处：`ASSETFIX` 提升后、`MAINFIX` 纠正后。

### 一个坑（记下来）

检测串不能写「不在核心监控清单」——原文中间隔着 markdown 的 `**`，
连写串永远匹配不上。正确检测串是 `**不在**核心监控清单`。

## 五、历史存量怎么办（需要你拍板）

历史 93 条**没有**自动回填——改历史文本等于改证据。两条路：

| 方案 | 说明 |
|---|---|
| ① 只读忽略 | 反思已按 `reasoning_path` 里的「分析降级」区分，不追历史 |
| ② 回填重写 | 用 `rerender_degrade_text_for_asset` 批量重写这几行的文案（不动判定），可先导出 93 行清单给你过一遍 |

`scripts/audit_asset_scope_text.py` 只读，随时可复查。

## 六、还没解决的（下一层）

文案修正只是把「归因污染」止住了。**89% 情感分为 0** 的真实上游是
LLM 空输出/截断 —— 这才是采样不出方向的主因。下一步应该查：

1. 空输出的占比到底多少（开 `TRIDENT_DUMP_RAW=1` 留原始返回，`/tmp/trident_raw` 最多 20 份）
2. 是不是 `<think>` 未闭合被剥掉、或 token 上限截断
3. `market_confirmation` 全 unknown 的兜底是否应从"注入 0.10 权重"改成"不参与"
