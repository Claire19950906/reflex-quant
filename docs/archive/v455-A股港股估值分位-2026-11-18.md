# v455 · A股/港股：把「只有增速一把尺」补成「增速 + 估值分位」（2026-11-18）

> 一句话：A股/港股的财报读数早就能读（v406 接的东财），但**估值分量一直恒为 None** ——
> 每票只有 1~7 个快照点，60 天门槛永远到不了。后果不是"分数偏低"，是"分数失真"：
> 东山精密 / 新易盛这类高增长票直接打满 **1.0**，因为没人拦它们贵不贵。

## 二、做法：两个已公布的真数相除（与美股 v454 同构）

```
PE(日) = 当日收盘 ÷ 该日之前**已公布**的 EPS_TTM
PB(日) = 当日收盘 ÷ 该日之前**已公布**的 BPS
```

- **收盘**：腾讯 K 线（`cn_prices.fetch_stock_history`，前复权）。实测 `sh600519` / `sz002384` /
  `hk00700` 各返 **320+ 根日线**。
- **财报**：东财 `RPT_LICO_FN_CPD`（A股）/ `RPT_HKF10_FN_MAININDICATOR`（港股），每票 **16 期**（4 年）。
- **TTM 还原**：A股是累计口径，逐期走「本期累计 + 上年年报 − 上年同期累计」（`ttm_at` 切片复用 `_a_ttm`，
  不为历史期另写一套逻辑）；港股东财直接给 `EPS_TTM`。
- **防前视**：A股没有逐条申报日，所以用**法定披露截止日**当已知日 ——
  一季报 4/30、半年报 8/31、三季报 10/31、年报次年 4/30。
  这是**保守**方向：真实公告只会更早，因此不会前视；反过来拿季末当已知日就等于提前 1~4 个月知道业绩。
- **落库**：写 `cn_valuation_snapshots`（`source='derived'`），幂等 upsert；
  同日已有东财原始快照则**不覆盖**（采到的优先于推出来的）。

## 六、诚实边界

1. **只有自身历史分位，没有同业**。A股行业字段（`industry`）是有的，但库里 8 只跨 8 个行业，
   组内样本不足 → 按"样本<2 不给结论"的铁律，**不做** A股同业对比。
   等票池到 20~30 只同行业再谈，先不造数。
2. **前复权价 vs BPS**：分红/拆分会让"价格 ÷ BPS"的绝对水平有偏差（分位的相对位置影响小）。
   港股 BPS 来自东财 `BPS` 字段，口径以供应商为准。
3. **法定截止日 = 滞后**，不是精确申报日。宁可晚 0~30 天用，也不提前 1 天。
4. **NONE 类决策补不了**：13/20 的 CN/HK 决策根本没点名个股（指数、日历、失业率），
   这不是基本面缺口，是新闻层的标的缺失 —— 只能靠上下游（新闻层给具体标的）解决。
5. A股/港股仍然**没有**财报日历（`earnings_in_days=None`）、没有三表、没有同业、没有宏观传导。
   这一版只补了"估值分位"这一块。

- 清掉推导点：`DELETE FROM cn_valuation_snapshots WHERE source='derived';`
  （东财原始快照不动，删完回到"每票 1~7 点、估值分位不可用"的原状）
