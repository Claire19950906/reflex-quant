01为什么"清了好几次都清不干净"

清空本身是一次性的；难的是让清空**守得住**。

第一件事：真的一次清空了。73 张表、455,954 行判断/评分/账本归零， 原始事实全部保留 —— 新闻 16,335 条、事件 31,949 条、盘口 tick 878,142 条、 K 线 297,032 条、739 条因果链定义。weights 从 101 个不同值统一重置为 1.0。 备份 reset_20261115_0910.db（1,426 MB，integrity ok）。

第二件事：清空 4 小时后，脏数据自己长回来了。

根因不是"没清干净"，而是闸门一直没生效。 闸门里写的是 datetime.strptime(...)，而该文件顶部是 import datetime（模块没有这个方法）→ 抛 AttributeError → 被 except Exception: return 0 吞掉 → 纪元永远读成 0 → if _ep and ... 直接短路 → 闸门形同不存在。这个坑一天内踩了三次，最后一次是我自己的批量替换叠成了 datetime.datetime.datetime.strptime。

第三件事：把闸门收敛成一处，并且能被测出来。

改法说明
epoch_gate.py只有它解析 data_epoch；用 time.strptime + mktime，不依赖 datetime 的导入风格
读不到返回 None不是 0 —— "读不到"和"没有纪元"必须区分，这正是上次翻车的点
is_pre_epoch / clamp_since统一"留 1 天余量"口径：日频信号锚在当天 00:00，比纪元早几小时，属正常
五处闸门全部改调它异动 / 波段 / 归因 cutoff / 慢涨回填 / 快涨检测
12 条回归测试含端到端"写入口拿纪元前 ts 必须一行都写不进"和全库静态扫描
