> 账本只做**标记、敞口、对账**三件事，不下单、不写库、不补重置前的历史。

## 2. 口径（全部可复核）

| 项 | 做法 | 为什么 |
|---|---|---|
| 账户 | `t2_account` 最新一行（cash / equity / realized_pnl / fee_bps） | 只认账本，不另设“假设余额” |
| 权益 | `cash + Σ 持仓浮盈亏`，与 `equity` 并列显示差额 | 表里的 equity 可能是上次快照，不能当实时 |
| 标记价 | `market_ticks` 最新 tick → 1m 收盘 → 5m 收盘 | XAU 5m 可能为空，不能因此不估值；也不能编价 |
| 没有行情 | `mark=null`，浮盈亏/敞口按入场价估算并明确标注 | 没有价就不假装有价 |
| 方向 | short/sell = -1，long/buy = +1 | 空头浮盈方向不能反 |
| 敞口 | 总名义 Σqty×mark；净名义再乘方向；**同品种多笔合并**后再算集中度 | 两笔 ETH 各 5000，不能当“两个 50%”，实际是 100% 一个押注 |
| 手续费 | 只把 `currency in (USDT, USD)` 且 category 含 fee/commission 的行算手续费；`TOKEN` 行单独统计；没有手续费行时按 `fee_bps × 成交名义` 估“应记” | `t2_cost_ledger` 同时记交易费用和 LLM Token，混在一起会把 271 万 Token 当成 271 万 USDT |
| 已平仓 | 只统计 `status=closed` 的 `realized_pnl` | 重置前数据不回溯 |
| 新鲜度 | 行情 >300s 标“旧”；账户 >3600s 标“久未更新” | 旧价可以看，但不能当现价 |

---

## 4. 为什么不做“实盘账本”

`t2_account.mode='paper'`，成交备注是 `trade_executor/mock`，没有真实券商回报。
在真实成交接入之前，把模拟单包装成“实盘账本”就是假数据。
所以本批只做**模拟盘对账**；等真实成交回报接进来，同一套口径可以直接换成
`fills / commissions / realized_pnl`，不用重做页面。

---

## 5. 边界

- 当前只有 1 笔持仓、0 笔已平仓，**任何胜率/盈亏比都没有统计意义**；
- 手续费目前只“估应记”，没有补记接口——补记要写库，留待用户明确授权；
- `t2_cost_ledger` 的 TOKEN 行不是钱，页面只单独显示 Token 行数/数量，不并进 USDT 成本；
- 重置前的成交与持仓不回溯，账本从当前快照往后算（与“恢复时刻为新起点”的口径一致）；
- 标记价随请求刷新，页面数字会变，属正常。
