# 背离引擎（divergence_engine.py）

2026-11-16 · 技术指标能力扩展。目标是把「顶背离 / 底背离」做成可解释、可回测、不重绘的一等能力，接进 Trident 的接口与界面。

## 1. 识别口径

- **Pivot**：左右各 3 根确认的高点 / 低点（右侧 3 根收盘后才成立），因此信号会滞后 3 根，但不重绘。
- **腿（legs）**：RSI(14)、MACD 柱、OBV、MFI(14)、CCI(20)、Stoch %K，共 6 条；每条腿有独立阈值和权重。
- **常规背离**：价格创新高/新低，指标不创新高/新低（顶/底反转含义）。
- **隐藏背离**：价格未创新高/新低，指标创新高/新低（趋势延续含义）。
- 至少 2 条腿同向才成立；A 级要求评分 ≥78 且 ≥3 条腿一致。

## 2. 评分

`score = 100 × (0.30·腿一致度 + 0.30·摆动幅度 + 0.20·量能 + 0.20·ADX)`

再做趋势位置校正（±5 分）：

- 常规顶背离出现在均线上方（上升趋势末端）加分，底背离出现在均线下方加分；
- 隐藏背离顺势成立加分，逆势减分。

评分衡量的是**形态强度**，不是胜率。胜率由第 3 节的历史校准单独给出。

## 3. 历史校准（按趋势上下文）

`evaluate()` 除了按等级、方向统计外，还按 `kind/type/trend` 分组，例如：

- `regular/bearish/up`：上升趋势里的常规顶背离
- `regular/bullish/down`：下降趋势里的常规底背离
- `hidden/bullish/up`：上升趋势里的隐藏底背离（顺势）

每组给出样本数、命中率（确认后 N 根收盘方向一致）、平均方向调整盈亏。这样界面可以直接回答「这类信号在这个品种上到底准不准」，而不是给一个笼统的分数。

实测（2026-11-16，日线，12 个标的，持有 10 根，确认收盘入场）：

- 评分 80+ 的一组合命率约 62.5%，低分组 44–59%，说明评分有区分度；
- 但**逆势顶背离（价格在均线下方）与逆势隐藏背离是负期望**，这类信号应作为「减仓/观察」而不是直接反手；
- 上升趋势中的底背离、顺势隐藏底背离是正期望的主要来源。

结论：引擎不承诺「顶背离一定反转」。它把形态、趋势位置、历史胜率同时摆出来，由使用者决定是否执行。

## 4. API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/divergence/assets?interval=1d` | 有足够 K 线的标的 |
| GET | `/api/divergence/scan?asset=BTC&interval=1d&within=120&min_grade=C` | 当前信号 + 状态 + 交易计划 |
| GET | `/api/divergence/bars?asset=BTC&interval=1d&limit=420` | 图表 K 线 + pivot 标注 |
| GET | `/api/divergence/stats?asset=BTC&interval=1d&horizon=10` | 按等级 / 上下文的历史校准 |
| GET | `/api/divergence/confluence?asset=BTC` | 15m/1h/4h/日线 跨周期共振 |

所有接口只读 `ohlcv_daily` / `ohlcv_intraday`，不写库、不接下单链路。扫描结果有 45 秒内存缓存。

## 5. 前端

`frontend/app/divergence/page.tsx`，主导航「背离雷达」。包含：

- 蜡烛图 + A/B pivot 标注 + 入场/失效/目标三条计划线；
- 信号列表（等级、方向、腿数、盈亏比、状态）；
- 多腿证据条（A 点 → B 点）；
- 历史校准表（按等级、按趋势上下文），样本 <20 明确标注不作结论；
- 跨周期共振条。

## 6. 已知边界

- 只覆盖有 OHLCV 的品种；股票多数没有 4h/1h 数据，共振会退化为日线单周期。
- pivot 确认滞后 3 根，适合波段/日内，不适合抢第一根反转。
- 历史校准基于过去数据，趋势 regime 改变后会漂移；界面上按品种展示，不做跨品种平均。
- 目前不接自动下单。若要接，建议只用 `grade=A` 且 `context` 历史样本 ≥20、命中率显著高于基准的信号，并且先走模拟盘。

## 7. 样本外验证与本地台账（2026-11-16 追加）

### 7.1 为什么要做

样本内统计只能说明“历史上长什么样”，不能证明“下一段还有效”。所以把验证拆成两段：

- **观察段（前 70%）**：只用来形成规则假设；
- **检验段（后 30%）**：单独结算，不参与任何参数选择；
- **扣往返 8bp**（手续费 + 滑点），入场用确认当根收盘，出场用第 N 根收盘。

### 7.2 实测结论（27 个日线标的，持有 20 根）

| 范围 | 样本外 n | 命中率 | 扣费后每笔 | 结论 |
| --- | --- | --- | --- | --- |
| 全部背离信号 | 616 | 45.9% | -0.79% | 未通过 |
| 顺势隐藏底背离（上升趋势 + ADX≥20） | 125 | 60.8% | +1.55% | 有效 |

全样本基准上涨概率 57.3%。也就是说：**不是所有背离都有效，只有一类被样本外证实**。其他场景继续展示，但不进入“可执行”。

### 7.3 台账

`divergence_ledger` 表：每条信号确认后入库（`signal_key` 去重），按各自 horizon 到期结算，记录：

- 入场价、出场价、方向调整收益、是否命中；
- 持有期内 MFE / MAE（最大有利 / 不利变动）；
- 是否触及失效价 / 目标价；
- `executable`：是否命中有效规则（当前只有 `hidden_bull_up_adx20`）。

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/divergence/validation?horizon=20` | 观察段 vs 检验段，按上下文 / 等级 / 规则 |
| GET | `/api/divergence/ledger?status=all` | 台账列表 + 汇总；10 分钟内自动同步一次 |
| POST | `/api/divergence/ledger/sync` | 手动同步 + 结算 |
| GET | `/api/divergence/effective` | 当前命中有效规则的信号（跨标的） |

界面：`/divergence` 的「样本外验证」「信号台账」两个页签；实时信号台首页顶部新增「有效背离信号」条，只列有效规则的命中项。

### 7.4 边界

- 有效规则目前只在日线、20 根持有期上通过检验；4h/1h 尚未通过。
- 60.8% 是方向命中率，不是胜率保证；单笔最大不利仍可能达到 -7% 级别，必须配失效价。
- 规则会随市场结构漂移，每月应重跑一次 `/api/divergence/validation`，若检验段连续两次转负就下线该规则。
