## 二、五处改动与口径

### 2.1 洞 1：周期判型（PE 陷阱）

`src_python/fundamental_factor.py`

```
TTM 序列    = equity_earnings_events 的 eps_actual 滚动 4 季求和，同日去重，取近 8 点（回看 1200 天）
盈利位置 pos = (TTM_now − min) / (max − min)
周期度 cyc   = (第 2 大 − 第 2 小) / |序列中位数|
判型：cyc ≥ 1.5 → strong_cyclical；cyc < 1.5 → steady（需 ≥8 点，否则 profile=None 不判）
修正：强周期 且 pos ≥ 0.80 → 估值 ×0.5 + 盈利修正 ×0.5，标 peak_earnings
      强周期 且 pos ≤ 0.20 → 同上，标 trough_earnings
      平稳                  → 不动
```

两个必须写清的口径决定：

- **为什么盈利修正也折半**：峰值 EPS 的同比本身就是周期放大（MU 同比 +808%），
  只折估值会让"盈利在上行"这一项继续满权重往上推，等于同一份周期证据被用了两遍。
  折扣是**各折一次**（估值 0.5、修正 0.5），不是对总分折两次。
- **为什么 NVDA 不降**：按上表规则 NVDA cyc 0.75 < 1.5 → 平稳，只标 position 100%、不折半。
  v445 §五 验收表要求「NVDA/MU 都 ≤0.55」，与 §四 规则自相矛盾 —— 以规则为准，
  该表已就地修正（见 `docs/v445-...md` §五）。

### 2.2 洞 2：亏损股专用口径

`loss_maker_readout()`，只在 TTM EPS 或净利 ≤0 时启用：

| 读数 | 权重 | 含义 |
|---|---|---|
| 营收同比 | 0.40 | 生意还在不在长 |
| 毛利率趋势 | 0.20 | 规模效应有没有出现 |
| 经营现金流率 | 0.25 | 亏损是账面还是真失血 |
| 经营现金流趋势 | 0.15 | 失血在收窄还是扩大 |

- 三表不足 8 季（MARA 这类只有事件、没有报表）→ **单因子封顶 ±0.6** 并标 `loss_eps_only`，
  不再回到 −1.0 饱和；
- PB 可得时按 0.7（口径分）/ 0.3（PB 分）叠加；当前 PB 不可得（见 2.3），实际是纯口径分。

### 2.3 洞 3：PB 倒推（做了，但**数据侧仍不可用**）

`equity_fundamentals.pb_history()`：

```
每日去重 eq.mktcap 快照 → 市值 ×1e9（单位是十亿美元，见 feeds/equity_feed._ITEMS）
÷ 当时"已公布"的净资产（period_end ≤ 快照日；缺失用 assets−liabilities 并标 derived）
样本 ≥60 才给分位；市值恒定（max−min ≤1e-6）直接返回空 —— 分位是假的，宁可没有
```

**明确拒绝**用 `净利 / ROE` 反推净资产：美股源没有 ROE 字段，反推出来的数是假精度。

实测 10 只**全部 0 个点**，归因逐只如下 —— 这是数据源问题，不是算法问题：

| 票 | 市值快照 | 净资产 | 结论 |
|---|---|---|---|
| NVDA | 2475 个非空点 | NULL（assets/liab 也 NULL） | 缺净资产 |
| COIN | 2392 点 | NULL | 缺净资产 |
| RIOT | 2492 点 | NULL | 缺净资产 |
| MU | 18 行**全 NULL** | 1383.8 亿（有） | 缺市值 |
| CLSK | 18 行**全 NULL** | 76.1 亿（有） | 缺市值 |
| MSTR | 313 个非空但**恒定 63.8**（源没更新） | 684.97 亿（有） | 被恒定守卫拦下 |
| AAPL / AMZN / GOOGL | 7~8 个点 | NULL | 两头都不够 |
| MARA | 249 个非空但恒定 | 无三表 | 两头都不够 |

### 2.4 洞 4：财报日历三源兜底 + 窗口对称

`equity_fundamentals.calendar_events()`：**FMP → AV CSV → yfinance**，任何一路拿到就留着，
再按 `config.EQUITY_TICKERS` 逐票补缺，最后如实回报 `source / filled / missing / errors`。

- FMP `/stable/earnings-calendar` 本机**间歇 SSL EOF**（同一分钟重试就成功），成功时也只给 69 条、
  漏掉 NVDA/MU；
- AV `CALENDAR_CSV` 免费档会返回"权限提示"（非 CSV），不可靠；
- yfinance `Ticker.calendar` 不占配额、日期是真的（NVDA 2026-11-18 / MU 2026-12-24 实测）。

窗口从「只看未来 21 天」改成**前 7 天 ~ 后 90 天**；`fundamental_factor` 的窗口判定改为
**±3 天对称**（`-3 ≤ days ≤ +3`）。只认"未来"会漏掉最该折半的情形 ——
NVDA 的事件日期是 2026-11-17（早于"今天"），旧逻辑 `days=None`，窗口护栏一次都没触发过。

### 2.5 洞 5：可审计 + 可验证

**可审计**：`fundamental` 输出新增 `components`（earnings_position / cyclicity / profile / path /
valuation_used / earnings_revision_used / loss_score / rev_yoy / gm_trend / ocf_margin / ocf_trend）
与 `earnings_next`；`decision_guard._f_bits` 把这些直接写进闸门解释（亏损股口径分、四个读数、
盈利位置、周期度、护栏标签），复盘不用再猜"折半是因为见顶还是因为价值陷阱"。

**可验证**：`src_python/fundamental_shadow.py` + 表 `fundamental_shadow`

| 字段 | 用途 |
|---|---|
| `dir_with / dir_without` | 含 / 不含 fundamental 的加权方向分（各自按可得因子归一） |
| `action_with / action_without` | 用闸门同一组 `thresholds` 还原动作，不另造尺子 |
| `fund_score / fund_available / flags / components` | 决策当时的读数与标签 |
| `ret_1d/3d/5d`、`hit_with/hit_without`、`settled` | 用 `ohlcv_daily` 日线收盘回填前向收益与命中 |

- HOLD 不计命中；缺行情保持 `settled=0`（**不拿 0 冒充结果**）；
- 判定门槛 `_MIN_N=30`，`|Δ| ≥ 5pt` 才判 helps / hurts，否则一律 `insufficient`；
- 挂钩：`engine/ai_worker.py` 在 `record_factor_snapshot` 之后落一行，异常只打印、不影响主判定；
- 调度：`backend/cron/run_fundamental_shadow.sh`（06:10）+ 引擎内 `fundamental_shadow_daily_watcher`
  （06:20，`DISABLE_FUNDAMENTAL_SHADOW_WATCHER=1` 可关）。launchd 在本机被 TCC 拦住，
  真正会跑的是引擎自带调度这条；
- 报告：`backend/reports/fundamental_shadow/latest.json`（当前样本 0，判 `insufficient`）。

## 五、诚实边界（这一版没解决的）

1. **PB 分位仍然不可用**（0/10）：市值源与净资产源各缺一半，MSTR 还被恒定值污染。
   修它需要补市值口径（如 AV OVERVIEW 的 SharesOutstanding × 收盘价）或换资产负债表源，
   属数据修复项，不是再改一个公式能救的。
2. **AV 配额今天已耗尽（25/25）**：本轮为了验证日历与三表把 25 次全用掉了；明天起恢复 3 只/日轮转。
   FMP 的 statement 端点对 MU 直接返 **402 Payment Required** —— 三表宽度短期靠 AV 撑。
3. **财报日历里 NVDA 的日期是 11-17（AV/FMP 口径），yfinance 给 11-18**：跨源日期有 1 天差，
   窗口 ±3 天能吸收，但"财报当天"的精确时点不可靠，别拿它做分钟级交易。
4. **影子账本还没有样本**：只在决策链路挂上了记账，历史决策不回填（回填等于事后挑样本）。
   要 ≥30 笔得等引擎实际跑几天。
5. **权重 0.08 仍是先验**：账本只提供"证伪/证实"的通道，不提供"重新校准"的结论；
   真要改权重，等账本给出 `helps/hurts` 再说。
6. **A股/港股依旧没有触发源**：`target_asset` 里是 `CN_STOCK` 占位标签，接好了但没被点名。
