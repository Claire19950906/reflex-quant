# v476 · 64 项能力入页 + 输入层体检（2026-11-19）

## 一句话

后端的 64 项 Trident-2 功能和 v459–v475 的输入层数据，第一次在页面上有了入口 ——
不是新开一个"功能大全"页，而是**按归属挂回各自的业务页**，每页只看到自己该看的那几项。

## 一、为什么不是一页总表

64 项不是同一类东西：盘前体检属于开仓闸、持仓 thesis 属于账本、链上巨鲸属于资金流向。
堆在一页里，用户仍然不知道"我正在看的这件事，系统有没有替我看"。
所以只做了一个通用面板 `CapabilityPanel`，由各页按分类/ID 取自己那一段。

## 三、面板行为

`frontend/components/quant/capability-panel.tsx`

- 数据：`GET /api/trident2/features`（64 项目录 + 每项最近一次 `t2_results`）；
- 折叠展示：标题行只给「N 项 / 已运行 x」，展开看明细；
- 单条「跑一次」：`POST /api/trident2/run/{id}`，只写 `t2_*` 纸面账本；
- **保护名单禁跑**：F05/F08/F09/F17/F55/F58 按钮置灰，标「保护 · 只出计划」；
- 接口挂掉时显示「能力目录未响应」，不补占位行。

## 四、输入层体检（v459–v475 的可视化）

这批工作把美债、TIC、CAPE、链上、分歧度、可信度门槛接进了决策链，
但页面上只有结论。新增：

- 后端 `GET /api/input-layer/snapshot`（bridge_server.py，只读）
  - **分歧度**：从 `decision_fundamental_snapshot.components` 按 v472 公式重算
    （库里 `dispersion` 列当前全为 NULL，写入链路尚未落列 —— 这是已知缺口）；
  - **宏观/估值/链上**：`macro_snapshots` 的 valuation / auction / tic / onchain /
    defi_tvl / chain_fees / etf_flow / index_price / fred / equity，每个 key 取最近一次；
  - 每条读数都带 `observed_at` / `stale_days`，超 7 天标「旧」，不隐藏；
  - 不触发抓取、不改仓、不下单。
- 前端 `frontend/components/quant/input-layer-panel.tsx`，挂在 `/attribution` 末尾。

实测重算结果与 v472 报告一致：BTC 0.659（高）、ETH 0.316（低）、SOL 0.469（中）、XAU 0.326（低）。

## 六、第二轮补落库（当天 12:40–13:00）

上一轮遗留的两个"列建了却没值"的问题，这轮补齐：

### 6.1 分歧度真正落列

- 病根：`fundamental_shadow._record_snapshot` 从 `comp.get("dispersion")` 取值，
  但 `comp` 是 `guard["fundamental"]` 的**子字典**，分歧度在顶层键上 → 永远 None。
- 修：`_dispersion_from_components()` 在写入前按分量 `score/weight` 兜底重算
  （与 v472/v474 同一公式），表新增 `bull_weight` / `bear_weight` 两列。
- 历史回填：`backend/tools/backfill_dispersion_v476.py`（幂等，只补 NULL 行）。
  **205 行里 115 行有分量可算、90 行分量不足（占位/数据不全）保持空** —— 不硬凑。
- 接口侧：`/api/input-layer/snapshot` 优先读落库值（`source=stored`），
  旧行才重算（`source=recomputed`），面板等级后面标「库 / 算」。

### 6.2 门槛三层落库

- 新表 `decision_threshold_snapshot`（`fundamental_shadow.ensure_table` 建）：
  `buy_min / sell_min / buy_min_calibrated / sell_min_calibrated /
  buy_min_effective / sell_min_effective / confidence / confidence_penalty /
  action_before_gate / action_after_gate / gate_changed`。
- 写入点：`fundamental_shadow.record()` 同事务写一行（不额外扫库）。
- 新接口 `GET /api/decision-thresholds/recent?days=7&limit=40`：现状 + 统计
  （被门槛改变动作的条数、平均压低量）。
- 前端 `components/quant/threshold-panel.tsx` 挂 `/guards`：
  原始 → 校准 → 生效三列并排，「BUY → HOLD（被压）」单独标红。
- 说明：表只从本次改动后开始有行；历史决策没留门槛，**不反推**。
