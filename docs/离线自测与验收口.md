# 离线自测与真数据验收口

给"边改边测"用的两把尺子。改完代码不用起引擎，先跑第一把；等真有数据，再跑第二把。

## 一、离线自测（不依赖外网、不碰生产库）

```bash
cd /Users/claire/Desktop/金融1.0/backend
python3 scripts/offline_selftest.py
```

做的事：在临时目录建一个和生产同结构的空库，写入**明确标注的合成行情/合成决策**（不是真实数据），按真实代码路径跑完 27 项闭环：

| 检查 | 覆盖的行为 |
|---|---|
| S1 | 空账本放行；无行情品种被拒（`PREFLIGHT_MARK`） |
| S2 | 开仓手续费入账、现金扣减、权益重估 |
| S3 | 满仓时拒新单（`PREFLIGHT_LEVERAGE`） |
| S4 | 当日亏损超限拒新单（`PREFLIGHT_DAILY_LOSS`） |
| S5 | 止损触发 → 平仓 → 净盈亏（含双边费） |
| S6 | 对账零 block |
| S7 | 权益快照落库 |
| S8 | 告警去重与自动恢复 |
| S9 | 实盘未武装 → `RefusingAdapter` 硬拒单 |
| S10 | 执行器整轮 tick：决策 → 硬闸 → 成交 → 审计 → 镜像持仓 |
| S12 | 移动止损（跟踪最优价后回撤）+ 时间止损（超时平仓） |
| S13 | 资金费率按持有小时数入账，净盈亏扣掉 |
| S14 | 下单幂等（同 client_order_id 只下一次）+ 超时撤单 |
| S15 | 交易健康度 JSON（equity/杠杆/blocks 落 `runtime/trading_health.json`） |
| S16 | 健康度接口与页面就位（`/api/trading/health` + `frontend/public/trading-health.html`） |
| S11 | 验收口文件就位（检查脚本 + 文档 + 回放口 + 示例 bundle） |
| S17 | 反思三件套：成交 → `trade_reflections_v2` + 三维度 + 教训带「本笔 -1.25%」+ 可执行建议 |
| S18 | 降级决策（LLM 全挂）**不产洞察**：跑了 2 条只写 1 条 |
| S19 | 成绩单结算：BUY 判 WIN、HOLD 也落行且保留原始位移、冻结窗口被 `frozen_window` 挡掉 |
| S20 | 两套账本不相加（`R10_TWO_TRACKS` 只提示）+ 孤儿成交被触发器拒收 |
| S21 | 事件反查：同品种命中、跨品种排除；空库返回空而不抛错 |
| S22 | 402 归「额度耗尽」、401/403 归「key 失效」 |
| S23 | 数据回放口：示例 bundle 能装载（9 张表）并出 6 段结论 |
| S24 | HOLD 决策不进执行器：零成交、零审计行 |

退出码 0 = 全通。任何一项 FAIL 会打印实际数值（费用、盈亏、拒因、反思文本片段），不用去翻库。

## 二、真数据验收（只读，不改库）

数据/引擎起来后：

```bash
cd /Users/claire/Desktop/金融1.0/backend
python3 scripts/acceptance_check.py          # 人看
python3 scripts/acceptance_check.py --json    # 机器看 / 贴给我
```

13 项判据：

| 项 | PASS 条件 | FAIL 说明 |
|---|---|---|
| 库 | 能只读打开 | 路径错/权限 |
| 服务 | engine 进程在跑 | 未跑只 WARN（暂停期属正常） |
| 引擎心跳 | `runtime/ai_worker_progress.json` 600s 内更新 | 暂停期给 WARN |
| 行情 | 最新 tick 在 600s 内 | 数据断流 |
| 今日决策/成交 | 有决策 | 无决策只 WARN（可能没新闻） |
| 今日拒单 | 打印 top3 原因 | 用来判断是闸太紧还是数据不对 |
| 账户 | `canonical` 能算 | 账本口径坏了 |
| 杠杆 | ≤ `MAX_GROSS_LEVERAGE_PCT` | 超限就是真实满仓，必须减 |
| 对账 | 无 block | R1/R2/R7 等硬错 |
| 日亏 | 当日亏损 < `DAILY_LOSS_LIMIT_USDT` | 触线即停手 |
| 止损覆盖 | 无"开仓但没止损"的持仓 | 裸仓 |
| run 唯一性 | `paper_trading_runs` 只有 1 条 RUNNING | 自愈不幂等 |
| 未处理告警 | — | 只 WARN，需要人看 |

## 二·B 能力验收（判断"功能逻辑通不通"，而不是"账户对不对"）

```bash
cd /Users/claire/Desktop/金融1.0/backend
python3 src_python/capability_acceptance.py            # 人读
python3 src_python/capability_acceptance.py --json     # 机读 / 留档
python3 src_python/capability_acceptance.py --only 1,2,6
```

26 项分五档，**关键在于别把"等数据"读成"坏了"**：

| 状态 | 含义 | 该做什么 |
|---|---|---|
| ✅ PASS | 硬判据全达标 | 不用管 |
| ❌ FAIL | 逻辑/口径/接线坏了 | **只有这一类要改代码** |
| ⏳ INSUFFICIENT | 链路在跑，样本没到门槛 | 不改代码；看它给的 `等什么 / 现有 / 数据到了看` 三行 |
| ⚠️ WARN | 达标但样本偏少 | 先看趋势，别据此下结论 |
| ⏭️ SKIP | 前置条件不具备 | 无 HTTP / 新纪元无样本，属正常 |

每个 ⏳ 项都自带三个字段，数据进来后照它念：

- `need`：还差什么（"真实开仓结算 20 笔"）
- `have`：现在多少（"1 笔"）
- `watch`：够了以后看哪个数、什么算不通（"下界站不上 50% 才是逻辑问题"）

2026-11-20 实测：13 PASS / 2 FAIL / 7 ⏳。7 个 ⏳ 全是"决策/结算/反思还没攒到样本"，
其中 #2 的权重写入早已在 `decision_writer` 接通、#6 的 event-kline worker 已在跑
（`event_kline_impact` 1943 行），剩下只是窗口没到期 —— 这些**不需要动代码**。

## 三、真数据回放（只读，不碰生产库）

离线自测用的是合成数据，只能证明"代码路径通"，证明不了"这套判断在真实分布上合不合理"。
要验真数据，把要验的行导出成一个 bundle，倒进临时库，跑同一套语义检查：

```bash
cd /Users/claire/Desktop/金融1.0/backend
# 1) 从生产库只读导出（不写库，mode=ro）
python3 scripts/export_bundle.py --days 7 --out /tmp/bundle_7d.json
# 2) 回放并出结论
python3 scripts/replay_bundle.py --bundle /tmp/bundle_7d.json
python3 scripts/replay_bundle.py --bundle ... --md /tmp/replay.md --json /tmp/replay.json
```

bundle 就是一个 JSON，`tables` 里按「表名 → 行对象数组」放数据，列名和库表对得上就行：

```json
{
  "meta": {"source": "生产库导出 2026-11-20", "note": "7 天窗口"},
  "tables": {
    "ai_decisions": [{...}, ...],
    "quick_sim_trades": [...],
    "trade_reflections_v2": [...],
    "signal_performance": [...],
    "news_events": [...],
    "critical_price_moves": [...],
    "ohlcv_intraday": [...],
    "t2_positions": [...]
  }
}
```

导出用的只读 SQL（照抄即可，按需要裁时间窗）：

```sql
SELECT * FROM ai_decisions WHERE created_at >= datetime('now','-7 day');
SELECT * FROM quick_sim_trades WHERE created_at >= datetime('now','-7 day');
SELECT * FROM trade_reflections_v2 WHERE created_at >= datetime('now','-7 day');
SELECT * FROM signal_performance;
SELECT * FROM news_events WHERE ts >= strftime('%s','now') - 7*86400;
SELECT * FROM critical_price_moves WHERE ts >= strftime('%s','now') - 7*86400;
SELECT * FROM ohlcv_intraday WHERE ts >= strftime('%s','now') - 7*86400;
SELECT * FROM t2_positions;
```

报告固定给 6 段结论，每段都直接写"能不能据此下判断"：

| 段 | 看什么 | 不可信时的判语 |
|---|---|---|
| 决策分布 | HOLD 占比、降级率、无品种率 | HOLD > 80% → 瓶颈在决策层，先别看收益 |
| 成绩单结算 | WIN/LOSS 笔数、平均 forward_pnl / MFE / MAE | 结算笔数 < 30 → 只能当轶事 |
| 反思闭环 | 反思条数 / 已结算成交；三维度空值率 | 空值率 > 50% → 错误码没接上，统计退化成单一桶 |
| 教训可执行性 | 带「本笔」数字的比例、可执行建议比例 | 带数字 < 50% → 教训是模板，进 prompt 没信息量 |
| 双账本对账 | quick_sim 与 t2 的笔数/净额 | 永远不能相加，只报 quick_sim |
| 事件归因 | 归因行 / 异动点、方向一致率 | 覆盖低 → 事件没配到异动，归因不可用 |

示例 bundle 在 `backend/tests/fixtures/offline_bundle_example.json`（合成数据，仅用于验证装载与口径）。
**这个口是留给真数据的**：数据一进来，换文件路径重跑，结论就从"路径通不通"升级成"这套判断合不合理"。

## 三·B 留的口（开关与参数）

| 口 | 位置 | 用途 |
|---|---|---|
| 数据/引擎总开关 | `bash ~/.trident/wrappers/resume_data.sh` / `pause_data.sh` | 要测真数据就 resume；改代码时 pause |
| 交易模式 | `.env` 的 `TRADE_EXECUTOR_MODE` | `paper`（默认）/ `live_dry` / `live_real` |
| 实盘三重武装 | `BINANCE_API_KEY`、`LIVE_TRADING_ACK=I_UNDERSTAND_REAL_MONEY`、`LIVE_MAX_NOTIONAL_USDT` | 缺任一即 `RefusingAdapter`，不下单 |
| 风险阈值 | `MAX_GROSS_LEVERAGE_PCT`、`MAX_ASSET_WEIGHT_PCT`、`MAX_OPEN_POSITIONS`、`DAILY_LOSS_LIMIT_USDT` | 闸门松紧 |
| 成交模型 | `.env: PAPER_SLIPPAGE_BP` / `PAPER_FILL_RATIO` / `FUNDING_BPS_PER_8H` / `ORDER_STALE_SECONDS` | 纸面成交的滑点、部分成交、资金费、超时撤单 |
| 人工调权重 | `POST http://127.0.0.1:8100/api/signal-weights/override` | 乘法系数 0.5~2.0，必须写 reason+actor；`/revoke` 撤销；生效时 weight_explain 留 `manual_override ×1.2 (#3 by ...)` |
| 全量测试 | `python3 -m pytest tests/ -q` | 回归 |

## 四、建议的迭代节奏

1. 改代码（引擎可以一直停着，不用边改边跑）。
2. **一条命令看全局**：
   ```bash
   cd /Users/claire/Desktop/金融1.0/backend
   python3 scripts/iteration_check.py             # 闭环 + 能力口径 (~40 秒)
   python3 scripts/iteration_check.py --with-pytest   # 再加全量回归
   ```
   它把三条尺子压成三行：`交易闭环 27/27` · `能力验收 PASS/FAIL/⏳` · `回归 passed/failed`，
   然后给一句结论：要么"先修 ❌"，要么"⭐ 剩下的 ⏳ 是等数据，别改代码"。
3. 需要真数据时：`resume_data.sh` → 等 10 分钟 → `acceptance_check.py`。
4. 看 `acceptance_check` 的"今日拒单"和"对账"，判断是策略没出信号，还是闸/数据的问题。
5. 测完 `pause_data.sh`，继续改。

## 五、当前已知边界（不是 bug，是没做完）

- **美股/原油永续**：OKX 没有对应合约，`WTI-USDT-SWAP` 会返回空；美股走 yfinance，`^IRX` 这类符号会 delisted。股票资产目前只做展示与纸面，不接实盘。
- **两条轨道**：`quick_sim` 与 T2 各自一套账，对账只报 `R10_TWO_TRACKS` 提示，没有合并。对外只能说一个口径。
- **告警只落库**：`t2_alerts` 有了，但没接飞书/邮件推送；要看就查库或看面板。
- **止损守护需要引擎外的进程常驻**：`com.trident.stops-guard`，pause 时会一起停；暂停期间没有止损保护——这是暂停的代价，需知悉。
- **成交模型**：滑点/部分成交/资金费已计入（v479），但仍是线性估算，不是逐笔撮合；真实盘口深度只有实盘才测得准。

## 六、交易健康度（看板）

后端新增只读接口：

```
GET http://127.0.0.1:8100/api/trading/health
```

返回：现金/权益/已实现/浮盈/名义/杠杆/持仓数/对账 block/告警数/行情延迟 + 逐笔持仓浮盈。
阈值从 `backend/.env` 读，所以杠杆不会误报成 100% 上限。

页面：`frontend/public/trading-health.html`，浏览器直接打开或经前端静态目录访问
（`http://127.0.0.1:3030/trading-health.html`），可在页面顶部改 API 地址，10 秒自动刷新。
它**没有**挂进主导航，属于独立只读页；要嵌进现有前端需再改 Next 路由。

守护进程每轮对账还会把同一份数据写 `backend/runtime/trading_health.json`，
不启前端也能 `cat` 出来看。
