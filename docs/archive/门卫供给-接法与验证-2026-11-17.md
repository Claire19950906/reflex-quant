# 门卫供给：现状、接法、验证（2026-11-17 07:1x 实测）

> 一句话：门卫（gate）通道**配额打满**，近 30 分钟新入库的 54 条新闻里有 **20 条（37%）被冻结**
> 等回放、28 条拿不到门卫标签。这不是路由规则能解决的，需要给门卫一条**独立配额**的端点。

## 一、现状数字（都是刚查的）

| 指标 | 值 | 说明 |
|---|---|---|
| 近 30 分钟入库 | 54 条 | |
| `gate_unavailable=1`（冻结等回放） | 20 条 / 37% | 主分析**不认领**它们 |
| 无门卫标签 | 28 条 | 走 L1/L2 关键词路径进分析 |
| 门卫给了判定 | 4 条 / 7% | 只有这 4 条是真判过的 |
| 降级放行（`=2`，未判定） | 2 条 | 鉴权类失败才走这条 |
| 冻结池现值 | 22 条 PENDING | 最老的 06:31 |
| 近 3 小时已解冻 | 19 条 | 30 分钟兜底在跑，机制没坏 |

日志原话（07:0x）：`[FILTER] ⚠️ LLM 全池不可用（累计 N 次）| purpose=gate ... 熔断态={'llm_main_quota:minimax1': 'closed', 'llm_main_quota:minimax2': 'closed', ...}`

**注意健康面板会骗你**：`/api/health/models` 显示 `MiniMax-M2.7-highspeed (gate专用) available=true` ——
因为面板每轮只探**一次**，延迟 14 秒也能过；门卫是连续高频调用，一打 429 整条通道就熔断。

## 二、为什么现在只有两条门卫通道

`config.py:672` 附近写明：

- `minimax-gate`  → `MINIMAX_GATE_KEY`（账户2，号称"门卫专用配额"）
- `minimax-gate2` → `MINIMAX_MAIN_KEY`（账户1，**和主分析共用**）

所以两个账户的配额同时打满时，门卫整体不可用。引擎启动时自己都会打印：

> ⚠️ 门卫通道只有 1 条、独立 key 1 个 → 与主分析共用配额；配额打满时门卫会整体 429。

## 三、接法（改 `.env` 三行，代码已支持，不用改代码）

`config.py:706` 已经实现了"第三个门卫端点"的入口，只是 `.env` 里没填：

```bash
# backend/.env
GATE_ALT_BASE_URL=https://<你的端点>/v1     # OpenAI 兼容
GATE_ALT_API_KEY=<独立配额的 key>
GATE_ALT_MODEL=<模型名>
```

填了以后，config 会把它作为 `gate-alt/<模型>` 通道加入门卫池（`purpose=["gate"]`），
熔断键按 key_alias 隔离 —— 打满一个不会连坐另外两个。

**注意两件事**：

1. `.env` 是 config 在 Python 里加载的，**不会出现在进程环境变量里** ——
   所以别用 `ps -E | grep GATE_ALT` 验证（实测 engine 进程 env 里根本没有 `MINIMAX_GATE_KEY`，
   但门卫照样在调模型，说明值是在 Python 内读进来的）。验证只能走面板 + 日志。
2. 真正来自 wrapper 的只有 `~/.trident/wrappers/run_engine.sh` 里那几行 `export`（含
   `NEWS_ANALYZE_MAX_AGE_HOURS`）。**如果 `.env` 里填的 `GATE_ALT_*` 没生效，就把同样三行
   加到 wrapper 里**——wrapper 里的 export 优先级高于 .env。

## 四、改完怎么验（3 步，5 分钟）

```bash
# 1) 重启三个进程
launchctl kickstart -k gui/$(id -u)/com.trident.engine
launchctl kickstart -k gui/$(id -u)/com.trident.api
launchctl kickstart -k gui/$(id -u)/com.trident.bridge

# 2) 等 2 分钟，看通道是否多出一条 gate-alt
curl -s http://127.0.0.1:8000/api/health/models | python3 -m json.tool | grep -A3 "gate独立端点"

# 3) 看门卫到底有没有在判（判据是"有判定"的比例，不是 available）
cd backend && python3 - <<'PY'
import sqlite3, time
c = sqlite3.connect("file:trident_event_bus.db?mode=ro", uri=True)
print(c.execute("""SELECT
 SUM(COALESCE(gate_unavailable,0)=1) AS 冻结,
 SUM(COALESCE(gate_verdict,'')<>'' AND COALESCE(gate_unavailable,0)<>1) AS 有判定,
 COUNT(*) AS 总数
 FROM raw_news WHERE ts > ?""", (int(time.time())-1800,)).fetchone())
PY
```

**通过判据**：30 分钟内"有判定"占比 ≥ 80%、冻结 ≤ 5%、`[FILTER] 全池不可用` 不再新增。
**没通过** 说明新端点也没配额，别再试第二条 key，直接降级策略（见下）。

## 五、不接线的后果（现在的兜底边界，必须知道）

1. **30 分钟自动放行**（`ai_worker.py:11020`，`_GATE_FREEZE_TTL_S=1800`）会把超龄冻结改成 `gate_unavailable=2`
   —— 主分析照常分析，但**没有门卫标签**，决策层少一道过滤。
2. **回放会把它再冻回去**：`[gate-replay] 连续 3 条失败，本轮停止` —— 于是同一批新闻在
   "解冻→回放失败→再冻结" 之间振荡，不丢数据，但**不产出**。
3. 结果就是吞吐被压在低位：06:53 重启到现在 16 分钟，只产出 5 条决策（HOLD×5，其中 4 条 target_none）。

## 六、如果短期内拿不到独立配额

按性价比，这件事可以做（不用等 key）：

- **收紧门卫调用面**：只对「过了 L1/L2 关键词且命中池内品种名」的新闻调门卫，
  其余直接走规则兜底。门卫调用量能降到现在的 1/3 左右，配额打满的概率同步下降。
  代价：漏判一部分"只有宏观词没有品种词"的稿子——但这批本来 87% 判 NONE（见 `docs/第二道闸门设计-2026-11-17.md`）。
- 这条要不要做，等你拍板；它改的是门卫的"调用策略"，不是判据，回滚只要一个开关。

## 七、不接新 key 时，本机四条"替代通道"的实测结论（2026-11-17 08:2x）

结论先说：**四条都不可用，门卫要扩容量只能拿新 key。** 证据如下，免得再试一遍。

| 候选 | 状态 | 实测证据 |
|---|---|---|
| OpenRouter（`.env` 已有 `OPENROUTER_API_KEY`，73 字符） | **key 已失效** | `GET /api/v1/key` → `HTTP 401 {"error":{"message":"User not found"}}`；`/credits` 同样 401。`/models` 能返回 200 只是因为该接口对无效 key 也放行 |
| DeepSeek 直连（`DEEPSEEK_BASE_URL` 已配） | **无 key** | `.env` 里 `DEEPSEEK_API_KEY=` 为空 |
| 火山 ARK（`ARK_BASE_URL`/`ARK_MODEL=minimax-m3` 已配） | **无 key** | `ARK_API_KEY=` 为空；`DOUBAO_API_KEY=` 也为空 |
| 本地 Ollama（`qwen2.5:3b`，1.9GB 已装，服务在 11434） | **慢到不可用** | 门卫式短 prompt 实测 **>180s 超时**（`.env` 里 147–175s 的记录与此一致）。默认门卫超时 25–90s → 必然失败。这也是 `LOCAL_LLM_ENABLED=0` 的原因（`.env:154` 那段"必须保持 1"是旧结论，已被实测推翻） |

**顺带两条建议**：
1. `OPENROUTER_API_KEY` 既然已 401，建议从 `.env` 里删掉或置空 —— 留着会让排查时误以为"还有一条备用通道"（假冗余比没冗余更危险，这事儿 v321 已经踩过一次）。
2. 要扩门卫，最省事的是**再开一个 MiniMax 账户**（同 `MINIMAX_BASE_URL`，只换 key），
   然后把 key 填进 `GATE_ALT_API_KEY`、`GATE_ALT_BASE_URL=https://api.minimaxi.com/v1`、
   `GATE_ALT_MODEL=MiniMax-M2.7-highspeed`。这样连代理/SSL 风险都不用重新验证。
