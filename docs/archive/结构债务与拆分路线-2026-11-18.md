## 二、为什么 `ai_worker.py` 不能按模块一刀切

`_call_llm_sync`（2,186 行）是里面最大的单函数，我实测过它的自由变量：**162 个**。

```
自由变量数 162
样例：MARKET_CATEGORIES_PROD, _ANALYSIS_RATELIMIT_COOLDOWN_S, _CALENDAR_STATUS,
     _COVERAGE_STAGES, _DIRECTION_RETRY_HINT, _DOUBAO_SYSTEM_PROMPT, _JSON_PROMPT_FORCE,
     _LLM_SESSION, _MARKET_STRUCTURE_BLOCK, _OUTPUT_CONTRACT, _SYSTEM_PROMPT,
     _TWO_STEP_A_HINT, _analysis_breaker, _build_baseline_block, ...
```

意思是：这个函数是"长"在模块级全局变量上的。把它剪到新文件，得同时搬 162 个名字，
或者反向 `import ai_worker` 造成循环依赖 —— 两种都不比现在干净。**所以必须先把全局
常量收拢，再动函数。** 顺序错了就是白干。

## 四、不打算做的（理由）

- **给 `db.py` 继续拆 SQL 逻辑**：`migrate()` 791 行是"一表一段"的顺序执行，
  拆成多个函数反而要传一堆 `conn` 中间状态，收益低于风险。DDL 拆完就够了。
- **把 5 套部署收敛成 1 套**：`docs/部署方式矩阵-2026-11-17.md` 已说明各自场景
  （本机 launchd / 容器 / 云镜像），强行统一会砍掉现有用法。
- **删 144 条零引用端点**：`docs/零引用端点审计-2026-11-16.md` 已判定"不删"——
  它们是运维/回填/调试入口，删了下次出事没工具可用。

**两个流程教训（已写进 commit message）**
1. 切函数必须用 `min(decorator.lineno, def.lineno)` 作为起始行。只按 `node.lineno` 切，

## 2026-11-18 追加：事件循环阻塞审计（routers 层）

结构拆完之后顺手查了一个性能面的真问题：`routers/` 里 392 个端点，89.5% 是 `async def`。

判据（脚本，不靠肉眼）：装饰器是 `@router.get/post/...`、函数体内 **既没有** `await` /
`async for` / `async with`、**又出现** `sqlite3` / `db_cursor` / `conn.execute` —— 这种端点
把同步 SQL 读写直接压在事件循环上，一条慢查询就能卡住整个 8000 的所有请求（前端表现为
"整站点转圈"）。

全仓扫出 **137 个 async 端点体内零 await**，其中 **44 个在做同步 SQL**。本轮改掉 39 个
（12 个文件）为 `def`，FastAPI 会自动放进线程池，路由数与路径都不变；剩 5 个落在并行线
新增/未提交文件里，交给那条线自己改。ruff 全绿，相关测试 511 passed。

## 2026-11-18 追加：两条生产库"存量条数"断言改成结构不变量

`test_v200_p0_experience_loop` 里有两条集成断言：`applied >= 7`、`XAU 必须有 applied 行`。
它们数的是**生产库存量**，而 v340 数据纪元把派生表清空后，新纪元只攒了 2 行（id 288/289，
全是 WTI）——断言必然越界，跟代码对错无关。这和 2026-10-29 修过的
`test_weekly_insight_apply_dry_run_param_recovery`（`skipped_no_param < 30`）是同一个坑：
**拿会漂移的存量数据当阈值**。

改法：只看结构不变量——标了 applied 的行，`applied_setting_change` 不得为空，且文本里要能
看出这条改动落在哪个品种；库空则 skip。测试回到 22 passed / 1 skipped。
