## 二、改了什么

### 1. 结算口径统一（`quick_sim.py` / `history_review.py`）

新增唯一入口 `quick_sim.settle_figures(gross, asset, action) -> (net, cost_bps, cost_pct)`：

```python
净 = 毛 − round_trip_cost_bps(asset)/100      # 1bp = 0.01%
```

接入四条此前**不扣成本**的路径：

| 路径 | 之前 | 现在 |
|---|---|---|
| `_settle_sl`（止损） | 只写毛 `pnl_pct` | 毛/净分列 + `cost_bps` |
| `_settle_tp2`（止盈） | 只写毛 `pnl_pct` | 同上 |
| `cut_bleeding_trades`（强制砍仓） | 只写毛 `pnl_pct` | 同上（触发条件仍看毛浮亏，语义不变） |
| `history_review` 重判 | 只写毛 `pnl_pct` | 同上 |

口径细节：

- `verdict` 一律跟**净**收益符号走（`>0 WIN / <0 LOSS / =0 BREAKEVEN`）。
- `partial_pnl_pct`（TP1 部分止盈）仍存**毛值**，成本在最终 blended 结算时一次性扣 —— 成本按百分比线性，加权后等价，不会重复计费。
- 到期结算 `settle_trades` 原本就是净口径，未改动。

### 2. 反思的"判断对不对"改由 4h/24h 真值回答（`reflection_horizon_truth.py` 新增）

`trade_reflections_v2` 新增 5 列：

| 列 | 含义 |
|---|---|
| `truth_4h_verdict` | `direction_ok / direction_wrong / flat / insufficient / ''(无影子行)` |
| `truth_4h_net_pct` | 该方向 4h 扣往返成本后的净收益（百分点） |
| `truth_24h_verdict` / `truth_24h_net_pct` | 同上，24h 窗口（回答"慢半拍但方向对"） |
| `truth_stamped_at` | 盖章时刻 |

- 数据源：`shadow_reflections`（按 `decision_id` join），**不另算一套方向**，直接用影子层的结论。
- 净收益 = 方向符号 × 实际涨跌 − 往返成本；SELL 遇上涨 → 负。
- 没有影子行 / 没有结算价 → **留空，不写 0**（判不了 ≠ 判错）。
- 每次 `shadow_reflections.run(--commit)` 末尾自动盖章（失败不影响影子账本）。
- 反思自己的 `pnl_pct` 保留，降级为"20~40 分钟执行损益"，不再当对错依据。

### 3. HOLD 漏检记账从反思表分出去（`missed_signal_reflection.py` + `db.py`）

新表 `missed_signal_reflections`（`decision_id` 唯一，幂等 upsert）：

```
decision_id, asset, action, dimension, subcategory,
root_cause, lesson, verification, move_pct, hit,
confidence_at_time, reflection_text, evidence, created_at
```

- 不再写 `trade_reflections_v2`；`run()` 里做一次幂等建表，避免引擎重启前静默失败。
- 文案按 `hit` 分支：
  - `hit=1` → "漏检信号: 市场出现本应触发交易的方向(x% >= 1.0%), 但系统给了 HOLD"
  - `hit=0` → "HOLD 记账: 后续涨跌未达 1.0% 阈值, 不构成漏检, 仅留痕"
- 统计侧同步收紧（`reflection_scorecard.py` / `meta_reflection_loop.py`）：
  - 语料/判定/覆盖一律 `origin <> 'template'`；
  - 成绩单新增"反思 × 4h/24h 真值"一节，判得出方向才算可判定；
  - 元反思聚合加 `origin <> 'template'`（模板行本来也不满足 `settled=1`，此处是防回归）。

历史 52 条模板行**不删**（不动生产数据），只是从统计口径剔除；需要物理清理时另行确认。

#13093 净 −0.4041 → 文案写成 +0.4041，读起来像"反向做就赚 0.4%"。实际反向机械反演

## 第五批（v490）：结构加固 + 链路实测

### 11. 经验块缓存改成按上下文分键（`engine/ai_worker.py`）

旧实现只有**一条**全局缓存 `{"key","text","exp_ids"}`：BTC 取完紧接着取 WTI，BTC 那条就被顶掉；
并发时"命中哪条"取决于最后一个写入者。改成 `{(asset, gate_kind, actor): {...}}`，上限 64 条，
超了丢最老的一半。

- 效果：多品种同轮分析不再互相踢缓存；`exp_ids` 跟着各自 key 走，不会把 XAU 的经验 id 塞给 BTC 的决策。

### 12. 注入 id 标记改成线程本地（`engine/ai_worker.py`）

`_LAST_INJECTED_EXP_IDS` 是进程级单值。engine 里分析线程和 gate 线程并行跑，
A 决策注入的 id 可能被 B 决策的记账读走 —— 属于"看起来记了账，记到了别人头上"。

- 新增 `_EXP_IDS_TLS = threading.local()` 与 `_set_injected_exp_ids()` / `_get_injected_exp_ids()`：
  线程内优先，本线程没有才回落到全局（兼容老调用点）。
- 落库后的旧记账块也改读线程本地，并且**写完立刻清空**，避免二次重复。

### 13. 影子账本链路：确认是"等数据"，不是"断链"

实测生产库：

- `shadow_ledger` / `shadow_degraded` 两张表当前 **0 行**（今天所有决策都是 HOLD，没有可记账的方向样本）。
- 重启后 17:41–17:45 出现了 **4 条方向性候选**（`ungated_action` ∈ BUY/SELL，`analysis_degraded=0`）：
  13522 WTI/SELL、13523 BTC/BUY、13525 US_STOCK/BUY、13529 BTC/SELL。
- 它们的 4h 结算点在 21:41–21:45；`run_missed_signals.sh` 每小时跑一次，
  `run_shadow_ledger.sh` 每 4 小时跑一次并调 `shadow_reflections.py --commit`。
  所以今晚第一次结算后，`shadow_reflections` 才会有行，`truth_4h_*` 才有东西可盖章。

结论：这条链没有断，只是**之前确实没有可结算的样本**。不需要改代码。
