# Trident 评分规则全景

> 一条新闻从采集 → AI 打分 → 多因子合成 → 置信度闸门 → 策略过滤 → 模拟盘下单，
> 分数共经 **5 层流水线**。本文档按链路逐层列出全部规则、权重、阈值与出处（源码文件）。

---

## 链路总览

```
新闻入库
  │
  ▼
[第 0 层] AI 情绪分 sentiment_score（-1~+1，五级锚定）
          + 新鲜度衰减 ×(1.0~0.5) + VIP 加成 ×1.25
          + 影响三兄弟 heat/impact/asset_impact（0-10）
  │
  ▼
[第 1 层] 七因子加权合成 final_score（decision_guard.py）
          0.30 情绪 + 0.20 盘面确认 + 0.15 趋势 + 0.10 波动
          + 0.10 资金费率 + 0.10 聚合热度 + 0.05 历史胜率
          + 影响加权 boost
  │
  ▼
[第 2 层] 方向门槛 → raw_action（BUY ≥ +0.4 / SELL ≤ −0.3 / 否则 HOLD）
  │
  ▼
[第 3 层] 置信度闸门（evidence.py，GATE = 55）
          |final_score|×100 × 卡方显著性权重 − 矛盾扣分
          ≥ 55 → 输出方向单；< 55 → 强制降级 HOLD
  │
  ▼
[第 4 层] 策略入场过滤（strategy_store.py）
          方向符号 / 信号阈值 / 资产限定 / 事件强度 / 直接催化
  │
  ▼
[第 5 层] 模拟盘执行链
          is_running + 资产白名单 + 源开关 + 新闻时效(≤900s) + 闸门模式
  │
  ▼
          下单
```

## 第 0 层：AI 打分（分数源头）

源码：`backend/src_python/engine/ai_worker.py`（Prompt 内嵌锚定框架）

### 0.1 sentiment_score 五级锚定框架（-1.0 ~ +1.0）

| 区间 | 档位 | 典型事件示例 |
|---|---|---|
| ±0.05 ~ ±0.15 | 弱信号 | 官员口头表态但无政策落地、第三方评论 |
| ±0.15 ~ ±0.35 | 轻度信号 | 二级经济数据超预期、关联市场异动、监管传闻 |
| ±0.35 ~ ±0.55 | 中度信号 | CPI/NFP 大幅偏离、美元指数剧烈波动、交易所黑客/挤兑、机构增持减持 |
| ±0.55 ~ ±0.75 | 强信号 | FOMC 意外转向、ETF 获批/拒绝、OPEC 减产、大国制裁升级 |
| ±0.75 ~ ±0.95 | 极端信号 | ETF 历史性获批、战争爆发、主权违约、央行无限 QE、交易所破产 |
| ±1.00 | 绝对确信 | 几乎不使用；仅「事后看不可能错」的极端事件 |

**分数铁律（Prompt 内强制）**
- score **严禁为 0.0**；中性区给 ±0.03 ~ ±0.10
- 方向不确定时 **HOLD 是正确答案**，不赌
- sentiment_score 语义 = 「**2 小时窗口内**该事件推动价格方向的置信度与幅度预期」
- BTC 在战争/危机/流动性恐慌中 → SELL（纯风险资产，无避险属性）
- 市场快照价格与方向判断矛盾 → confidence 降级、market_confirmation 设 negative
- 缺少市场数据时 market_confirmation 必须为 unknown

### 0.2 新鲜度衰减（新闻越旧信号越弱）

源码：`ai_worker._apply_freshness`（按入库/发布时间年龄）

| 新闻年龄 | 权重 |
|---|---|
| 0 – 15 分钟 | × 1.0 |
| 15 – 30 分钟 | × 0.85 |
| 30 – 45 分钟 | × 0.70 |
| > 45 分钟 | × 0.50 |

与硬时效门槛（第 5 层 900s）配合：门槛负责「超时禁止交易」，这里做平滑衰减「置信」。

### 0.3 影响评估三兄弟（0-10，LLM 输出，缺失/越界钳制到 5.0 中性）

| 字段 | 含义 | 刻度 |
|---|---|---|
| `heat_score` | 舆情热度 | 0-3 冷门 / 4-6 行业关注 / 7-8 主流热议 / 9-10 现象级刷屏 |
| `impact_score` | 市场实际影响力 | 0-3 情绪扰动 / 4-6 局部行情 / 7-8 波段级 / 9-10 结构性黑天鹅 |
| `asset_impact` | 对 target_asset 直接影响 | 0 无关 / 1-3 间接 / 4-6 直接相关 / 7-8 直接催化 / 9-10 决定性事件 |

### 0.4 VIP 加成

命中 VIP 关键词且 action ∈ {BUY, SELL} → `|score| × 1.25`（钳制不超 1.0）。
源码：`ai_worker` 主循环，`VIP_SCORE_BOOST`。

### 0.5 输出质量强制（重试机制）

- 六段推演 `reasoning_path` 不完整 → 带纠正提示重试 1 次
- 推演文本方向与 `suggested_action` 相反 → 带一致性提示重试 1 次
- 主模型失败 → 备用通道 / 关键词兜底（偏多 +0.4 / 偏空 −0.4 / 中性 +0.05）
- **HOLD 永不因分数被改写成方向单**（观望就是观望）

## 第 1 层：七因子加权合成 final_score

源码：`backend/src_python/decision_guard.py`

每个因子归一化到 **-1 ~ +1**，按权重加权：

| 因子 | 权重 | 计算方式 |
|---|---|---|
| news_sentiment | **0.30** | AI 情绪分（钳制 ±1） |
| market_confirmation | 0.20 | confirmed/strong/yes → +1；rejected/opposite → −1；无字段 → 24h涨跌幅 ÷ 5 |
| trend | 0.15 | strong bull +1 / bull +0.6 / bear −0.6 / strong bear −1 / 其它 0 |
| volatility | 0.10 | 1 − ATR% ÷ 10（波动越大分越低） |
| funding | 0.10 | −资金费率 ÷ 0.1（多头拥挤→减分） |
| cluster_heat | 0.10 | (聚合新闻数 − 1) ÷ 4（封顶 +1） |
| historical_confidence | 0.05 | (已结算胜率 − 50%) × 2；无样本 → 0 |

```
final_score = Σ(因子分 × 权重)
```

### 影响加权加成

```
impact_boost = (impact_score − 5) × 0.03
             + (heat_score    − 5) × 0.01
             + (asset_impact  − 5) × 0.02

final_score = final_score + impact_boost
```

影响评估默认 5.0（中性）= 不加不减；缺省字段同样按 5.0。

## 第 2 层：方向门槛（raw_action）

源码：`decision_guard.py`（阈值后台可调，5s TTL 生效）

| 方向 | 条件 | 默认门槛 |
|---|---|---|
| BUY | final_score ≥ buy_min | **+0.40** |
| SELL | final_score ≤ −sell_min | **−0.30** |
| HOLD | 其余情况 | — |

说明：做多胜率偏低 → BUY 门槛默认高一档；SELL 门槛较低（做空更倾向）。

## 第 3 层：置信度闸门（0-100，GATE=55）

源码：`backend/src_python/evidence.py`

### 3.1 卡方显著性权重（样本 vs 50/50 随机）

| p 值 | 显著性权重 | 说明 |
|---|---|---|
| 样本 < 8 条 | × 0.80 | 样本不足，历史不参与显著性判定 |
| p ≤ 0.05 | × 1.00 | 显著 |
| p ≤ 0.20 | × 0.85 | 弱显著 |
| 其余 | × 0.70 | 不显著，降低信任 |

样本自动扩展：同品种 → 同赛道（如 BTC/ETH/SOL…）→ 全市场补齐（只统计真实 WIN/LOSS，不造数）。

### 3.2 矛盾检测扣分（反幻觉）

检测因子间冲突（阈值 ±0.3 视为方向性）：

| 矛盾类型 | 触发 | 扣分 |
|---|---|---|
| sentiment_vs_trend | 新闻偏多但趋势向下 / 偏空但趋势向上 | 12 |
| sentiment_vs_confirmation | 新闻偏多但盘面反向 / 偏空但盘面走强 | 12 |
| sentiment_vs_funding | 新闻偏多但多头拥挤 / 偏空但空头拥挤 | 12 |

每条扣 **12 分**，上限 **36 分**（`_CONTRADICTION_PENALTY` / `_MAX_CONTRADICTION_PENALTY`）。

### 3.3 置信度合成

```
confidence = |final_score| × 100 × 显著性权重 − 矛盾扣分     （0-100，封顶）
```

### 3.4 闸门判定

- confidence ≥ **55**（CONFIDENCE_GATE）→ 输出方向性结论（raw_action 保留）
- confidence < 55 → **强制降级 HOLD**（只观望不下单）

verdict 文案：
- 过闸 → 「证据充分，允许输出方向性结论」
- 未过且无矛盾 → 「统一置信度 X 低于闸门 55，仅输出观望结论」
- 未过且有矛盾 → 「证据互相矛盾且统一置信度低于闸门，仅输出观望结论」

## 第 4 层：策略入场过滤（策略库参数）

源码：`backend/src_python/strategy_store.py`（`signal_matches` / `signal_mismatch_reason`）
回测与实时模拟盘共用同一口径。全部通过 → `signal_matches = true`：

| 检查项 | 规则 |
|---|---|
| 方向符号 | BUY 需 score > 0；SELL 需 score < 0；矛盾 → 拒绝 |
| 信号强度 | \|score\| ≥ `signal_threshold`（策略参数，可调范围 0.3 ~ 0.9） |
| 资产过滤 | `asset_filter` 非空时只允许该资产（如只做 BTC） |
| 事件强度 | 实际强度 ≥ `min_event_strength`（low < medium < high） |
| 直接催化 | `require_direct_catalyst` 开启时需 `direct_catalyst = true` |

默认策略示例：
- news-threshold 保守版：signal_threshold = 0.7
- news-threshold 进取版：signal_threshold = 0.35

## 第 5 层：模拟盘执行链（全部满足才下单）

源码：`backend/src_python/engine/ai_worker.py`（建仓段）+ `paper_trading.py`

```
auto_trade = is_running                                  模拟盘运行中
          ∧ active_run 存在
          ∧ asset_allowed(asset)                         资产在 TRACK_ASSETS 白名单
          ∧ source_enabled(source)                       该新闻源开关打开
          ∧ action ∈ {BUY, SELL}
          ∧ asset ∉ {"", "NONE"}
          ∧ news_fresh                                    新闻年龄 ≤ 时效门槛(默认900s=15分钟)
          ∧ (宽松模式: 闸门关  → 直接建仓
             │
             严格模式: 闸门过(≥55) ∧ 策略过(signal_matches))
```

**新闻时效门槛**：后台「模拟盘 · 复盘看板」页可调 `news_trade_max_age_seconds`（默认 2700s = 45 分钟，当前设为 900s = 15 分钟）；引擎 5s TTL 重读，改完立即生效。超龄 → 跳过建仓但**仍入库统计**。

**拒绝原因落库**：`no_trade_reason` / `trade_gate_reason` 写入 ai_decisions，信号台展示"未下单"原因。

## 时间口径说明

- 全项目时间**统一北京时间**：`config.parse_time_to_bj` / `config.fmt_bj`（带时区换算，无时区按北京，支持 epoch 秒/毫秒）。
- 存量 `published_at` 由 db.migrate 幂等归一化回填为北京时间串（`db._normalize_published_at`）。
- AI 分数的新鲜度衰减、交易时效门槛均按统一北京时间口径计算（入库闸另设 3h 拒收过时新闻）。

### 新闻新旧标记（实时信号台，四态）

每条新闻按「平台发布时间 vs 我们入库时刻」显示标记，悬停可见完整解释：

| 标记 | 条件 | 含义 |
|---|---|---|
| 🟢 新鲜（绿） | 差 < 10 分钟 | 平台即时发布、即时收到 |
| 🟠 滞后 X（琥珀） | 差 ≥ 10 分钟 | **平台发布早、推送晚**（feed 滞后/补发历史），非内容过时 |
| 🔵 实时推送（蓝） | 无平台时间 + WS/webhook 源 | 到达即发布，无独立发布时间可比对 |
| 🔵 官方数据（紫） | FRED 源 | 数据所属日期在正文"观测日"，非滞后推送 |
| ⚪ 时间未记录（灰） | 无平台时间 + 非实时流源 | 存量未存 / 接口无此字段 |

滞后判定阈值 `STALE_GAP_MINUTES = 10`（前端 event-bus.tsx）。展示层阈值与交易时效门槛（后台可调，默认 900s）互相独立。

### 采集时效可视化（新闻数据整理页）

每个源展示：轮询间隔（config 配置值，WS 实时推为 0）/ 中位滞后 / 严重滞后(>3h)条数 / 最新采集时刻。
滞后 = 平台发布 → 我们入库；**滞后 > 轮询间隔的部分 = 平台 feed 自身延迟**（轮询再勤也无法缩短）。
后端：`news_organizer.source_latency_stats()`；API：`GET /api/news/exports/latency`。

### 入库新鲜度闸豁免

金十日历 / FRED 公布事件带 `fresh_event: true` 豁免 3h 拒收闸——它们 actual/观测刚出现即生成（检测到公布=新鲜），其 `pub_time`/观测日是计划或数据所属时间，可能早于检测时刻，不宜作新鲜度依据（否则月度 CPI 等会被误杀）。

### 只推"最新公布"（金十日历 / FRED 事件通道）

防止重置/首次启动/feed 滞后把早已公布的旧数据当新事件推入信号台：

- **金十日历**：`calendar_events(max_age_hours)` 公布时间窗口，只生成"公布距今 ≤ 窗口"的已公布条目。watcher 传 `max(模拟盘新闻时效参数, 60分钟)`——复用后台"新闻时效"输入框（默认 900s → 窗口 60min 保底，防数据延迟公布被误杀；参数调到 ≥60min 时窗口随参数走）。
- **FRED**：水位记忆（`api_server._fred_new_only`），按 series 记录最近见过的观测日期——**只推观测日期变化的真发布**；首轮/重启只建基线不推存量（月度指标观测日滞后一个月，首启全推会把旧观测刷屏）。与新闻时效参数无关。
