兜底有好几条路径（完整降级 / 只要到 reasoning 摘要 / 只要到短摘要），
文案各不相同，但**从来没被计数**。于是"89% 是 0 分"看起来像模型偏好，
实际是上游没给输出。这一项就是把它们分开计。

## 三、新增的两件东西

### 1. 探针表 `llm_degrade_probe`（`llm_degrade_probe.py`）

| 列 | 用途 |
|---|---|
| `archetype` | 5 类之一，见上表 |
| `raw_len` / `raw_head` | LLM **原始输出**的长度与开头 80 字 |
| `path_len` / `rsn_len` | 落库的八段长度、reasoning 长度 |
| `action` / `score` | 落库时的动作与分数 |

`raw_head` 是关键：空输出（`raw_len=0`）、`<think>` 未闭合被剥光（开头是 `<think>`）、
JSON 被截断（开头是 `{"sentiment_sc…`）三种情况的处置完全不同，
有这 80 字就能事后分清，不用重跑 LLM、也不用开 dump。

接线：`_presanitize_for_schema` 入口 `note_raw(cleaned)` → 落库侧 `record(conn, ...)`。
探针写失败静默（`sqlite3.Error` 吞掉），绝不影响主流程。
